# ESC-008 — SE-12: day-ring empty text vs. enabled modules (which closure?)
- Opened: 2026-11-15 · By: Lead + Product/Contracts / T-033 · Class: D2 · Blocking: no now (SE-12 is needed "before the Home task", M2); yes for closing SE-12
## Question
SE-12's proposed text builds the empty sentence by joining module noun phrases with «یا», which KN-03 forbids, and it leaves a choice open (hide the card vs. keep HM-01 «ثابت» with a neutral sentence). Which closure should Product/Contracts write into VI-15, HMX-01, HM-01/HM-02 and DM-01?
## Context (links only; no pasted spec)
`docs/design/SPEC_ERRATA.md` SE-12 (proposed text + interim rule); `01-identity.md` VI-15; `09-tone-and-copy.md` HMX-01, KN-02, KN-03, KN-04; `05-navigation-home-modules.md` HM-01, HM-02, DM-01, DM-07; `docs/architecture/MODULE_CONTRACT.md` MDC-A4, `dayRingArc`, line "the host decides the empty state (VI-15)", budget row "Disabled"; `docs/product/MVP_SCOPE.md` U-6 (v0.1 builds only `budget`).
## Options
A) **Hide when no provider; one full sentence per provider set.** HM-01: the day-ring card is fixed in place but shown only while at least one arc-providing module is enabled (DM-01). VI-15/HMX-01 become complete sentences keyed by the enabled provider set (KN-03, no joining): v0.1 needs only `hmx.01.budget` «برای دیدن وضعیت امروز، یک بودجه اضافه کنید.»; the other keys (`habit`, `task`, and the combinations) are added by KN-04 when those modules ship. DM-01's list gains «متن حالت خالی». Cost: one small spec PR, no contract change; risk: the host picks a key from the enabled set (a small mapping next to the registry, MDC-A4) and the rows grow combinatorially (≤ 7 for budget/tasks/health).
B) **Card always shown; one neutral sentence** that names no module (new copy row written by Product/Contracts). Cost: same PR; risk: new Persian copy without a spec source (AG-05), and a card that can never fill when every provider is off.
C) **SE-12 as written:** each descriptor supplies a noun-phrase key, joined with «یا». Cost: KN-03 exception plus a `MODULE_CONTRACT` descriptor field (contract change); risk: highest.
## Recommendation
A — it is the interim rule already in force (budget-only sentence, card omitted with budget off), keeps KN-03 intact and needs no contract change.
## What happens if no answer
AG-16 default: SE-12's interim rule stays (budget-only sentence from the catalog via AGX-01; card omitted when `budget` is off). Safe until the Home task starts (M2).
