# ESC-002 — Themes v2 define 8 roles; the token contract needs 46 per theme
- Opened: 2026-11-01 · By: Product/Contracts/T-012 · Class: D2 (contract/spec gap, AG-08) · Blocking: yes (T-012 acceptance criteria 1 and 4: writing the four themes into `design/tokens/design_tokens.json`; then T-010 and T-013)
## Question
`design/brand/themes-v2.json` gives each theme 8 roles (bg, surface, surface2, ink, text2, line, accent, onaccent) plus on-bg text, mascot, scene and activity colours. The token contract (table A-2-a, AXT-02/03; contrast groups VTG-01…VTG-10, 210 checks) needs 46 colour roles per theme (plus elevation shadow colours), including the money/status colours `success`, `warning`, `danger`, `info`, three module accents, hover/pressed/subtle variants, `focus-ring`, `text-disabled`, `inverse-*`, and `scrim`. Where do the 38 missing values come from?
## Context (links only; no pasted spec)
ADR-UI-011 §1 and "Consequences"; T-012 packet; SE-13 in `docs/design/SPEC_ERRATA.md`; AG-05 and AG-08 (no invented numbers); `docs/design/ui-spec/02-tokens.md`, `docs/design/ui-spec/11-testing-and-machine-checks.md` (VTG groups), `docs/design/ui-spec/A-appendix-tokens.md` (A-2-a, A-3). Measured on branch `agent/contracts-T-012-tokens-v2` (`test/tool/themes_v2_contrast_test.dart`): all 44 pairs that v2 defines pass, but Clay `accent` on Clay `surface` is 4.45:1, so `accent` cannot become v1 `primary` as is (VTG-02 needs 4.5), and Clay `ink`/`text2` on Clay `bg` are 3.12 and 1.41 (VTG-01 needs `text-primary`/`text-secondary` ≥ 4.5 on `background`).
## Options
A) Owner/designer supplies the full role table per theme (status colours, module accents, states, focus, inverse, scrim, shadows) as `themes-v2.json` version 3; T-012 then maps one-to-one. Cost: one design pass; risk: none for the contract.
B) Product/Contracts derives the missing roles by a written rule (e.g. hover/pressed = accent mixed 8 %/12 % toward ink, subtle = accent at 8 % on surface, status colours tuned per theme with the contrast guard to pass VTG-02/03/04) and the owner reviews the resulting table once before merge. Cost: one task plus a review; risk: derived money colours the owner has not seen.
C) Shrink the v1 role set to the v2 roles and rewrite VTG groups. Cost: spec rewrite (AG-02), touches money colours and every later component; risk: high.
## Recommendation
B for states, subtle tints, focus, inverse, scrim and shadows (mechanical, guard-checked), but A for the four status colours and three module accents, because income/expense/warning colours are money behaviour the owner should see. Clay needs either a darker `accent` for text use or a rule that accent text on Clay uses the guard's nearest shade (`#B3482F`, 4.51:1).
## What happens if no answer
v1 tokens stay binding in code (interim rule SE-13); T-012 ships only the contrast guard and the v2 contrast test; T-010 and T-013 stay blocked. Safe indefinitely for code (no screen uses the new palette yet).
