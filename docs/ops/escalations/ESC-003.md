# ESC-003 — MC-08 and MC-01 "allowed in" vs. files the tokens contract puts in `lib/`
- Opened: 2026-11-03 · By: Product/Contracts/T-016 · Class: D2 (spec gap, AG-08; changing an "allowed in" cell needs Agent 1 approval, VR-03) · Blocking: no (blocks only wiring `ui_check rules` as a blocking CI step; T-016 itself is not blocked)
## Question
Table 11-2-a allows `Duration(milliseconds:` only in package `app_motion` (MC-08), but the generated token file `lib/design/tokens/design_tokens.g.dart` (TK-01, generated from the `motion` block of appendix A) contains 14 such lines. Separately, MC-01 allows hex colour numbers only in that generated file, but the runtime theme derivation and contrast guard of PR #21 (`lib/design/tokens/theme_derivation.dart`, `contrast_guard.dart`, for the custom theme of ADR-UI-011) work on `0xRRGGBB` ints. Should the "allowed in" cells be extended, or should the code change?
## Context (links only; no pasted spec)
`docs/design/ui-spec/11-testing-and-machine-checks.md` table 11-2-a (MC-01, MC-08), VR-03; `04-motion.md` MX-03, §4-2 (values come from appendix A); `tool/ui_check/src/generator.dart` (emits `Duration(milliseconds: …)`); ADR-UI-011 (custom theme with contrast control); PR #21 (T-012, waits for the owner); T-016 (`tool/ui_check/src/rules_stage.dart`, PR for T-016).
## Options
A) Errata: MC-08 "allowed in" += the generated token file; MC-01 "allowed in" += `lib/design/tokens/` (derivation and guard only, no widget). Cost: two cells; risk: low, both are generated or pure computation files, not UI.
B) MC-08: keep the cell, make the generator emit integer milliseconds and let `app_motion` build the `Duration`s; MC-01: keep the cell, store colours in the derivation as strings `#RRGGBB` parsed by a helper inside the generated file. Cost: generator + T-012 rework; risk: code shaped around a text pattern.
C) A for MC-08, B for MC-01.
## Recommendation
A — the cells already list the generated file for MC-01, MC-05 and MC-07, so its absence in MC-08 reads as an omission, and ADR-UI-011 (accepted) requires runtime colour computation, which MC-01 did not foresee.
## What happens if no answer
`ui_check rules` reports the spec as written (14 × MC-08 in the generated file today); the stage is run in tool tests and printed in CI, not wired as a blocking step, so no PR goes red because of it. Safe until the first UI component task (M1), which needs the blocking step (VR-02).
