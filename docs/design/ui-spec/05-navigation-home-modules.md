## ۵. ناوبری، خانه و ماژول‌ها

**وضعیت:** پیشنهاد (Proposed) و ذیل `ADR-UI-002` (مدل ناوبری). مالک قرارداد Agent 1 است و پیاده‌سازی پوسته با Agent 2؛ Agent 3 و 4 و 5 فقط مقصد خود را در کاتالوگ بخش ۵-۱ ثبت می‌کنند و حق ساخت ناوبری جداگانه ندارند. اگر این بخش با قانون اساسی UI/UX تعارض داشته باشد، قانون اساسی برنده است؛ تفسیرهای این بخش از قانون اساسی در بخش ۵-۸ فهرست شده‌اند.

سه تصمیم اصلی: (۱) فقط ده مقصد قانون اساسی وجود دارد و همه از یک کاتالوگ ساخته می‌شوند؛ (۲) نوار پایین موبایل همیشه «خانه، حسابداری، دو مقصد سنجاق‌شده، بیشتر» است؛ (۳) ماژول غیرفعال هیچ ردی در رابط ندارد.

### ۵-۱ کاتالوگ مقصدها

ترتیب جدول همان ترتیب کاتالوگ و ترتیب نمایش در صفحه‌ی «بیشتر» است. عنوان کامل برای سایدبار، هدر و «بیشتر» و عنوان کوتاه فقط برای برچسب نوار پایین است.

| شناسه | عنوان کامل | عنوان کوتاه | همیشه فعال | قابل سنجاق | رنگ تأکید | گروه سایدبار | مالک |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `home` | خانه | خانه | بله | خیر (ثابت) | `primary` | بدون گروه | Agent 2 |
| `accounting` | حسابداری | حسابداری | بله | خیر (ثابت) | `accent-finance` | مالی | Agent 3 |
| `budget` | بودجه و اهداف مالی | بودجه | خیر | بله | `accent-finance` | مالی | Agent 3 |
| `tasks` | کارها و تقویم | کارها | خیر | بله | `accent-tasks` | زندگی روزمره | Agent 4 |
| `health` | عادت‌ها و سلامت | سلامت | خیر | بله | `accent-health` | زندگی روزمره | Agent 4 |
| `car` | خودرو | خودرو | خیر | بله | `accent-car` | زندگی روزمره | Agent 4 |
| `markets` | دارایی‌ها و بازارها | بازارها | خیر | بله | `accent-finance` | مالی | Agent 4 |
| `assistant` | دستیار هوشمند | دستیار | خیر | بله | `primary` | دستیار | Agent 5 |
| `reports` | گزارش‌ها | گزارش‌ها | بله | بله | `accent-finance` | مالی | Agent 3 |
| `settings` | تنظیمات | تنظیمات | بله | خیر (در «بیشتر» و نوار بالا) | `primary` | ندارد (نوار بالا) | Agent 2 |

```dart
enum DestinationId { home, accounting, budget, tasks, health, car, markets, assistant, reports, settings }

class Destination {
  final DestinationId id;
  final String titleKey;       // l10n: nav.<id>.title
  final String shortTitleKey;  // l10n: nav.<id>.short  (<= 9 characters, ZWNJ not counted)
  final String iconId;         // logical: nav-<id>; glyph chosen by ADR-UI-005
  final ModuleAccent accent;   // primary | finance | tasks | health | car
  final bool alwaysOn;         // true: home, accounting, reports, settings
  final bool pinnable;         // may occupy a pinned slot in the bottom bar
  final NavGroup group;        // none | finance | life | assistant | topbar
  final String route;          // '/home', '/accounting', ... (logical names)
}
```

- **ND-01:** تنها یک `DestinationCatalog` وجود دارد. نوار پایین، سایدبار، صفحه‌ی «بیشتر»، جست‌وجوی سراسری، QuickAdd و تنظیمات ماژول‌ها همه از همین کاتالوگ و از وضعیت فعال بودن ماژول‌ها ساخته می‌شوند؛ فهرست مقصدها در هیچ جای دیگر تکرار یا سخت‌کد نمی‌شود.
- **ND-02:** چهار مقصد `home`، `accounting`، `reports` و `settings` همیشه فعال‌اند و Switch ندارند. شش مقصد دیگر اختیاری‌اند. افزودن یا حذف مقصد فقط با ADR انجام می‌شود.
- **ND-03:** عنوان‌ها فقط از l10n می‌آیند. عنوان کوتاه از ۹ نویسه بیشتر نمی‌شود و برچسب نوار پایین هرگز شکسته یا با «…» بریده نمی‌شود؛ اگر ترجمه‌ای بلندتر شد، عنوان کوتاه باید کوتاه‌تر شود، نه اندازه‌ی فونت.
- **ND-04:** نام مسیرها همان ستون `route` است (`/home`، `/accounting`، `/budget`، `/tasks`، `/health`، `/car`، `/markets`، `/assistant`، `/reports`، `/settings` و `/more`). مسیرهای فرزند (مثل `/accounting/transactions/:id`) را مالک همان مقصد تعریف می‌کند و در بخش خودش ثبت می‌کند. کتابخانه‌ی مسیریابی با ADR معماری انتخاب می‌شود و این نام‌ها منطقی‌اند.
- **ND-05:** رنگ تأکید هر مقصد از ستون «رنگ تأکید» می‌آید و کل صفحه‌ی آن مقصد از همان رنگ استفاده می‌کند؛ پس در هر لحظه فقط یک رنگ تأکید روی صفحه است (VI-02).

### ۵-۲ نوار پایین (Compact و Medium)

نوار پایین فقط در Compact و Medium نمایش داده می‌شود (بخش ۲-۵) و در ریشه‌ی مقصدهای سطح‌بالا دیده می‌شود؛ صفحه‌ی جزئیات و فرم آن را می‌پوشانند.

- **BN-01 (جایگاه‌ها):** پنج جایگاه از `start` به `end`: ۱) خانه (ثابت)، ۲) حسابداری (ثابت)، ۳) و ۴) دو جایگاه سنجاق‌شده، ۵) «بیشتر» (ثابت و همیشه آخر). «آخر» منطقی است؛ در فارسی سمت چپ‌ترین جایگاه است.
- **BN-02 (سنجاق‌ها):** هر جایگاه سنجاق‌شده یکی از مقصدهای قابل سنجاق و فعال است. پیش‌فرض سنجاق‌ها `[assistant, tasks]` است. اگر سنجاقی غیرفعال یا نامعتبر باشد، جایش با نخستین مقصد فعال و سنجاق‌نشده از فهرست اولویت پر می‌شود. فهرست سنجاق‌های کاربر با غیرفعال شدن ماژول پاک نمی‌شود؛ با فعال شدن دوباره، سنجاق قبلی برمی‌گردد. جایگاه خالی یا خاکستری هرگز نمایش داده نمی‌شود؛ پس نوار کمینه چهار مورد دارد (خانه، حسابداری، گزارش‌ها، بیشتر).

```dart
const _fallbackPins = [
  DestinationId.assistant, DestinationId.tasks, DestinationId.budget,
  DestinationId.reports, DestinationId.markets, DestinationId.health, DestinationId.car,
];

List<DestinationId> effectivePins(List<DestinationId> userPins, Set<DestinationId> enabled) {
  final out = <DestinationId>[];
  for (final id in userPins) {
    if (out.length == 2) break;
    if (catalog[id].pinnable && enabled.contains(id) && !out.contains(id)) out.add(id);
  }
  for (final id in _fallbackPins) {
    if (out.length == 2) break;
    if (enabled.contains(id) && !out.contains(id)) out.add(id);
  }
  return out;
}
// bar = [home, accounting, ...effectivePins(...), more]
```

این تابع باید با بردارهای زیر آزمون شود (`enabled` همیشه شامل چهار مقصد همیشه‌فعال است):

| ماژول‌های اختیاری فعال | `userPins` | نوار از start به end |
| --- | --- | --- |
| همه | `[assistant, tasks]` | خانه، حسابداری، دستیار، کارها، بیشتر |
| همه جز دستیار | `[assistant, tasks]` | خانه، حسابداری، کارها، بودجه، بیشتر |
| بودجه، سلامت، خودرو، بازارها | `[assistant, tasks]` | خانه، حسابداری، بودجه، گزارش‌ها، بیشتر |
| هیچ | `[assistant, tasks]` | خانه، حسابداری، گزارش‌ها، بیشتر |
| همه جز خودرو | `[car, health]` | خانه، حسابداری، سلامت، دستیار، بیشتر |
| همه | `[tasks, tasks, markets]` | خانه، حسابداری، کارها، بازارها، بیشتر |
| همه | `[home, settings, tasks]` | خانه، حسابداری، کارها، دستیار، بیشتر |

- **BN-03 (ساختار هر آیتم):** ستونی از آیکون `icon-lg` (۲۴) داخل نشانگر و زیر آن برچسب عنوان کوتاه با اندازه‌ی `caption`. نوار همه‌عرض است، ارتفاعش `bottom-nav-height` (۶۴) به‌علاوه‌ی ناحیه‌ی امن پایین، آیتم‌ها هم‌عرض‌اند و کل آیتم ناحیه‌ی لمس است (حداقل `touch-min`). برچسب همیشه دیده می‌شود، نه فقط برای آیتم فعال.
- **BN-04 (حالت‌ها):** آیتم غیرفعال: آیکون و برچسب `text-secondary`. آیتم فعال: نشانگر قرص‌مانند با عرض «آیکون + دو برابر `space-4`» و ارتفاع «آیکون + دو برابر `space-1`» و گوشه‌ی کامل با رنگ `*-subtle` همان مقصد، آیکون با رنگ تأکید همان مقصد و برچسب `text-primary`. وزن برچسب در همه‌ی حالت‌ها یکی است تا عرض نمی‌پرد. حالت فعال هم با شکل (نشانگر) و هم با رنگ منتقل می‌شود. حرکت نشانگر `MO-03` است.
- **BN-05 (نشان‌ها):** در نسخه‌ی اول هیچ شمارنده یا نقطه‌ی نشان روی نوار پایین نیست.
- **BN-06 (دسترس‌پذیری):** نوار با برچسب «ناوبری اصلی» به‌عنوان ناوبری معرفی می‌شود؛ هر آیتم برچسب کامل، وضعیت انتخاب‌شده و جایگاهش (مثلاً «۳ از ۵») را اعلام می‌کند.
- **BN-07 (صفحه‌ی «بیشتر»):** ضربه روی «بیشتر» صفحه‌ی `MorePage` را (نه Bottom Sheet) باز می‌کند و شامل سه بخش است: ۱) فهرست همه‌ی مقصدهای فعال که در نوار نیستند، به ترتیب کاتالوگ، ۲) ردیف «ماژول‌ها» که به تنظیمات ماژول‌ها می‌رود، ۳) ردیف «تنظیمات». هر ردیف یک چیپ آیکون ۴۰px با `*-subtle` و عنوان کامل و یک خط توضیح کوتاه دارد. `ModuleSwitcher` قانون اساسی همین فهرست است و کامپوننت جداگانه‌ای برایش ساخته نمی‌شود.
- **BN-08 (ویرایش سنجاق‌ها):** در هدر `MorePage` اقدام «ویرایش نوار» صفحه‌ای باز می‌کند با فهرست مقصدهای قابل سنجاق و فعال؛ حداکثر دو مورد انتخاب می‌شود و انتخاب سوم تا برداشتن یکی غیرفعال است (متن کمکی: «حداکثر دو مقصد را می‌توان سنجاق کرد»). ترتیب انتخاب همان ترتیب جایگاه‌هاست. اگر کمتر از دو مورد انتخاب شود، بقیه خودکار با فهرست اولویت پر می‌شود. پیش‌نمایش زنده‌ی نوار بالای فهرست دیده می‌شود.

### ۵-۳ جای QuickAdd

- **QA-01 (Compact و Medium):** دکمه‌ی شناور `fab` (۵۶) در گوشه‌ی `end` پایین (`AlignmentDirectional.bottomEnd`)، با فاصله‌ی `space-4` از لبه‌ی `end` و `space-4` بالای نوار پایین. رنگ آن همیشه `primary` است و رنگ ماژول جاری را نمی‌گیرد (بخش ۲-۳).
- **QA-02 (نمایش):** QuickAdd روی ریشه‌ی همه‌ی مقصدهای سطح‌بالا دیده می‌شود، به‌جز `settings`، `MorePage` و `assistant` (دستیار نوار ورودی خودش را دارد). روی صفحه‌ی جزئیات، فرم و دیالوگ دیده نمی‌شود.
- **QA-03 (فضای انتهایی):** لیست‌ها و صفحه‌های اسکرول‌شونده‌ای که QuickAdd دارند، پایینشان فضای خالی برابر `fab` به‌علاوه‌ی دو برابر `space-4` (یعنی ۸۸) دارند تا آخرین ردیف پوشیده نشود.
- **QA-04 (Expanded و Large):** QuickAdd دکمه‌ی اصلی بالای سایدبار است (بخش ۵-۴)؛ دکمه‌ی شناور ساخته نمی‌شود.
- **QA-05 (دسترسی):** برچسب `Semantics` «ثبت سریع» است، با صفحه‌کلید فوکوس‌پذیر است و Enter و Space آن را فعال می‌کند. میان‌بر صفحه‌کلید در `ADR-UI-008` (میان‌برها) ثبت می‌شود و تا آن زمان هیچ میان‌بری در کد نیست. محتوای پنجره‌ی ثبت در بخش ۶ است.

### ۵-۴ سایدبار و نوار بالا (Expanded و Large)

- **SB-01 (حالت‌ها):** سایدبار در سمت `start` است. حالت باز ۲۶۴ و جمع‌شده ۷۲ است. پیش‌فرض: Large باز و Expanded جمع‌شده. دکمه‌ی جمع‌/باز‌کردن در پایین سایدبار است؛ انتخاب کاربر حفظ می‌شود و بر پیش‌فرض غالب است. سایدبار باز محتوا را کنار می‌زند و روی آن نمی‌افتد.
- **SB-02 (ساختار از بالا):** (۱) `BrandMark` (نقطه‌ی `dot-lg` و نام برنامه؛ در حالت جمع‌شده فقط نقطه)، (۲) دکمه‌ی QuickAdd (تمام‌عرض با ارتفاع `control-lg` و برچسب «ثبت سریع»؛ در حالت جمع‌شده فقط آیکون در اندازه‌ی `fab`)، (۳) مقصد `home`، (۴) گروه‌ها به ترتیب جدول زیر، (۵) فضای انعطاف‌پذیر، (۶) دکمه‌ی جمع‌/باز‌کردن. مقصد `settings` در سایدبار نیست و در نوار بالا است.

| گروه | عنوان گروه | اعضا (به ترتیب کاتالوگ) |
| --- | --- | --- |
| `finance` | مالی | `accounting`، `budget`، `markets`، `reports` |
| `life` | زندگی روزمره | `tasks`، `health`، `car` |
| `assistant` | دستیار | `assistant` |

- **SB-03 (آیتم):** ارتفاع `control-lg` (۴۸)، آیکون `icon-md` (۲۰) در `start`، عنوان کامل با `label` و فاصله‌ی `space-3` بین آیکون و متن. عنوان گروه با `caption` و `text-secondary` است و اگر گروه عضو فعالی ندارد نمایش داده نمی‌شود. آیتم فعال پس‌زمینه‌ی `*-subtle` دارد و آیکون و متنش با رنگ تأکید همان مقصد است. در حالت جمع‌شده فقط آیکون دیده می‌شود، عنوان با Tooltip می‌آید و بین گروه‌ها یک جداکننده‌ی ۱px با `border` است. hover و focus طبق `MO-01` و جابه‌جایی نشانگر طبق `MO-03`.
- **SB-04 (صفحه‌کلید):** سایدبار یک ناحیه‌ی ناوبری است (برچسب «ناوبری اصلی»). Tab وارد آن می‌شود، پیکان‌های بالا و پایین بین آیتم‌ها حرکت می‌کنند، Enter و Space مقصد را باز می‌کند و آیتم فعال `selected` اعلام می‌شود.
- **TB-01 (نوار بالا):** فقط در Expanded و Large و با ارتفاع `topbar-height` (۶۴). از `start` به `end`: عنوان صفحه (`title`)، فضای انعطاف‌پذیر، فیلد جست‌وجوی سراسری (حداکثر عرض `side-panel-width`)، `SyncStatus`، دکمه‌ی اعلان‌ها و دکمه‌ی تنظیمات (آیکون `IconButton` که `/settings` را باز می‌کند).
- **TB-02 (جست‌وجوی سراسری):** در Compact و Medium به‌جای فیلد، آیکون جست‌وجو در اقدام‌های `PageHeader` صفحه‌های `home`، `accounting` و `MorePage` است و یک صفحه‌ی تمام‌صفحه باز می‌کند. نتایج بر اساس ماژول گروه‌بندی می‌شوند (ترتیب کاتالوگ)، هر گروه حداکثر پنج مورد با پیوند «نمایش همه»، فقط از ماژول‌های فعال، و مقایسه با `normalizeForSearch` (بخش ۳-۸).
- **TB-03 (اعلان‌ها):** دکمه‌ی اعلان‌ها یک `Popover` با حداکثر ۱۰ یادآور سررسیدشده یا نزدیک (کارها، اقساط، سرویس خودرو) باز می‌کند که به‌ترتیب تاریخ‌اند و ضربه روی هر ردیف به مورد مربوط می‌رود. حالت خالی: «یادآور فعالی ندارید.» اعلان‌های سیستم‌عامل جداگانه از تنظیمات کنترل می‌شوند.

### ۵-۵ صفحه‌ی خانه

- **HM-01 (ساختار):** `PageHeader` با عنوان «امروز» و زیرعنوان تاریخ امروز با قالب `date-weekday` (مثل «شنبه ۲ آبان»)؛ بعد از آن به ترتیب: ۱) کارت «حلقه‌ی روز» (ثابت)، ۲) کارت «موجودی» (ثابت)، ۳) ویجت‌های قابل تنظیم. بخش جداگانه‌ای به نام «اقدامات سریع» ساخته نمی‌شود؛ QuickAdd همیشه‌حاضر آن را برآورده می‌کند (بخش ۵-۸).
- **HM-02 (حلقه‌ی روز):** `DayRing` طبق بخش ۱-۳ و زیر آن فهرست متنی (VI-12)؛ اگر عرض کارت دست‌کم ۴۴۰ باشد فهرست کنار حلقه است و وگرنه زیر آن (DY-06). اگر کمانی نباشد `EmptyState` طبق VI-15 نمایش داده می‌شود.
- **HM-03 (موجودی):** `SummaryCard` با برچسب «موجودی کل»، عدد اصلی `CurrencyAmount` با اندازه‌ی `display` و زیر آن دو سطر `body-sm`: «درآمد این ماه» و «هزینه‌ی این ماه». اگر همه‌ی حساب‌ها یک ارز دارند یک عدد اصلی نشان داده می‌شود. اگر ارزها چندتاست، برای هر ارز یک ردیف (حداکثر ۳، بقیه با «+N ارز دیگر» که به حسابداری می‌رود) نشان داده می‌شود (ساختار دقیق: SC-05؛ تفسیر IN-7) و هیچ جمع میان‌ارزی بدون نرخ و زمان و منبع ساخته نمی‌شود (MN-06). بدون حساب: `EmptyState` کوچک با متن «برای دیدن موجودی، اولین حساب خود را بسازید.» و دکمه‌ی «ساخت حساب».

- **HM-04 (قواعد ویجت):** هر ویجت یک کارت با یک رنگ تأکید (ماژول مالک) و یک عدد یا یک فهرست اصلی است. ویجت ماژول غیرفعال هرگز ساخته نمی‌شود. ترتیب پیش‌فرض همان ترتیب جدول بالاست.
- **HM-05 (سفارشی‌سازی):** دکمه‌ی متنی «سفارشی‌سازی خانه» در انتهای خانه و در تنظیمات (ظاهر) صفحه‌ای باز می‌کند با فهرست ویجت‌های ماژول‌های فعال: هر ردیف یک `Switch` برای نمایش و دکمه‌های بالا و پایین برای ترتیب (کشیدن اختیاری است و جایگزین دکمه‌ها نمی‌شود). حلقه‌ی روز و موجودی در این فهرست نیستند. تنظیم محلی ذخیره می‌شود (`homeLayout`: فهرست مرتب‌شده‌ی شناسه‌ها و مجموعه‌ی پنهان‌ها)؛ شناسه‌ی ناشناخته نادیده گرفته می‌شود و ویجت تازه به انتهای فهرست می‌پیوندد.
- **HM-06 (چیدمان):** Compact: یک ستون، حاشیه‌ی صفحه `space-4`، فاصله‌ی کارت‌ها `space-4`. Medium: دو ستون، حاشیه `space-6`. Expanded: دو ستون با سایدبار باز و سه ستون با سایدبار جمع‌شده. Large: سه ستون و محتوا حداکثر `content-max` (۱۱۲۰) و وسط‌چین. حلقه‌ی روز و موجودی ردیف اول‌اند و ویجت‌ها به ترتیب ردیفی (چپ‌به‌راست یا راست‌به‌چپ بر اساس زبان) ادامه می‌دهند؛ چیدمان آجری (masonry) ممنوع است تا ترتیب خواندن و Tab قابل‌پیش‌بینی بماند.
- **HM-07 (حالت‌ها):** بارگذاری: `Skeleton` برای هر کارت (بعد از `skeleton-delay`). خطا در یک ویجت فقط همان کارت را به `ErrorState` کوچک با «تلاش دوباره» تبدیل می‌کند و بقیه‌ی خانه دست‌نخورده می‌ماند. آفلاین: `OfflineBanner` زیر هدر؛ داده‌ی محلی نشان داده می‌شود و `marketWatch` برچسب «آخرین قیمت: <زمان>» می‌گیرد.

### ۵-۶ ماژول غیرفعال

- **DM-01 (بدون ردپا):** ماژول غیرفعال هیچ ردی در رابط ندارد. جاهایی که باید ناپدید شوند: نوار پایین، `MorePage`، سایدبار، جست‌وجوی سراسری، انواع QuickAdd، ویجت‌های خانه، کمان‌های `DayRing`، بخش‌های گزارش‌ها، یادآورهای نوار اعلان، و پیوندهای میان‌ماژولی. خاکستری‌کردن، قفل‌گذاشتن یا نمایش «به‌زودی» برای ماژول غیرفعال ممنوع است.
- **DM-02 (کشف و فعال‌سازی):** تنها جای کشف و فعال‌سازی «تنظیمات › ماژول‌ها» است. این صفحه هر ماژول اختیاری را با چیپ آیکون، عنوان، یک جمله توضیح و `Switch` نشان می‌دهد و ماژول‌های هسته را با برچسب «همیشه فعال» و بدون Switch. زیر توضیح ماژول سلامت یادداشت حریم خصوصی هم هست: «داده‌های این ماژول فقط روی دستگاه شما می‌مانند.» (متن نهایی در بخش ۹).
- **DM-03 (غیرفعال‌سازی):** خاموش‌کردن Switch دیالوگ تأیید ندارد چون هیچ داده‌ای حذف نمی‌شود. بلافاصله Toast «ماژول <نام> غیرفعال شد. داده‌های شما نگه داشته شد.» با دکمه‌ی «واگرد» (`toast-undo-visible`) نشان داده می‌شود. «حذف داده‌های ماژول» عملی جداست در صفحه‌ی همان ماژول در تنظیمات، مخرب است و دیالوگ تأیید دارد.
- **DM-04 (فعال‌سازی):** با روشن‌کردن: مقصد در جای قبلی‌اش برمی‌گردد (BN-02 و HM-05)، کمان مربوط به `DayRing` اضافه می‌شود و Toast «ماژول <نام> فعال شد.» نشان داده می‌شود. هیچ راه‌اندازی مجددی لازم نیست.
- **DM-05 (مسیر مستقیم به ماژول غیرفعال):** باز شدن مسیر یک ماژول غیرفعال (پیوند عمیق، یادآور قدیمی، حالت ذخیره‌شده) صفحه‌ی `ModuleDisabledPage` را نشان می‌دهد: `EmptyState` با عنوان «این ماژول غیرفعال است»، توضیح «برای استفاده از آن، ماژول را فعال کنید.»، دکمه‌ی اصلی «فعال‌سازی ماژول» (همان لحظه فعال می‌کند) و دکمه‌ی ثانویه «بازگشت به خانه». این صفحه در هیچ ناوبری فهرست نمی‌شود.
- **DM-06 (داده‌ی مالی):** تراکنش‌هایی که یک ماژول (مثلاً خودرو) در حسابداری ثبت کرده، پس از غیرفعال‌شدن ماژول در حسابداری می‌مانند؛ فقط عناصر مخصوص ماژول (فیلتر، برچسب ماژول و پیوند به صفحه‌ی ماژول) پنهان می‌شوند. غیرفعال‌شدن هیچ ماژولی نباید هسته‌ی مالی را مختل کند.
- **DM-07 (آزمون ماتریسی):** برای شش ماژول اختیاری این چهارده ترکیب اجباری است: همه خاموش، همه روشن، و هر ماژول یک‌بار تنها خاموش و یک‌بار تنها روشن. در هر ترکیب هیچ مقصد غیرفعالی در جاهای DM-01 دیده نمی‌شود، ناوبری بدون استثنا انجام می‌شود و `effectivePins` با بردارهای بخش ۵-۲ سازگار است.

### ۵-۷ قالب صفحه و رفتار بازگشت

- **PG-01 (قالب):** هر صفحه از بالا به پایین: `PageHeader`، `OfflineBanner` (فقط وقتی آفلاین است)، `FilterBar`، `SummarySection`، `MainContent`. `FeedbackState` (بارگذاری، خالی، خطا) جای `MainContent` را می‌گیرد، نه کل صفحه را؛ `PageHeader` و `FilterBar` در همه‌ی حالت‌ها می‌مانند. بخش‌های بی‌مورد حذف می‌شوند، خالی نگه داشته نمی‌شوند.
- **PG-02 (PageHeader):** در Compact و Medium ارتفاع آن `topbar-height` (۶۴) است و از `start`: دکمه‌ی بازگشت (فقط در صفحه‌ی داخلی؛ `IconButton` با آیکون جهت‌دار)، عنوان با `title` در یک خط (طولانی‌تر از جا با «…» بریده می‌شود)، فضای انعطاف‌پذیر، و در `end` حداکثر دو اقدام آیکونی؛ اقدام‌های بیشتر در منوی سه‌نقطه. در Expanded و Large عنوان صفحه در `TopBar` است و `PageHeader` فقط ردیف زیرعنوان و اقدام‌های صفحه را دارد (اگر هیچ‌کدام نباشد ساخته نمی‌شود).
- **PG-03 (PrimaryAction):** در Compact و Medium «افزودن» همان QuickAdd است؛ دکمه‌ی اصلی فرم‌ها دکمه‌ای تمام‌عرض با ارتفاع `control-lg` است که به پایین می‌چسبد و بالای صفحه‌کلید مجازی می‌ماند. در Expanded و Large دکمه‌ی اصلی صفحه (پر و با رنگ تأکید همان مقصد) در `end` ردیف `PageHeader` است. در هر لحظه فقط یک دکمه‌ی پر روی صفحه است.
- **NV-01 (حفظ وضعیت):** جابه‌جایی بین مقصدهای سطح‌بالا وضعیت اسکرول و فیلتر هر مقصد را حفظ می‌کند.
- **NV-02 (ضربه‌ی دوباره):** ضربه روی مقصد فعال؛ اگر در عمق باشد به ریشه‌ی همان مقصد برمی‌گردد؛ اگر در ریشه است به بالای صفحه اسکرول می‌کند.
- **NV-03 (بازگشت سیستم‌عامل):** در ریشه‌ی مقصدی غیر از `home` بازگشت سیستم‌عامل به `home` می‌رود؛ در `home` رفتار پیش‌فرض سیستم‌عامل (خروج یا پس‌زمینه) اجرا می‌شود.
- **NV-04 (خروج از فرم):** دکمه‌ی بازگشت سلسله‌مراتب را برمی‌گردد، نه تاریخچه‌ی زمانی را. اگر فرم تغییر ذخیره‌نشده دارد، قبل خروج دیالوگ نشان داده می‌شود: عنوان «تغییرات ذخیره نشده‌اند»، متن «اگر خارج شوید، تغییرات از بین می‌روند.»، دکمه‌های «ماندن» (اصلی) و «دور انداختن» (مخرب، ثانویه).
