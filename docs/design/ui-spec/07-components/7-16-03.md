#### ۷-۱۶-۳ انتخابگر و تاریخ‌انتخاب (AppSelect، AppDatePicker)

AppSelect و AppDatePicker «ماشه‌ی انتخابگر»اند: ماشه همان AppChip است (CT-05) و انتخابگر یکی از لایه‌های ۷-۱۰ است (BottomSheet در Compact و Medium، Popover در Expanded و Large) که این زیربخش محتوایش را می‌گوید. هر دو تک‌انتخابی‌اند و برای چیپ‌های ثبت سریع (CP-01) و فیلترها (۷-۱۶-۸) به کار می‌روند. PickResult، PickerController، SelectModel و CalendarGridPort ساختار تازه‌اند و، مثل هر ساختار تازه، تأیید Agent 1 می‌خواهند (CM-13)؛ CalendarGridPort همان لایه‌ی تاریخ مرکزی DT-05 را به ویجت وصل می‌کند.

// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum PickerVariant { chip }                          // تنها واریانت نسخه‌ی ۱؛ واریانت تازه ردیف تازه در ۷-۰ می‌خواهد (PK-01)

sealed class PickResult<T> { const PickResult(); }
final class Picked<T> extends PickResult<T> { const Picked(this.value); final T value; }
final class Dismissed<T> extends PickResult<T> { const Dismissed(); }   // هر بسته‌شدن بی‌انتخاب (PK-06)

class PickerController<T> {                          // pickChip(slot) در QD-12 همین را صدا می‌زند
  Future<PickResult<T>> Function()? opener;          // ویجت در initState وصل و در dispose جدا می‌کند
  Future<PickResult<T>>? _pending;
  bool get isOpen => _pending != null;
  Future<PickResult<T>> open() =>                    // اگر باز است همان Future؛ با بسته‌شدن کامل می‌شود
      _pending ??= opener!().whenComplete(() => _pending = null);
}

abstract interface class PickerScope<T> {            // فقط به builder حالت ساخت داده می‌شود (PK-07)
  void pick(T value);                                // انتخاب را ثبت می‌کند و انتخابگر را می‌بندد
  void dismiss();
}
typedef CreateBuilder<T> = Widget Function(BuildContext context, PickerScope<T> scope);

class SelectOption<T> {
  const SelectOption({required this.value, required this.label, required this.semanticLabel, this.subtitle, this.icon});
  final T value;
  final String label;                                // رشته‌ی آماده از ViewModel (CM-10)
  final String semanticLabel;                        // «{نام}؛ {زیرعنوان}» (PK-12)
  final String? subtitle;                            // مثل ارز حساب
  final IconData? icon;
}

class SelectModel<T> {
  SelectModel.list({
    required this.title,                             // از کاتالوگ: PKX-01 تا PKX-04
    required this.options,                           // همه‌ی گزینه‌ها به ترتیب نمایش
    this.selected,
    this.none,                                       // «بدون دسته» (QX-06) یا «همه» (FB-04)؛ نخستین ردیف
    this.frequent = const [], this.frequentTitle, this.allTitle,   // «پرکاربرد»: تا ۵ مقدار به ترتیب SD-04
  })  : createBuilder = null, createFooter = null,
        assert(frequent.length <= 5 && (frequent.isEmpty || (frequentTitle != null && allTitle != null)));
  SelectModel.create({required this.title, required this.createBuilder, this.createFooter})
      : options = const [], selected = null, none = null,
        frequent = const [], frequentTitle = null, allTitle = null;
  final String title;
  final List<SelectOption<T>> options;
  final T? selected;
  final SelectOption<T>? none;
  final List<T> frequent;
  final String? frequentTitle, allTitle;
  final CreateBuilder<T>? createBuilder;             // تنها اسلات آزاد مجاز CM-02 در این بخش: ساخت حساب (SD-05)
  final WidgetBuilder? createFooter;
}

class AppSelect<T> extends StatefulWidget {
  AppSelect({
    super.key,
    required this.chip,                              // ChipVM: برچسب، semanticLabel و آیکون را فراخواننده می‌سازد (CT-02)
    required this.model,
    required this.onPicked,                          // فقط با انتخاب؛ با Dismissed صدا زده نمی‌شود
    required this.closeLabel,                        // «بستن»؛ PKX-13
    this.searchLabel,                                // «جست‌وجو»؛ PKX-06 (با بیش از ۵ گزینه الزامی است)
    this.emptyLabel,                                 // «موردی پیدا نشد.»؛ PKX-07 (همان)
    this.controller,
    this.focusAfterPick,                             // null یعنی همان چیپ (PK-06)
    this.variant = PickerVariant.chip,
    this.readOnly = false,
  })  : assert(model.options.length <= 5 || (searchLabel != null && emptyLabel != null));
  final ChipVM chip;
  final SelectModel<T> model;
  final ValueChanged<T> onPicked;
  final String closeLabel;
  final String? searchLabel, emptyLabel;
  final PickerController<T>? controller;
  final FocusNode? focusAfterPick;
  final PickerVariant variant;
  final bool readOnly;
}

- **PK-01 (نقش و دامنه):** AppSelect و AppDatePicker فقط ماشه و محتوای انتخابگرند. ماشه همان AppChip است و برچسب، `semanticLabel` و آیکونش را فراخواننده با ChipVM می‌سازد (CT-02، CT-05)؛ ظرف و بسته‌شدن از ۷-۱۰ است. تنها واریانت نسخه‌ی ۱ `chip` است و واریانت تازه ردیف تازه در ۷-۰ می‌خواهد (CM-13). ترتیب گزینه‌ها، رتبه‌بندی «پرکاربرد» (SD-04)، حذف گزینه‌های نامعتبر (مثل فهرست حساب‌های مقصد transfer؛ SD-03) و ساخت مقدار کار use-case است؛ کامپوننت فقط ViewModel آماده می‌گیرد (CM-01). ساعت و تقویم را هم نمی‌خواند: `today` و CalendarGridPort را می‌گیرد (DT-05).
- **PK-02 (ظرف):** ظرف و اندازه‌ها طبق جدول الف است. در Compact و Medium BottomSheet است با سربرگ ثابت و در Expanded و Large Popover است بدون سربرگ و بدون دکمه‌ی بستن؛ عنصر بازکننده‌ی Popover مستطیل چیپ در مختصات پنجره است (OV-08). رنگ تأکید ظرف همان رنگ تأکید بازکننده است (OV-09؛ در ثبت سریع primary، QD-12). بسته‌شدن هیچ‌گاه تأیید نمی‌خواهد (`onCloseRequested` برابر null). اگر کلاس پنجره حین باز بودن عوض شود، انتخابگر بدون انتخاب بسته می‌شود و فوکوس به چیپ برمی‌گردد (QD-03)؛ در Popover اسکرول صفحه‌ی پشت یا تغییر اندازه هم همین کار را می‌کند (OV-08 ث).
- **PK-03 (محتوای فهرست):** از بالا: ۱) فیلد جست‌وجو (PK-04)؛ ۲) ردیف `none` اگر هست، مثل «بدون دسته» (QX-06) و «بدون سررسید» (QX-12)، که مقدار معتبر است (CT-03) و همیشه نخستین ردیف است؛ ۳) اگر `frequent` خالی نیست: سرتیتر `frequentTitle` («پرکاربرد»، PKX-08) با حداکثر ۵ ردیف به ترتیب داده‌شده (SD-04) و سپس سرتیتر `allTitle` («همه‌ی دسته‌ها»، PKX-09) با همه‌ی گزینه‌ها، که هر گزینه‌ی پرکاربرد را دوباره می‌آورد؛ کلید ردیف ترکیب بخش و شناسه‌ی داده است تا یکتا بماند (RL-04). اگر گزینه‌ها ۵ یا کمتر باشند فهرست ساده است، بدون جست‌وجو و بدون سرتیتر (CP-01). سرتیتر بخش `label` با `text-secondary` روی ظرف است (TK-05)، با inset افقی `space-4` و فاصله‌ی `space-2` از بالا و پایین، و Semantics آن `header` است. سرتیتر چسبان نیست، چون جداکننده‌ی چسبان مرز یا سایه می‌خواهد (TK-10، TK-11).
- **PK-04 (جست‌وجو):** فیلد جست‌وجو AppTextField با `showLabel: false` است که hint و `semanticLabel` آن هر دو «جست‌وجو» (PKX-06) است، با `clearable: true` و بدون helper و error؛ این دومین استثنای FD-01 است و به Agent 1 گزارش می‌شود. فیلتر با هر تغییر همان لحظه اعمال می‌شود: `normalizeForSearch` (بخش ۳-۸) روی پرس‌وجو و روی `label` هر گزینه اجرا می‌شود و گزینه‌ای می‌ماند که برچسب نرمال‌شده‌اش پرس‌وجوی نرمال‌شده را در بر بگیرد؛ ترتیب گزینه‌ها همان ترتیب اصلی است. با پرس‌وجوی غیرخالی سرتیترها و تکرار «پرکاربرد» نمی‌آیند و یک فهرست تخت دیده می‌شود؛ ردیف `none` هم مثل بقیه فیلتر می‌شود. اگر چیزی نماند، متن «موردی پیدا نشد.» (PKX-07) با `body` و `text-secondary` وسط‌چین و با فاصله‌ی `space-6` از بالا و پایین می‌آید و با liveRegion از نوع polite اعلام می‌شود. فوکوس اولیه روی فیلد جست‌وجو نیست (FD-07)، تا صفحه‌کلید مجازی بی‌دلیل باز نشود و برگه کوتاه نشود (OV-04، QD-12).
- **PK-05 (ردیف):** هندسه، متن و حالت‌های ردیف طبق جدول ب است. کل ردیف از لبه تا لبه‌ی ظرف هدف لمس است. رنگ تأکید برای ردیف انتخاب‌شده به کار نمی‌رود (TK-07)؛ انتخاب را علامت تیک و Semantics می‌گویند (CM-11). فاصله‌ی میان ردیف‌ها صفر است و جداکننده ندارند، مثل منوی PageHeader (PH-05).
- **PK-06 (انتخاب و بسته‌شدن):** یک ضربه (یا Enter و Space) انتخاب می‌کند و انتخابگر را می‌بندد؛ دکمه‌ی تأیید ندارد. `Picked(value)` همان لحظه ثبت می‌شود: `onPicked` یک‌بار صدا زده می‌شود، Future کنترلر با `Picked` کامل می‌شود و چیپ در همان فریمی که بسته‌شدن شروع می‌شود متن تازه را می‌گیرد، بی‌انیمیشن (CT-05، CT-10). فوکوس به `focusAfterPick` می‌رود: در ثبت سریع فیلد اصلی نوع است و مقدار تایپ‌شده پاک نمی‌شود (CP-01)؛ در FilterBar و جاهای بی‌فیلد اصلی null است و فوکوس به خود چیپ برمی‌گردد. هر بسته‌شدن بی‌انتخاب (Escape، پس‌زمینه، کشیدن، بازگشت سیستم‌عامل، «بستن»، تغییر کلاس پنجره) `Dismissed` است و فوکوس به چیپ می‌رود (OV-04 پ). انتخاب دوباره‌ی مقدار فعلی هم `Picked` است. QuickAdd با `controller.open()` (همان `pickChip(slot)` در QD-12) انتخابگر را باز می‌کند و تا کامل‌شدن Future چیپ دیگری ضربه نمی‌گیرد (OV-01)؛ pointer-down بیرونِ Popover فقط آن را می‌بندد و به چیپ زیرین نمی‌رسد. اگر `readOnly` باشد ضربه و `open()` هیچ لایه‌ای باز نمی‌کنند و Future بی‌درنگ با `Dismissed` کامل می‌شود.
- **PK-07 (حالت ساخت؛ SD-05):** `SelectModel.create` همان ظرف را با بدنه‌ی `createBuilder` و، اگر داده شده، پاورقی `createFooter` پر می‌کند. فقط برای چیپ «ساخت حساب» است و همین یک اسلات آزاد در PK مجاز است (CM-02). محتوا را QuickAdd با کامپوننت‌های موجود می‌سازد: AppTextField «نام حساب» با فوکوس خودکار (FD-07)، Tabs «نقدی» و «بانکی» با پیش‌فرض «نقدی»، Button «ساخت حساب» در پاورقی که تنها دکمه‌ی پر همین لایه است (BU-01) و خطای تکراری‌بودن QX-21 با FieldMessage زیر فیلد (FD-05)؛ مقایسه‌ی نام و ساخت با use-case CreateAccount است (CM-01). با موفقیت builder `scope.pick(حساب تازه)` را صدا می‌زند: انتخابگر بسته می‌شود، چیپ حساب تازه را نشان می‌دهد و فوکوس و مبلغ تایپ‌شده سر جایشان می‌مانند (SD-05). ساخت حساب لایه‌ی سوم نمی‌سازد (QD-12). عنوان ظرف «ساخت حساب» (QX-21) و اندازه‌ی Popover همان `picker` است.

تاریخ‌انتخاب از Select سه چیز به ارث می‌برد: ماشه، ظرف و منطق انتخاب و بسته‌شدن (PK-01، PK-02 و PK-06)؛ آنچه در ادامه می‌آید فقط شبکه‌ی ماه است. AppDatePicker هیچ محاسبه‌ی تقویمی ندارد و ساعت نمی‌خواند: ماه، عنوان و برچسب‌ها را CalendarGridPort می‌دهد و پیاده‌سازی آن در لایه‌ی تاریخ مرکزی است (DT-05).

- **PK-08 (تاریخ‌انتخاب؛ نقش و مقدار):** AppDatePicker روز را از شبکه‌ی ماه برمی‌گزیند و `LocalDate` میلادی (DT-01) برمی‌گرداند، حتی وقتی تقویم کاربر جلالی است (DT-02)؛ نگاشت به جلالی و برچسب‌ها کار port است. `value` روز انتخاب‌شده است و `null` یعنی «بدون». دکمه‌ی «بدون» (مثل «بدون سررسید»، QX-12) فقط با `noneLabel` هست و `Picked(null)` می‌دهد؛ «هیچ» مقدار معتبر است، نه چیپ خالی (CT-03). انتخاب دوباره‌ی همان روز و «امروز» هم `Picked` است (PK-06). متن چیپ (امروز، دیروز، فردا یا تاریخ؛ CP-01) را فراخواننده می‌سازد، نه تاریخ‌انتخاب.
- **PK-09 (محتوا و ماه نمایش‌داده‌شده):** `port.month` شبکه را می‌سازد و `port.addMonths` ماه را جابه‌جا می‌کند و روز را به آخر ماه مقصد می‌چسباند (مثل ۳۱ به ۳۰ یا ۲۹)؛ `port.today` امروز را می‌دهد (در ثبت سریع همان date ثابت‌شده‌ی SD-06) و ویجت ساعت و locale نمی‌خواند (CM-01). تنها محاسبه‌ی خود ویجت جمع و تفریق ۱ و ۷ روز روی `LocalDate` با فلش‌هاست (حساب میلادی ساده)؛ هر چه به تقویم کاربر برمی‌گردد (DT-02 تا DT-05) در port است. ماه نخست ماه `value` است و اگر `null` است ماه `port.today`. روزهای هفته به ترتیب DT-03 می‌آیند و جمعه فقط با `text-secondary` متمایز می‌شود (DT-04). رشته‌های PKX-05 و PKX-10 تا PKX-13 را فراخواننده از کاتالوگ می‌دهد (CM-10).
- **PK-10 (هندسه):** اندازه‌ها از جدول پ است. شبکه تمام‌عرض ظرف است و حاشیه‌ی افقی ندارد، چون هر ستون دست‌کم `touch-min` می‌خواهد (CM-04): ۷×۴۴ = ۳۰۸؛ ظرف باریک‌تر از ۳۰۸ از دامنه‌ی نسخه‌ی ۱ بیرون است و در ریسک‌های بخش ۱۲ ثبت می‌شود. ناحیه‌ی لمس هر روز کل سلول (ستون × ۴۴) است، نه فقط دایره، و سلول‌ها هم‌پوشانی ندارند. ارتفاع شبکه همیشه شش ردیف است. ردیف‌های ناوبری، روزهای هفته و پاورقی با مقیاس متن بلند می‌شوند و عنوان ماه تا دو خط می‌شکند (CM-07).
- **PK-11 (حالت‌ها و حرکت):** حالت‌های سلول روز جدول ت است و هیچ‌کدام فقط با رنگ گفته نمی‌شود: انتخاب با پرکننده و `selected`، امروز با مرز و برچسب (CM-11). روز انتخاب‌شده خنثی است؛ لایه همچنان AccentScope بازکننده را می‌گیرد (OV-09)، ولی هیچ‌یک از ردیف‌ها و روزها رنگ تأکید نمی‌خوانند (TK-07). تغییر ماه، انتخاب و جابه‌جایی فوکوس حرکت ندارند و ردیفی در ۴-۳ برایشان نیست (CM-08)؛ فقط ورود و خروج خودِ ظرف حرکت دارد (MO-08؛ Popover بی‌حرکت). hover و pressed لایه‌ی MO-01 اند.
- **PK-12 (Semantics):** الف) هر ردیف Select یک `button` است با `selected` برای ردیف انتخاب‌شده و `inMutuallyExclusiveGroup`، و برچسبش `semanticLabel` است («{نام}؛ {زیرعنوان}») بی‌واژه‌ی «انتخاب‌شده» (CM-05)؛ سرتیترهای بخش `header` اند؛ فیلد جست‌وجو برچسب «جست‌وجو» دارد؛ «موردی پیدا نشد.» `liveRegion` از نوع polite است. ب) هر روز تاریخ‌انتخاب یک `button` است با `selected` برای روز انتخاب‌شده و برچسب `semanticLabel` از port (نام روز و تاریخ کامل؛ برای امروز با «امروز،» آغاز می‌شود)؛ سلول‌های بیرون ماه و ردیف حرف‌های روز هفته در درخت نیستند؛ عنوان ماه `header` و `liveRegion` از نوع polite است تا با ماه قبل و بعد اعلام شود. پ) BottomSheet گره‌ی مسیر دارد و `semanticTitle` آن عنوان انتخابگر است؛ Popover گره‌ی مسیر ندارد، پس چیپ تا باز بودن آن `expanded: true` است (OV-05، CT-02).
- **PK-13 (فوکوس و صفحه‌کلید):** کلیدها جدول ث است. فهرست و شبکه هر کدام یک توقف Tab اند و درونشان فوکوس رووینگ است؛ ترتیب Tab ترتیب دیداری است (OV-04). فوکوس اولیه (`initialFocus`) در Select روی ردیف انتخاب‌شده است و اگر نیست روی اولین ردیف، نه فیلد جست‌وجو (FD-07)؛ در تاریخ‌انتخاب روی روز انتخاب‌شده است و اگر `value` خالی است روی امروز. فلش یا PageUp و PageDown که از مرز ماه بگذرد ماه نمایش‌داده‌شده را هم عوض می‌کند. با دکمه‌های ماه قبل و بعد روزِ رووینگ همان‌قدر ماه جابه‌جا می‌شود (`port.addMonths`) و فوکوس روی دکمه می‌ماند. حلقه‌ی فوکوس طبق ۲-۶ فقط با صفحه‌کلید دیده می‌شود. فوکوس پس از بسته‌شدن طبق PK-06 است.
