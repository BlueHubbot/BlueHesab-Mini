#### ۷-۱۶-۲ چک‌باکس، سوئیچ و ردیف سوئیچ‌دار (Checkbox، Switch، SwitchRow)

Checkbox و Switch دو کنترل دودویی‌اند: چک‌باکس برای «انجام‌شده یا انتخاب‌شده» (ردیف کار در ۷-۶، LC-04) و سوئیچ برای «روشن یا خاموش بودن یک تنظیم» (ماژول‌ها در DM-02، چیدمان خانه در HM-05). هر دو دو نقش دارند: `control` (کنترل مستقل با ناحیه‌ی لمس و Semantics خودش) و `indicator` (فقط گرافیک، درون ردیفی که خودش لمس و Semantics دارد). چون RowTrailing بسته است و Switch نمی‌پذیرد (۷-۶)، ردیف تنظیمات ساختار تازه‌ی SwitchRow است که به ردیف TG در ۷-۰ اضافه شده و، مثل هر ساختار تازه، تأیید Agent 1 می‌خواهد (CM-13).

```dart
// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum ToggleRole { control, indicator }        // indicator: فقط گرافیک؛ لمس، فوکوس و Semantics با ردیف است (TG-05)

class AppCheckbox extends StatelessWidget {
  const AppCheckbox({
    super.key,
    required this.value,                      // کنترل‌شده؛ وضعیت داخلی ندارد (CM-01)
    this.onChanged,                           // control: null یعنی غیرفعال
    this.semanticLabel,                       // control: الزامی، فارسی و بدون واژه‌ی وضعیت (TG-10)
    this.role = ToggleRole.control,
    this.enabled = true,                      // فقط برای indicator؛ در control از onChanged می‌آید
  }) : assert(role == ToggleRole.indicator || semanticLabel != null, 'AQ-01');
  final bool value;
  final ValueChanged<bool>? onChanged;
  final String? semanticLabel;
  final ToggleRole role;
  final bool enabled;
}

class AppSwitch extends StatelessWidget {     // امضای AppCheckbox؛ فقط گرافیک و اندازه فرق می‌کند (جدول الف)
  const AppSwitch({super.key, required this.value, this.onChanged, this.semanticLabel,
      this.role = ToggleRole.control, this.enabled = true})
      : assert(role == ToggleRole.indicator || semanticLabel != null, 'AQ-01');
  final bool value;
  final ValueChanged<bool>? onChanged;
  final String? semanticLabel;
  final ToggleRole role;
  final bool enabled;
}

class SwitchRowReorder {
  const SwitchRowReorder({this.onMoveUp, this.onMoveDown});   // null یعنی غیرفعال: ردیف اول یا آخر (TG-09)
  final VoidCallback? onMoveUp, onMoveDown;
}

class SwitchRow extends StatelessWidget {
  const SwitchRow({
    required super.key,                       // کلید پایدار شناسه‌ی داده، نه اندیس (RL-04)
    required this.title, this.subtitle, this.note,
    this.icon, this.accent,                   // چیپ آیکون ۴۰×۴۰ مثل RowLeading.icon؛ هر دو یا هیچ‌کدام
    required this.value, required this.onChanged,
    this.reorder,                             // فقط فهرست سفارشی‌سازی خانه (HM-05)
  })  : alwaysOn = false,
        assert((icon == null) == (accent == null));
  const SwitchRow.alwaysOn({                  // «همیشه فعال» به‌جای Switch (DM-02، TG-08)
    required super.key, required this.title, this.subtitle, this.icon, this.accent,
  })  : alwaysOn = true, note = null, value = true, onChanged = null, reorder = null,
        assert((icon == null) == (accent == null));
  final String title;
  final String? subtitle, note;               // note: مثل یادداشت حریم خصوصی ماژول سلامت (DM-02)
  final IconData? icon;
  final ModuleAccent? accent;
  final bool value;
  final ValueChanged<bool>? onChanged;        // null در ردیف عادی یعنی غیرفعال
  final SwitchRowReorder? reorder;
  final bool alwaysOn;
}
```

جدول ۷-۱۶-۲-الف: هندسه (px؛ همه توکن‌اند یا حاصل‌شان حساب شده است).

| ویژگی | Switch | Checkbox |
| --- | --- | --- |
| جعبه‌ی چیدمان، نقش `control` | ۴۸×۴۴ (`control-lg` × `touch-min`)؛ همین ناحیه‌ی لمس است | ۴۴×۴۴ (`touch-min`)؛ همین ناحیه‌ی لمس است |
| جعبه‌ی چیدمان، نقش `indicator` | ۴۸×۳۲ (همان track) | ۲۴×۲۴ (همان جعبه)؛ ListRow آن را وسط جایگاه ۴۰×۴۰ (`avatar-md`) می‌گذارد، یعنی ۸ فاصله از هر سو (LC-02) |
| شکل | track به ابعاد ۴۸×۳۲ (`control-lg` × `space-8`) با `radius-full` و دستگیره‌ی دایره‌ای ۲۴ (`icon-lg`) | جعبه‌ی ۲۴×۲۴ (`icon-lg`) با `radius-sm` |
| جای دستگیره | `space-1` (۴) تا لبه‌ی track در هر چهار سو؛ مسیر حرکت ۱۶ (= ۴۸ − ۲×۴ − ۲۴)؛ خاموش در سمت start و روشن در سمت end | ندارد |
| خاموش یا نشانه‌نخورده | track بدون پرکننده (سطح میزبان) با مرز ۱px `border-strong`؛ دستگیره‌ی پر با `border-strong` | بدون پرکننده با مرز ۱px `border-strong` |
| روشن یا نشانه‌خورده | track پر با `text-primary`؛ دستگیره‌ی پر با `surface` که علامت تیک `text-primary` در مرکز دارد | جعبه‌ی پر با `text-primary` و علامت تیک `surface` در مرکز |
| علامت تیک | اندازه‌ی `icon-sm` (۱۶)، ضخامت ۲px (TK-11)، سر خط گرد؛ آینه نمی‌شود (۲-۷) | همان |
| هاله‌ی hover و pressed | روی کل جعبه‌ی ۴۸×۴۴ با `radius-full`؛ لایه‌ی `text-primary` با شفافیت ۰٫۰۸ و ۰٫۱۲ | دایره‌ی ۴۴ (`radius-full`)؛ همان لایه‌ها (مثل IconButton در BU-08) |
| حلقه‌ی فوکوس | ۲px `focus-ring` با فاصله‌ی ۲px از track و شعاع کامل؛ در جهت افقی ۴px از جعبه‌ی چیدمان بیرون می‌زند و والد آن را نمی‌برد (۲-۶) | ۲px `focus-ring` با فاصله‌ی ۲px از جعبه و شعاع ۸ (= `radius-sm` + ۲) |

جدول ۷-۱۶-۲-ب: حالت‌ها (Switch و Checkbox در نقش `control`؛ در نقش `indicator` فقط دو ردیف اول و disabled معنا دارند).

| حالت | قاعده |
| --- | --- |
| عادی، خاموش یا نشانه‌نخورده | جدول الف |
| عادی، روشن یا نشانه‌خورده | جدول الف |
| hover (فقط ماوس) | هاله‌ی جدول الف با شفافیت ۰٫۰۸ (MO-01) |
| pressed | همان هاله با شفافیت ۰٫۱۲ |
| focus (صفحه‌کلید) | حلقه‌ی جدول الف با شرط نمایش ۲-۶ |
| disabled | کل کنترل با شفافیت ۰٫۳۸ و بدون hover و pressed و focus؛ `onChanged` برابر null و `Semantics(enabled: false)` (۲-۶). دلیل غیرفعال بودن، اگر باید گفته شود، در زیرعنوان ردیف می‌آید |
| loading | ندارد؛ مقدار همان لحظه اعمال می‌شود (CM-03) |
| error | ندارد؛ مقدار نامعتبر وجود ندارد (CM-03) |

جدول ۷-۱۶-۲-پ: ارتفاع SwitchRow و عرض ستون متن (کمینه در مقیاس متن ۱٫۰ و کارت ۳۲۸ در Compact، یعنی ۲۹۶ جای محتوا؛ px؛ فرمول ارتفاع: ۲ × `space-3` + بلندترین بخش).

| ترکیب | بلندترین بخش | ارتفاع ردیف | عرض ستون متن |
| --- | --- | --- | --- |
| فقط عنوان، بدون چیپ | Switch (۳۲) | ۵۶ | ۲۳۶ |
| عنوان و زیرعنوان، بدون چیپ | ۲۸ + ۲۴ | ۷۶ | ۲۳۶ |
| چیپ آیکون و فقط عنوان | چیپ (۴۰) | ۶۴ | ۱۸۴ |
| چیپ آیکون و عنوان و زیرعنوان | ۲۸ + ۲۴ | ۷۶ | ۱۸۴ |
| چیپ آیکون و عنوان و زیرعنوان و یادداشت | ۲۸ + ۲۴ + ۴ + ۲۴ | ۱۰۴ | ۱۸۴ |
| دکمه‌های ترتیب و فقط عنوان، بدون چیپ | دکمه (۴۴) | ۶۸ | ۱۳۲ |
| دکمه‌های ترتیب و عنوان و زیرعنوان، بدون چیپ | ۲۸ + ۲۴ | ۷۶ | ۱۳۲ |

- **TG-01 (نقش و رنگ):** Checkbox و Switch فقط رنگ‌های خنثی دارند: `text-primary`، `surface` و `border-strong` (جدول الف). رنگ تأکید ماژول به آن‌ها نمی‌رسد، چون TK-07 آن‌ها را میان مصرف‌های مجاز تأکید نیاورده؛ پس AccentScope نمی‌خوانند (مثل CT-11). جفت `text-primary` و `surface` (علامت تیک، دستگیره‌ی روشن) و جفت `border-strong` و `surface` (مرز و دستگیره‌ی خاموش) همان گروه‌های اعتبارسنجی‌شده‌ی ۲-۸ روی `background`، `surface` و `surface-raised`‌اند (کمینه‌ی ۱۷٫۰۶ و ۱۳٫۳۵ در آستانه‌ی ۴٫۵؛ ۳٫۳۱ و ۳٫۳۰ در آستانه‌ی ۳) و چون نسبت تضاد متقارن است، جای دو رنگ در جفت فرقی نمی‌کند (CM-09). وضعیت هیچ‌گاه فقط با رنگ گفته نمی‌شود: جای دستگیره و علامت تیک هم هست (CM-11).
- **TG-02 (Switch):** هندسه و رنگ طبق جدول الف. روشن‌شدن دستگیره را به سمت end می‌برد و خاموش‌شدن به سمت start؛ پس در RTL خاموش در راست و روشن در چپ است (MT-06). متنی مثل «روشن» و «خاموش» درون یا کنار track نیست: متن کنار سوئیچ عنوان ردیف یا برچسب Semantics است. دستگیره کشیدنی نیست؛ ضربه، Enter و Space کافی‌اند (TG-12).
- **TG-03 (Checkbox):** هندسه و رنگ طبق جدول الف. دو وضعیت دارد، نشانه‌خورده و نشانه‌نخورده (حالت نامعین در TG-12 ممنوع است). در نسخه‌ی ۱ تنها مصرف‌کننده‌ی آن leading چک‌دار ListRow است (`RowLeading.check`؛ LC-02، LC-04) در نقش `indicator`؛ نقش `control` برای فرم‌های بعدی است و `semanticLabel` فارسی می‌خواهد (assert).
- **TG-04 (حالت‌ها):** حالت‌ها طبق جدول ب است و هر ردیف آن یک آزمون ویجت دارد (CM-03).
- **TG-05 (نقش indicator):** در `RowLeading.check` و در SwitchRow گرافیک تزئینی است: `ToggleRole.indicator` ضربه، hover، فوکوس و Semantics ندارد (`ExcludeSemantics`) و هاله و حلقه‌ی جدول الف را نمی‌سازد. هدف لمس، لایه‌ی حالت، حلقه‌ی فوکوس و گره‌ی Semantics مال ردیف است (LC-03، LC-04، LC-08)؛ ردیف مقدار و `enabled` را می‌دهد و گرافیک فقط آن را می‌کشد.
- **TG-06 (SwitchRow؛ چیدمان):** SwitchRow ردیف تنظیمات است و فقط درون قاب RLSection می‌نشیند (۷-۱۶-۱)؛ لبه‌تا‌لبه‌ی قاب، جداکننده و کلید پایدار را همان فهرست می‌دهد (RL-04). ساختار ردیف ضربه‌پذیر ListRow را دارد (LC-02): فاصله‌ی افقی `space-4` و عمودی `space-3`؛ به ترتیب منطقی: چیپ آیکون ۴۰×۴۰ (اختیاری؛ `avatar-md`، `radius-md`، پس‌زمینه‌ی `{accent}-subtle`، آیکون `icon-md` به رنگ `{accent}` با `accent` صریح مثل LC-02)، `space-3`، ستون متن، `space-3`، گروه دکمه‌های ترتیب (اختیاری)، `space-2` و Switch در نقش indicator. ستون متن: `title` با `body` و `text-primary`؛ `subtitle` با `body-sm` و `text-secondary`؛ `note` با `body-sm` و `text-secondary` به فاصله‌ی `space-1` زیر زیرعنوان (مثل یادداشت حریم خصوصی ماژول سلامت در DM-02). برخلاف ListRow هیچ‌کدام از این سه متن با «…» کوتاه نمی‌شود: همه می‌شکنند و ردیف بلندتر می‌شود (CM-07)، چون ردیف تنظیمات صفحه‌ی جزئیاتی ندارد که متن کامل را نشان بدهد. ارتفاع‌ها و عرض ستون متن طبق جدول پ است و در مقیاس بزرگ‌تر فقط بیشتر می‌شوند.
- **TG-07 (تغییر مقدار):** در SwitchRow کل ردیف از لبه تا لبه‌ی قاب هدف تغییر مقدار است، به‌جز دو دکمه‌ی ترتیب (ارتفاع دست‌کم ۵۶، یعنی بیشتر از `touch-min`). ضربه، Enter یا Space دقیقاً یک‌بار `onChanged(!value)` را صدا می‌زند. hover، focus و pressed لایه‌ی `text-primary` با شفافیت ۰٫۰۸ و ۰٫۱۰ و ۰٫۱۲ روی ردیف است و حلقه‌ی فوکوس داخل مرز ردیف رسم می‌شود (LC-03)؛ وقتی نشانگر روی دکمه‌ی ترتیب است لایه‌ی ردیف خاموش است و فقط هاله‌ی خود دکمه (BU-08) دیده می‌شود. `value` را والد می‌دهد؛ ردیف وضعیت داخلی ندارد (CM-01) و آنچه پس از تغییر می‌آید (ذخیره، Toast، واگرد) کار use-case است (DM-03، DM-04). ردیف با `onChanged` برابر null غیرفعال است (جدول ب).
- **TG-08 (`SwitchRow.alwaysOn`):** برای ماژول هسته (DM-02) به‌جای Switch متن «همیشه فعال» (TGX-03) با `body-sm` و `text-secondary` در end می‌آید، همان نقش `RowTrailing.text` (۷-۶): نمی‌شکند و بریده نمی‌شود (CA-02) و بر ستون متن اولویت دارد. ردیف ضربه‌پذیر و فوکوس‌پذیر نیست و hover ندارد (مثل ردیف بدون onTap در LC-03). گره‌ی Semantics آن ایستا است: «{عنوان}؛ {زیرعنوان}؛ همیشه فعال» بدون `toggled` و `button`. ارتفاع همان ردیف‌های جدول پ بدون جزء Switch است: ردیف بدون چیپ و فقط‌عنوان ۵۲ می‌شود (مثل ListRow در ۷-۶) و بقیه همان ۶۴ و ۷۶ می‌مانند. عرض ستون متن در ردیف چیپ‌دار ۲۳۲ منهای عرض اندازه‌گرفته‌ی متن «همیشه فعال» است.
- **TG-09 (ترتیب؛ HM-05):** `reorder` فقط در فهرست سفارشی‌سازی خانه (HM-05) و فقط روی ردیف عادی می‌آید. دو IconButton استاندارد (BU-08) هستند، هر کدام ۴۴×۴۴ با آیکون فلش بالا و پایین `icon-md`، با فاصله‌ی `space-2` از هم. `semanticLabel` و Tooltip هر دکمه TGX-01 و TGX-02 با عنوان ردیف است. دکمه‌ی «بالا» در ردیف اول و «پایین» در ردیف آخر غیرفعال می‌شود (`null`)، پنهان نمی‌شود. جابه‌جایی ردیف‌ها آنی است، چون حرکتی برای آن در جدول ۴-۳ ثبت نشده (CM-08). فوکوس روی همان دکمه می‌ماند و با ردیف جابه‌جا می‌شود؛ اگر آن دکمه به‌خاطر رسیدن به اول یا آخر غیرفعال شد، فوکوس به دکمه‌ی دیگر همان ردیف می‌رود. جایگاه تازه (TGX-04) با `polite` اعلام می‌شود. کشیدن برای ترتیب اختیاری است و جای دکمه‌ها را نمی‌گیرد (HM-05)؛ نسخه‌ی ۱ آن را نمی‌سازد.
- **TG-10 (Semantics و صفحه‌کلید):** Checkbox با `Semantics(checked: value)` و Switch و SwitchRow با `Semantics(toggled: value)` اعلام می‌شوند، به‌همراه `enabled`. وضعیت با ویژگی گفته می‌شود و به برچسب واژه‌ی «روشن»، «خاموش» یا «انتخاب‌شده» اضافه نمی‌شود (CM-05). برچسب SwitchRow «{عنوان}؛ {زیرعنوان}؛ {یادداشت}» به ترتیب دیداری است (LC-08) و برچسب نقش control همان `semanticLabel` است. Tab وارد کنترل می‌شود و Space و Enter مقدار را عوض می‌کنند (مثل SC-07)؛ ترتیب فوکوس در SwitchRow: ردیف، دکمه‌ی بالا، دکمه‌ی پایین. پس از تغییر مقدار فوکوس روی ردیف می‌ماند.
- **TG-11 (حرکت؛ MO-02):** با تغییر مقدار، دستگیره ۱۶px در جهت منطقی جابه‌جا می‌شود و علامت تیک (در دستگیره یا جعبه) با progress از ۰ تا ۱ رسم یا پاک می‌شود، با `exit` (۲۰۰ms) و `standard`. پرکننده‌ی track یا جعبه و رنگ دستگیره هم‌زمان با شفافیت دو لایه‌ی روی هم عوض می‌شوند، نه درون‌یابی رنگ (MT-04). همه‌ی اجزا با یک کنترلر و یک CustomPainter رسم می‌شوند، پس هر کنترل یک انیمیشن حساب می‌شود (MT-08). تغییر دوباره در میانه‌ی حرکت از مقدار فعلی ادامه می‌دهد (MT-07، MR-03). با کاهش حرکت همه آنی است. لایه‌ی hover و pressed MO-01 است.
- **TG-12 (ممنوع‌ها):** Radio و حالت نامعین (indeterminate) در نسخه‌ی ۱ نیستند (MO-02 رادیو را نام برده، ولی در ۷-۰ کامپوننتی برایش نیست؛ افزودنش ردیف تازه در ۷-۰ و تأیید Agent 1 می‌خواهد، CM-13)؛ متن «روشن» و «خاموش» یا هر برچسب درون یا کنار track؛ رنگ تأکید ماژول یا رنگ معنایی؛ حالت loading؛ دیالوگ تأیید برای تغییر سوئیچ (DM-03)؛ کشیدن دستگیره؛ Switch یا Checkbox در نقش `control` در trailing ListRow یا هر ردیف دیگر (ردیف تنظیمات SwitchRow است)؛ دو کنترل تغییر مقدار در یک ردیف؛ اندازه یا فاصله‌ی غیر از جدول‌های این زیربخش (TK-13).
- **TG-13 (متن‌ها):** متن‌های این زیربخش از کاتالوگ بخش ۹ می‌آیند (CM-10): TGX-01 «انتقال {عنوان} به بالا»، TGX-02 «انتقال {عنوان} به پایین»، TGX-03 «همیشه فعال» و TGX-04 «جایگاه {n} از {m}» (عددها از formatter مرکزی).
- **TG-14 (آزمون):** هر ردیف جدول ب یک آزمون ویجت و هر مورد زیر یک آزمون یا golden دارد؛ آزمون Semantics و ردیف نمونه در Style Guide هم لازم است (CM-13). الف) هندسه با `tester.getSize`: Switch در نقش control ۴۸×۴۴ با track ۴۸×۳۲ و دستگیره‌ی ۲۴؛ Checkbox ۴۴×۴۴ با جعبه‌ی ۲۴؛ در نقش indicator ۴۸×۳۲ و ۲۴×۲۴؛ جعبه‌ی چک در ListRow دقیقاً وسط جایگاه ۴۰×۴۰ است (۸ از هر سو). ب) جای دستگیره: خاموش ۴ و روشن ۲۰ (= ۴ + ۱۶) از لبه‌ی start، که در RTL قرینه می‌شود؛ علامت تیک فقط در حالت روشن و نشانه‌خورده است. پ) حرکت با FakeClock و MotionProbe (MX-08): جابه‌جایی دستگیره در ۰ و ۱۰۰ و ۲۰۰ms برابر ۰ و ۱۴٫۰ (با خطای ۰٫۵) و ۱۶ است؛ MotionProbe در ۱۰۰ms یک انیمیشن و در ۲۰۰ms صفر گزارش می‌دهد؛ تغییر دوباره در ۱۰۰ms از ۱۴٫۰ ادامه می‌دهد؛ با کاهش حرکت در ۰ms همان ۱۶ و صفر انیمیشن. ت) SwitchRow: ارتفاع و عرض ستون متن هر ردیف جدول پ (با متن کوتاه)؛ ضربه، Enter و Space هر کدام دقیقاً یک‌بار `onChanged(!value)` را صدا می‌زنند و ضربه روی دکمه‌ی ترتیب مقدار ردیف را عوض نمی‌کند؛ hover روی دکمه لایه‌ی ردیف را خاموش می‌کند؛ ترتیب Tab: ردیف، بالا، پایین؛ فوکوس پس از جابه‌جایی طبق TG-09. ث) Semantics: Checkbox با `checked`، Switch و SwitchRow با `toggled` و برچسب بدون «روشن» و «خاموش»؛ indicator گره ندارد؛ `.alwaysOn` فقط گره‌ی ایستا دارد و فوکوس‌ناپذیر است؛ دکمه‌های ترتیب برچسب و Tooltip یکسان TGX-01 و TGX-02 دارند. ج) تضاد همه‌ی جفت‌ها در هر دو تم از آستانه‌های ۲-۸ کمتر نیست (اسکریپت بخش ۱۱). چ) golden: Switch و Checkbox هر کدام خاموش، روشن و disabled؛ SwitchRow با چیپ و یادداشت، با دکمه‌های ترتیب و `.alwaysOn`؛ و «بدترین حالت» بخش ۱۰ (عنوان دوخطی) برای SwitchRow؛ همه در چهار ترکیب جهت × تم و مقیاس ۱٫۰ و ۲٫۰.
