### ۷-۱۲ حالت‌های خالی، خطا و بارگذاری (EmptyState، ErrorState، Skeleton)

این سه کامپوننت تنها راه نشان دادن «چیزی برای نمایش نیست»، «بارگذاری نشد» و «داده در راه است» هستند. هر کدام دو اندازه دارند: `regular` که جای MainContent صفحه را می‌گیرد (FeedbackState در PG-01 نام گروهی همین سه است، نه ویجت چهارم) و `small` که جای محتوای یک کارت یا Popover را می‌گیرد (۷-۵، ۷-۶، ۷-۷، HM-03، HM-07، VI-15، TB-03). EmptyState و ErrorState ایستا هستند و تصویرسازی ندارند (۱-۵، MT-10)؛ تنها حرکت این بخش MO-12 است و فقط به Skeleton تعلق دارد (حرکت دکمه‌های داخل آن‌ها از BU می‌آید). همه‌ی متن‌ها از کاتالوگ بخش ۹ یا props می‌آیند (CM-10).

```dart
// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum StateSize { regular, small }             // regular: جای MainContent (PG-01)؛ small: جای محتوای کارت یا Popover
enum StateEmphasis { primary, secondary }     // نقش دکمه‌ی اقدام (ST-04)
enum FeedbackKind { loading, empty, error }   // نام‌های PG-01 برای جای MainContent؛ حالت را use-case می‌دهد (ST-01)

class StateAction {
  const StateAction({
    required this.label,                      // از کاتالوگ متن (CM-10)؛ حداکثر سه کلمه (BU-03)
    required this.onPressed,
    this.emphasis = StateEmphasis.secondary,
    this.loading = false,                     // فقط برای «تلاش دوباره» (ST-04)
    this.loadingLabel,                        // مثل «در حال تلاش…»
  }) : assert(!loading || loadingLabel != null);
  final String label;
  final VoidCallback onPressed;
  final StateEmphasis emphasis;
  final bool loading;
  final String? loadingLabel;
}

class StateVM {                               // ورودی کارت‌ها: StateVM? stateContent (SC، LC، DY)
  const StateVM.empty({required this.title, this.description, this.icon, this.action, this.secondaryAction})
      : retry = null;
  const StateVM.error({required this.title, this.description, required this.retry, this.secondaryAction})
      : icon = null, action = null;
  final String title;                         // در small تنها متن (پیام) است
  final String? description;                  // فقط regular؛ در ErrorState regular الزامی (ST-03)
  final IconData? icon;                       // فقط EmptyState regular و الزامی؛ ErrorState آیکون ثابت دارد (ST-03)
  final StateAction? action, secondaryAction, retry;
}

class EmptyState extends StatelessWidget {
  const EmptyState({super.key, required this.vm, this.size = StateSize.regular});   // assertها: ST-02، ST-04، ST-05
  final StateVM vm;
  final StateSize size;
}

class ErrorState extends StatelessWidget {
  const ErrorState({super.key, required this.vm, this.size = StateSize.regular});   // assertها: ST-03، ST-04، ST-05
  final StateVM vm;
  final StateSize size;
}

enum SkeletonKind { heroCard, numberCard, listCard, dayRingCard, listRows, block }

class Skeleton extends StatelessWidget {      // فقط محتوای داخل قاب؛ قاب را والد می‌دهد (ST-06)
  const Skeleton.heroCard({super.key, required SummaryPlacement placement, int rows = 0});   // rows: ۰ تا ۲ (SC-02)
  const Skeleton.numberCard({super.key});
  const Skeleton.listCard({super.key});                                                     // سرتیتر و سه ردیف (LC-07)
  const Skeleton.dayRingCard({super.key, int rows = 3});                                    // rows: ماژول‌های فعال، ۱ تا ۳ (DY-01)
  const Skeleton.listRows({super.key});
  const Skeleton.block({super.key, required double height});                                // height از جدول والد (TK-13)
}
```

جدول ۷-۱۲-الف: اجزای EmptyState و ErrorState (واحد px؛ همه‌ی فاصله‌ها و اندازه‌ها توکن‌اند).

| جزء | regular | small |
| --- | --- | --- |
| جای‌گیری | بالای ناحیه‌ی MainContent و وسط‌چین افقی؛ فاصله‌ی بالا `space-12` (۴۸)؛ عرض بلوک `min(عرض ناحیه، ۳۸۸)` که ۳۸۸ برابر `side-panel-width` منهای دو `space-4` است | از start و به‌تمام‌عرض محتوای کارت؛ فاصله‌ی بیرونی ندارد و والد می‌دهد (ST-05) |
| آیکون | EmptyState: خطی، `text-secondary`، اندازه‌ی `state-icon` (۴۸)؛ ErrorState: آیکون خطای ثابت، `danger`، همان اندازه | EmptyState: ندارد؛ ErrorState: آیکون خطا `icon-md` (۲۰)، `danger`، در start و هم‌تراز اولین خط پیام |
| فاصله‌ی آیکون | تا عنوان `space-4` | تا پیام `space-2` (افقی) |
| عنوان یا پیام | عنوان `title-sm`، `text-primary`، وسط‌چین | پیام `body`؛ در EmptyState `text-secondary` و در ErrorState `text-primary`؛ تراز start |
| توضیح | `body`، `text-secondary`، وسط‌چین؛ فاصله‌ی بالا `space-2` | ندارد |
| دکمه‌ها | AppButton اندازه‌ی `md`؛ فاصله‌ی بالا `space-6`؛ دو دکمه زیر هم با فاصله‌ی `space-2`، وسط‌چین، عرض به اندازه‌ی برچسب | یک دکمه‌ی `secondary` اندازه‌ی `md` در start؛ فاصله‌ی بالا `space-3` |

جدول ۷-۱۲-ب: ارتفاع بلوک (px؛ عنوان، توضیح و پیام تک‌خطی در عرض ۳۶۰؛ برای مقیاس‌های میانی نتیجه‌ی هر خط یا کنترل به بالا گرد می‌شود). فرمول regular: ۴۸ + ۴۸ + ۱۶ + عنوان (۳۰×s) + \[۸ + توضیح (۲۸×s)\] + \[۲۴ + دکمه\] + \[۸ + دکمه‌ی دوم\]؛ فرمول small: پیام (۲۸×s) + \[۱۲ + دکمه\]؛ دکمه‌ی `md` برابر max(۴۴، ۲۲×s + ۱۶) است (BU-10).

| ترکیب | s = ۱٫۰ | s = ۱٫۵ | s = ۲٫۰ |
| --- | --- | --- | --- |
| regular: عنوان | ۱۴۲ | ۱۵۷ | ۱۷۲ |
| regular: عنوان و توضیح | ۱۷۸ | ۲۰۷ | ۲۳۶ |
| regular: عنوان، توضیح و یک دکمه | ۲۴۶ | ۲۸۰ | ۳۲۰ |
| regular: عنوان، توضیح و دو دکمه | ۲۹۸ | ۳۳۷ | ۳۸۸ |
| small: پیام | ۲۸ | ۴۲ | ۵۶ |
| small: پیام و دکمه | ۸۴ | ۱۰۳ | ۱۲۸ |

- **ST-01 (جای‌گیری):** `regular` فقط جای MainContent را می‌گیرد؛ PageHeader و FilterBar (و OfflineBanner وقتی آفلاین است) در هر سه حالت loading، empty و error سر جایشان می‌مانند (PG-01). `small` فقط درون قاب کارت (CM-12) یا Popover می‌نشیند: قاب و عنوان کارت می‌ماند (LC-07) و در SummaryCard و DayRingCard محتوای کارت کامل جایگزین می‌شود، پس برچسب و عدد ساخته نمی‌شوند (HM-03). در هر ناحیه در هر لحظه دقیقاً یکی از چهار چیز دیده می‌شود: Skeleton، EmptyState، ErrorState یا محتوای آماده؛ ترکیب دو تا (مثلاً Skeleton کنار ErrorState) ممنوع است. ترتیب تصمیم والد: نخستین بارگذاری ← Skeleton؛ شکست ← ErrorState؛ موفق و بی‌داده ← EmptyState؛ موفق و دارای داده ← محتوا. حالت را use-case می‌دهد و کامپوننت هرگز حدس نمی‌زند (CM-01).
- **ST-02 (EmptyState regular):** آیکون الزامی است: آیکون ماژول مالک صفحه از کاتالوگ ماژول‌ها (IN-2) یا آیکون معنایی همان زمینه (مثلاً جست‌وجو برای نتیجه‌ی خالی)؛ آیکون تزئینی تازه ممنوع است. آیکون خطی با `text-secondary` و اندازه‌ی `state-icon` است؛ `state-icon` برابر ۴۸ (دو برابر `icon-lg`) و **مقدار تازه‌ی این بخش** است، چون جدول ۲-۵ اندازه‌ای بین ۲۴ و سقف ۶۴ بخش ۱-۵ ندارد؛ ضخامت خط با همان نسبت ۲-۷ برابر ۳٫۵px می‌شود. هیچ آیکونی در این کامپوننت‌ها بزرگ‌تر از ۶۴ نیست (assert و آزمون ST-13). تصویرسازی، گرادیان، پس‌زمینه‌ی رنگی و قاب دور بلوک ندارد (۱-۵، TK-12). عنوان الزامی و توضیح اختیاری است. بلوک بالای ناحیه می‌نشیند (`space-12`، همان «بالای حالت خالی» جدول ۲-۵)، نه وسط عمودی، تا با چرخش دستگاه یا باز شدن صفحه‌کلید نپرد؛ ناحیه اسکرول‌شونده می‌ماند و تازه‌سازی بومی کار می‌کند (MT-09).
- **ST-03 (ErrorState regular):** ErrorState فقط برای «داده بارگذاری نشد» است؛ شکست اقدام کاربر (ذخیره، حذف، واگرد) درجا با FieldMessage (FD-05) یا Toast (۷-۱۳) گفته می‌شود. آیکون، همان آیکون خطای VI-13 و FD-05 است، ثابت است و پارامتر ندارد و رنگش `danger` است؛ رنگ هرگز تنها نیست: عنوان می‌گوید چه شد و توضیح می‌گوید چه باید کرد (CM-11، TK-04). توضیح در regular الزامی است. `retry` الزامی است و ErrorState بدون آن ساخته نمی‌شود (assert)؛ اقدام دوم اختیاری است (ST-04). تکان‌دادن، لرزش، چشمک و هر حرکتی ممنوع است (MT-10). علت شکست را use-case به‌صورت enum می‌دهد (unknown یا network)؛ UI حدس نمی‌زند و متن را از جدول ۷-۱۲-ث برمی‌دارد.
- **ST-04 (اقدام‌ها و تلاش دوباره):** اقدام یک `StateAction` است و با AppButton اندازه‌ی `md` ساخته می‌شود (BU-02)؛ برچسب حداکثر سه کلمه و بدون نقطه است (BU-03). emphasis پیش‌فرض `secondary` است، چون در Compact و Medium QuickAdd و در Expanded و Large دکمه‌ی اصلی PageHeader پیشاپیش دکمه‌ی پرِ صفحه‌اند (PG-03، BU-01). `primary` فقط در EmptyState regular و فقط برای اقدام اصلی صفحه‌ای مجاز است که دکمه‌ی پر دیگری ندارد (ModuleDisabledPage؛ DM-05) و حداکثر یکی است؛ ErrorState و small همیشه `secondary` دارند. دکمه‌ی دوم (`secondaryAction`) فقط در regular می‌آید: اگر اقدام اصلی `primary` است واریانت `secondary` می‌گیرد («بازگشت به خانه» در DM-05) و وگرنه `tertiary`. small یک دکمه‌ی `secondary` دارد یا هیچ. «تلاش دوباره» با `loading` کار می‌کند (BU-04، MO-13): ضربه برچسب را به «در حال تلاش…» crossfade می‌کند، دکمه غیرفعال می‌شود و عرضش ثابت می‌ماند و اسپینر پس از `skeleton-delay` می‌آید؛ ErrorState در تمام مدت می‌ماند و به Skeleton برنمی‌گردد، پس سوسو نمی‌زند. با شکست، دکمه دوباره عادی است و فوکوس را از دست نداده است (BU-05)؛ با موفقیت، والد ErrorState را با محتوا عوض می‌کند (ST-08).
- **ST-05 (small):** small بلوکی بی‌قاب است و والد جایش را می‌دهد: در SummaryCard و DayRingCard همان فاصله‌ی داخلی کارت (`space-4`؛ SC-01، DY-06)، در ListCard فاصله‌ی افقی `space-4` و فاصله‌ی عمودی `space-3` بالا و پایین مثل یک ردیف (LC-02) و در Popover (TB-03) فاصله‌ی `space-4`. متن تراز start است (در RTL سمت راست) و آیکون خطا آینه نمی‌شود (۲-۷). small فقط پیام دارد: description و `secondaryAction` در آن assert می‌شکنند؛ در EmptyState آیکون ندارد و در ErrorState آیکون خطای `icon-md` دارد. پیام یک جمله با نقطه‌ی پایانی است و بریده نمی‌شود، بلکه می‌شکند و بلوک بلندتر می‌شود (CM-07). ارتفاع طبق جدول ۷-۱۲-ب است؛ کارت‌ها ارتفاع ثابت ندارند (SC-01)، پس بریدگی و overflow نیست. متن EmptyState‌ِ small ویجت‌های خانه از جدول ویجت‌های HM-03 و برای DayRingCard از VI-15 می‌آید؛ متن تازه ساخته نمی‌شود.

جدول ۷-۱۲-پ: ارتفاع لوح خط (px). ارتفاع لوح = ارتفاع جعبه‌ی خط نقش × s (گرد به بالا) منهای ۸، یعنی دو `space-1`؛ لوح در جعبه‌ی خط وسط‌چین عمودی است و خود جعبه تغییر نمی‌کند، پس چیدمان Skeleton با کارت آماده یکی می‌ماند.

| نقش | caption | label | body-sm | body | title-sm | title | heading | display |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| جعبه‌ی خط (s = ۱٫۰) | ۲۰ | ۲۲ | ۲۴ | ۲۸ | ۳۰ | ۳۴ | ۴۴ | ۵۸ |
| ارتفاع لوح (s = ۱٫۰) | ۱۲ | ۱۴ | ۱۶ | ۲۰ | ۲۲ | ۲۶ | ۳۶ | ۵۰ |

جدول ۷-۱۲-ت: ترکیب‌های Skeleton (px؛ s = ۱٫۰). عرض هر لوح درصدی از عرض جایگاه همان لوح است (ستون متن برای عنوان و زیرعنوان ردیف، و کل عرض محتوای داخل قاب برای بقیه). سه درصد ۲۰٪ و ۴۰٪ و ۶۰٪ **مقدارهای تازه‌ی این بخش‌اند** و فقط شکل لوح‌ها را می‌سازند.

| ترکیب | لوح‌ها | ارتفاع | معادل آماده |
| --- | --- | --- | --- |
| `heroCard`، homeBalance | لوح برچسب (نقش label، ۴۰٪)، `space-1`، لوح عدد (display، ۶۰٪)؛ اگر ردیف هست `space-2` و برای هر ردیف (۰ تا ۲) لوح برچسب (body-sm، ۴۰٪) در start و لوح مقدار (body-sm، ۲۰٪) در end بدون فاصله‌ی میانی | ۱۱۶ بدون ردیف، ۱۴۸ با یک ردیف، ۱۷۲ با دو ردیف | جدول ۷-۵ |
| `heroCard`، moduleHero در Expanded و Large | همان با نقش heading برای عدد | ۱۰۲، ۱۳۴، ۱۵۸ | جدول ۷-۵ |
| `heroCard`، moduleHero در Compact و Medium | همان با نقش title برای عدد | ۹۲، ۱۲۴، ۱۴۸ | جدول ۷-۵ |
| `numberCard` | لوح عنوان (title-sm، ۴۰٪)، `space-1`، لوح مقدار (title-sm، ۶۰٪) | ۹۶ | SC-06 |
| `listCard` | سرتیتر ۶۰ (۱۶ + ۳۶ + ۸) با لوح عنوان (title-sm، ۴۰٪) وسط‌چین عمودی در بلوک ۳۶؛ سه ردیف ۷۶؛ دو Divider ۱px میان ردیف‌ها (LC-05) | ۲۹۰ (۶۰ + ۳ × ۷۶ + ۲) | LC-07 |
| `dayRingCard` | سه مسیر هم‌مرکز `ring-track` با شعاع ۸۷ و ۷۳ و ۵۹ و ضخامت ۱۰ بدون کمان و بدون متن مرکز (DY-02)؛ `rows` ردیف ۴۴ با لوح آیکون ۲۰×۲۰ (`radius-full`)، لوح برچسب (body، ۴۰٪) و لوح مقدار (body-sm، ۲۰٪)؛ چیدمان کنار یا زیر حلقه طبق DY-06 | زیر حلقه: ۲۷۲ و ۳۱۶ و ۳۶۰ (یک تا سه ردیف)؛ کنار حلقه: ۲۱۶ | جدول ۷-۷ |
| `listRows` | هر ردیف ۷۶ (۲ × `space-3` + ۵۲): لوح چیپ ۴۰×۴۰ (`radius-md`)، لوح عنوان (body، ۶۰٪)، لوح زیرعنوان (body-sm، ۴۰٪) و لوح مقدار (body، ۲۰٪) در end؛ تعداد ردیف‌ها ⌈ارتفاع در دسترس ÷ ۷۶⌉ و دست‌کم ۳؛ جداکننده‌ها را والد می‌گذارد | ۷۶ برای هر ردیف | جدول ۷-۶ |

- **ST-06 (Skeleton: ساختار):** Skeleton فقط ترکیب‌های `SkeletonKind` جدول ۷-۱۲-ت را دارد و لوح آزاد یا اسلات child ندارد (CM-02). لوح شکلی پر و بی‌مرز با رنگ `ring-track` است: خط متن `radius-sm`، چیپ `radius-md`، نقطه `radius-full` و بلوک `radius-lg`. لوح هیچ اطلاعاتی نمی‌دهد (نه متن، نه عدد، نه آیکون) و تزئینی است؛ از جفت‌های بررسی ۲-۸ و CM-09 معاف است و excludeSemantics می‌شود. Skeleton فقط محتوای داخل قاب را رسم می‌کند و قاب CM-12 را والد می‌دهد؛ تنها ترکیب `listCard` سرتیتر و Divider هم دارد، چون LC-07 نوار عنوان را هم Skeleton کرده است. جعبه‌ی هر لوح همان جعبه‌ی خط متنی است که جایش را می‌گیرد (جدول ۷-۱۲-پ)، پس ارتفاع Skeleton با ارتفاع کارت آماده‌ی تک‌خطی‌اش در هر مقیاس متن برابر است و با رسیدن داده هیچ چیدمانی نمی‌پرد. `rows` را والد از پیش می‌داند (ماژول‌های فعال، نقشه‌ی HI-01 صفحه)، نه از داده. Skeleton ضربه‌پذیر و فوکوس‌پذیر نیست (IgnorePointer و ExcludeFocus) و کارت در حالت loading ضربه‌پذیر نیست (۷-۵).
- **ST-07 (Skeleton: تأخیر و نبض؛ MO-12):** Skeleton از لحظه‌ی ساخته‌شدن تا `skeleton-delay` (۴۰۰ms) چیزی رسم نمی‌کند و جایش را با همان ابعاد نگه می‌دارد؛ اگر داده پیش از آن برسد Skeleton هرگز دیده نمی‌شود و محتوا بدون هیچ انیمیشنی می‌نشیند. کمینه‌ی زمان نمایش اضافه نشده است (عدد تازه ساخته نشد)؛ crossfade ST-08 جلوی پرش را می‌گیرد. پس از تأخیر لوح‌ها با شفافیت ۰٫۶ ظاهر می‌شوند و نبض شفافیت ۰٫۶ ← ۱٫۰ ← ۰٫۶ به مدت `skeleton-loop` (۱۲۰۰ms) تکرار می‌شود، هر نیمه با منحنی `standard`. همه‌ی لوح‌های یک صفحه با یک کنترلر مشترک نبض می‌زنند: `SkeletonScope` (در app\_motion، یکی برای هر صفحه) کنترلر را وقتی نخستین Skeleton دیده می‌شود شروع می‌کند، Skeletonهای دیرتر در فاز جاری به آن می‌پیوندند، و کنترلر وقتی هیچ Skeleton دیدنی نیست یا صفحه پوشیده است یا اپ در پس‌زمینه است می‌ایستد (LP-02، LP-03، LP-04). نبض با یک FadeTransition روی کل ترکیب اجرا می‌شود، نه جداگانه روی هر لوح، و ترکیب در RepaintBoundary است (PF-01). Skeleton فقط برای نخستین بارگذاری است که چیزی برای نمایش ندارد: بازخوانی با داده‌ی نشان‌داده‌شده، تازه‌سازی کشیدنی و همگام‌سازی پس‌زمینه Skeleton نمی‌سازند (MT-09) و اقدام کاربر (ذخیره، حذف) دکمه‌ی در حال انجام دارد (MO-13).
- **ST-08 (تعویض با محتوا و کاهش حرکت):** وقتی Skeleton دیده می‌شود و داده می‌رسد، تعویض آن با جایگزین (محتوای آماده، EmptyState یا ErrorState) یک crossfade به مدت `exit` (۲۰۰ms) و منحنی `standard` است: Skeleton از ۱ به ۰ و جایگزین از ۰ به ۱. اندازه بلافاصله به اندازه‌ی جایگزین می‌رسد (MT-04: انیمیشن اندازه ممنوع است) و دو لایه با تراز بالا و start روی هم می‌نشینند. این تنها تعویضی است که انیمیشن دارد؛ ready ← error، error ← ready، empty ← ready و تعویض دو محتوا آنی است (CM-08: ردیفی ثبت نشده) و ErrorState پس از «تلاش دوباره» به Skeleton برنمی‌گردد (ST-04). تعویض‌های هم‌فریم (مثل پنج کارت خانه) را `SkeletonScope` با یک کنترلر پیش می‌برد و در MT-08 یک انیمیشن حساب می‌شوند؛ تعویضی که شمار انیمیشن‌های هم‌زمان صفحه را از سه بیشتر کند آنی انجام می‌شود (مثل SV-01). با کاهش حرکت (RM-01) نبض می‌ایستد و لوح‌ها با شفافیت ثابت ۱٫۰ رسم می‌شوند (RM-03)، هیچ کنترلر حلقه‌ای فعال نیست و crossfade همان `exit` می‌ماند (ستون «کاهش حرکت» ردیف MO-12). تنها ردیف حرکت ST همین MO-12 است.

- **ST-09 (متن‌ها):** هیچ رشته‌ی فارسی در کد این کامپوننت‌ها نیست (CM-10): عنوان، توضیح، پیام و برچسب دکمه از کاتالوگ بخش ۹ می‌آیند و کامپوننت فقط آن‌ها را می‌گیرد. متن‌های پیش‌فرض خطا، نتیجه‌ی خالی جست‌وجو و برچسب Skeleton در جدول ۷-۱۲-ث (STX-01 تا STX-06) آمده‌اند؛ متن‌هایی که جای دیگری تعریف شده‌اند همان‌جا می‌مانند و تکرار نمی‌شوند: VI-15، HM-03 و جدول ویجت‌های خانه، HM-07، DM-05 و TB-03. الگوی متن خالی هر صفحه: عنوان جمله‌ی کوتاه بدون نقطه است که می‌گوید چه نیست («هنوز تراکنشی ثبت نکرده‌اید»)؛ توضیح یک جمله با نقطه است که راه پر شدنش را می‌گوید و اگر آن راه افزودن است، نام «ثبت سریع» (QX-01) را می‌آورد. این متن‌ها در ستون «حالت خالی» نقشه‌ی HI-01 همان صفحه می‌آیند و باید همین الگو را رعایت کنند. متن خطا مثل FD-05 است: چه شد و چه باید کرد، بدون سرزنش، کد فنی، علامت تعجب و ایموجی. لحن و قواعد نگارش بخش ۹ حاکم است.
- **ST-10 (حالت‌ها):** حالت‌های هر سه کامپوننت جدول ۷-۱۲-ج است. هیچ‌کدام از سه کامپوننت خودش ضربه‌پذیر یا فوکوس‌پذیر نیست؛ تنها عناصر تعاملی دکمه‌های داخل EmptyState و ErrorState هستند و حالت‌هایشان همان BU است (BU-09).
- **ST-11 (Semantics و فوکوس):** آیکون و لوح‌ها excludeSemantics هستند. EmptyState و ErrorState یک گره‌ی container با دو متن دارند: عنوان (در regular با header: true و در small بدون آن) و توضیح؛ دکمه‌ها گره‌های AppButton خودشان‌اند و به ترتیب دیداری فوکوس می‌گیرند. ErrorState liveRegion از نوع polite دارد و هنگام ظاهر شدن یک‌بار «{عنوان}. {توضیح}» (در small: پیام) خوانده می‌شود؛ EmptyState liveRegion ندارد، چون خالی‌بودن رویداد نیست. Skeleton هر صفحه یک گره‌ی واحد در SkeletonScope با برچسب «در حال بارگذاری» (STX-06) و liveRegion از نوع polite دارد که از لحظه‌ی دیده‌شدن نخستین Skeleton تا پایان آخرین فقط یک‌بار اعلام می‌شود؛ پایان بارگذاری اعلام جداگانه ندارد. در حالت‌های loading، error و empty گره‌ی خود این کامپوننت‌ها خوانده می‌شود، نه گره‌ی کارت (SC-09). اگر عنصر دارای فوکوس با تعویض بلوک ناپدید شد، فوکوس به اولین عنصر فوکوس‌پذیر محتوای جایگزین و اگر نبود به اولین عنصر فوکوس‌پذیر صفحه می‌رود (مثل OV-04، بند پ) و هرگز به ریشه‌ی برنامه نمی‌پرد.
- **ST-12 (ممنوع‌ها):** تصویرسازی، Lottie، Rive، GIF، ویدیو و هر حرکت در EmptyState یا ErrorState (۱-۵، MT-10)؛ اسپینر یا نوار پیشرفت بی‌پایان به‌جای Skeleton برای بارگذاری صفحه یا کارت (LP-01؛ اسپینر فقط در دکمه‌ی در حال انجام است)؛ Skeleton برای دکمه، فیلد، PageHeader، FilterBar و TopBar (PG-01)؛ عدد یا متن ساختگی در لوح‌ها (MT-10: هیچ چیز ساختگی)؛ Toast یا دیالوگ برای شکست بارگذاری، چون Toast بازخورد اقدام است؛ EmptyState یا ErrorState تودرتو؛ ErrorState برای خطای یک فیلد (FieldMessage؛ FD-05)؛ دکمه‌ی `primary` در small و در ErrorState (ST-04)؛ و آیکون بزرگ‌تر از ۶۴ (۱-۵).

بلوک گرادیان یا سایه ندارد؛ ۴) در ۳۹۹ms هیچ لوحی رسم نمی‌شود و جای Skeleton با ابعاد کامل رزرو است، در ۴۰۰ms رسم می‌شود؛ اگر داده در ۳۹۹ms برسد Skeleton هرگز رسم نمی‌شود و محتوا بدون انیمیشن می‌نشیند؛
