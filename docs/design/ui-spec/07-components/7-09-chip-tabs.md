### ۷-۹ چیپ و تب (`Chip`، `Tabs`)

`Chip` کنترلی گرد است که یک مقدار فعلی را نشان می‌دهد و با ضربه، انتخاب‌گرِ آن مقدار را باز می‌کند؛ مقدارهای پیش‌فرض ثبت سریع (دسته، حساب، تاریخ، سررسید) با آن ساخته می‌شوند (CP-01). `Tabs` در نسخه‌ی اول فقط یک واریانت دارد، `segmented`، برای انتخاب یکی از ۲ تا ۴ گزینه‌ی کوتاه که محتوای همان نما یا فرم را عوض می‌کند (QT-03، SD-05). هر جا در جدول ۴-۳ «SegmentedControl» آمده، همین `Tabs` با واریانت `segmented` است.

```dart
enum ChipKind { value, empty }            // empty فقط برای «ساخت حساب» و «انتخاب حساب» (CT-03)
enum ChipRowSeparator { none, direction } // direction فقط در ردیف مبدأ و مقصد transfer (CT-04)

class ChipVM {
  const ChipVM({
    required this.kind,
    required this.label,           // متن دیداری؛ از formatter مرکزی یا کاتالوگ (CM-10)
    required this.semanticLabel,   // مثل «دسته: غذا»؛ از قالب کاتالوگ (AQ-01)
    required this.icon,            // نام معنایی از رجیستر آیکون (ADR-UI-005)
  });
  final ChipKind kind;
  final String label;
  final String semanticLabel;
  final AppIcon icon;
}

class AppChip extends StatelessWidget {
  const AppChip({
    required this.vm,
    required this.onPressed,       // null یعنی disabled
    this.readOnly = false,         // true در saving (IDP-02)
    this.expanded = false,         // true فقط وقتی Popover همین چیپ باز است
  });
  final ChipVM vm;
  final VoidCallback? onPressed;
  final bool readOnly;
  final bool expanded;
}

class ChipRow extends StatelessWidget {
  ChipRow({required this.chips, this.separator = ChipRowSeparator.none})
      : assert(chips.length >= 1 && chips.length <= 3),
        assert(separator == ChipRowSeparator.none || chips.length == 2);
  final List<AppChip> chips;
  final ChipRowSeparator separator;
}

enum TabsVariant { segmented }            // نسخه‌ی اول فقط همین (CT-06)

class TabItem<T> {
  const TabItem({required this.id, required this.label}); // label از کاتالوگ (QX-02)
  final T id;
  final String label;
}

class AppTabs<T> extends StatelessWidget {
  AppTabs({
    required this.items,           // ۲ تا ۴ مورد
    required this.selected,        // باید id یکی از items باشد
    required this.onChanged,       // فقط وقتی انتخاب واقعاً عوض شود
    this.variant = TabsVariant.segmented,
    this.enabled = true,
    this.readOnly = false,         // true در saving (IDP-02)
  }) : assert(items.length >= 2 && items.length <= 4);
  final List<TabItem<T>> items;
  final T selected;
  final ValueChanged<T> onChanged;
  final TabsVariant variant;
  final bool enabled;
  final bool readOnly;
}
```

| loading، error | ندارد؛ انتخاب نوع حالت ناهم‌زمان و خطا ندارد | ندارد |

- **CT-01 (نقش `Chip`):** `Chip` فقط مقدار فعلی یک فیلد را نشان می‌دهد و انتخاب‌گرش را باز می‌کند. حالت «انتخاب‌شده» و «انتخاب‌نشده» ندارد و برای روشن و خاموش کردن چیزی به کار نمی‌رود (برای آن `Switch` و `Checkbox` هست). فلش یا نشانک کشویی، شمارنده، نشان، آواتار و دکمه‌ی بستن روی چیپ ممنوع است؛ شکل گرد با مرز و آیکونش خودش می‌گوید ضربه‌پذیر است.
- **CT-02 (متن و Semantics):** متن چیپ از formatter مرکزی یا کاتالوگ می‌آید و در ویجت ساخته یا الحاق نمی‌شود (CM-10)؛ تاریخ طبق CP-01 و بخش ۳-۵. `semanticLabel` را فراخواننده از قالب‌های AQ-01 می‌سازد («دسته: {نام}»، «حساب: {نام}»، «تاریخ: {تاریخ}»، «از حساب: {نام}»، «به حساب: {نام}»؛ برای چیپ خالی «حساب: ساخت حساب» و مانند آن). در debug اگر `label` (بدون نقطه‌گذاری و «…») درون `semanticLabel` نباشد `assert` می‌شکند (CM-05). گره‌ی Semantics: `button: true`، `enabled` و همان برچسب؛ در `readOnly` اقدام ضربه ندارد؛ با `expanded` برابر true مقدار `Semantics(expanded: true)` را دارد. آیکون چیپ تزئینی است (`excludeSemantics`).
- **CT-03 (دو نوع):** `value` مقدار فعلی است؛ مقدارهای «هیچ» مثل «بدون دسته» (QX-06) و «بدون سررسید» (QX-12) هم `value` هستند، چون مقدار معتبرند، و ظاهر ویژه ندارند. `empty` فقط دعوت به اقدام است و فقط برای «ساخت حساب» (QX-07) و «انتخاب حساب» (QX-22) به کار می‌رود (SD-05). نوع تازه‌ی چیپ خالی بدون ردیف تازه در این جدول و تأیید Agent 1 ساخته نمی‌شود.
- **CT-04 (ردیف چیپ‌ها):** `ChipRow` طبق CP-02 همیشه یک خط است: ۱ تا ۳ چیپ، فاصله‌ی `space-2` میان آن‌ها، عرض مساوی و هم‌ارتفاع (ارتفاع بلندترین چیپ)، و در هر مقیاس متن به خط بعد نمی‌شکند. با `ChipRowSeparator.direction` (فقط برای دو چیپ مبدأ و مقصد در transfer) میان دو چیپ جایگاهی به عرض ثابت ۳۶px (= `icon-md` + ۲×`space-2`) هست که به‌جای فاصله‌ی معمولی می‌نشیند و آیکون جهت‌دار `icon-md` با `text-secondary` را وسطش می‌گذارد (از start به end طبق ۲-۷، با `excludeSemantics`)؛ چیپ‌ها عرض باقی‌مانده را مساوی تقسیم می‌کنند. نمونه در ظرف ۳۲۸px: سه چیپ هر کدام ۱۰۴px ((۳۲۸ − ۲×۸) ÷ ۳) و دو چیپ transfer هر کدام ۱۴۶px ((۳۲۸ − ۳۶) ÷ ۲). در مقیاس متن بزرگ ممکن است فقط چند نویسه دیده شود؛ این استثنای روشن CM-07 است، چون CP-02 «یک خط با …» گفته، و متن کامل در Semantics و در انتخاب‌گر هست؛ این مورد در ریسک‌ها (بخش ۱۲) ثبت می‌شود.
- **CT-05 (ضربه و انتخاب‌گر):** چیپ فقط `onPressed` را صدا می‌زند؛ خودش انتخاب‌گری باز نمی‌کند و اندازه‌ی صفحه را نمی‌خواند. `Select` و `DatePicker` با واریانت `chip` همین `AppChip` را به‌عنوان ماشه‌ی خود رسم می‌کنند (CP-01) و باز کردن انتخاب‌گر (BottomSheet در Compact و Medium، Popover در Expanded و Large) با آن‌هاست (۷-۱۰). مقدار تازه در همان فریمی که انتخاب‌گر شروع به بسته شدن می‌کند در چیپ می‌نشیند و تعویض متن انیمیشن ندارد. پس از انتخاب فوکوس به فیلد اصلی نوع می‌رود (CP-01)؛ اگر انتخاب‌گر بی‌انتخاب بسته شود (Escape، پس‌زمینه، کشیدن، بازگشت) فوکوس به همین چیپ برمی‌گردد. چیپ و تغییرش هرگز پنجره‌ی ثبت سریع را «تغییردار» نمی‌کند (DR-01).
- **CT-06 (کاربرد `Tabs`):** `Tabs` فقط واریانت `segmented` و ۲ تا ۴ بخش دارد؛ بخش‌ها گزینه‌های کوتاهی هستند که هم‌زمان فقط یکی از آن‌ها برقرار است (یک یا دو واژه) و همیشه یکی انتخاب شده است (حالت «هیچ‌کدام» ندارد). کاربردهای نسخه‌ی اول فقط QT-03 و SD-05 است. کاربرد تازه فقط با ثبت در نقشه‌ی اطلاعات صفحه (HI-01) و تأیید Agent 1 در دروازه‌ی بازبینی صفحه (بخش ۱۴) مجاز است؛ واریانت تازه (مثل زبانه‌ی خط‌زیرین) یا بیش از ۴ بخش فقط با ردیف تازه در ۷-۰ (CM-13). ناوبری سطح‌بالا (`BottomNav`، `Rail` و `Sidebar`) `Tabs` نیست و فقط MO-03 را با آن مشترک دارد.
- **CT-07 (عرض بخش‌ها):** عرض داخلی ظرف W برابر عرض ظرف منهای ۶ است (دو مرز ۱px و دو padding ۲px). نیاز هر بخش برابر عرض متن برچسبش در مقیاس متن فعلی به‌علاوه‌ی ۲×`space-2` است. الف) اگر نیاز هیچ بخشی از W ÷ تعداد بخش‌ها بیشتر نباشد، همه‌ی بخش‌ها عرض مساوی W ÷ تعداد را می‌گیرند. ب) وگرنه اگر مجموع نیازها از W بیشتر نباشد، عرض هر بخش برابر نیاز آن × W ÷ مجموع نیازهاست. پ) وگرنه عرض هر بخش برابر نیاز آن است و ظرف افقی اسکرول می‌شود (بدون نوار اسکرول دیدنی)؛ بخش انتخاب‌شده هنگام ساخت و پس از هر تغییر انتخاب، بدون انیمیشن، کاملاً در دید می‌آید. برچسب بخش هرگز نمی‌شکند و بریده نمی‌شود؛ این استثنای روشن CM-07 است، چون به‌جای شکستن متن، عرض‌ها طبق همین قاعده تنظیم می‌شوند. عرض متن با همان فونت و همان `textScaler` و با `TextPainter` اندازه گرفته می‌شود، نه با تخمین.
- **CT-08 (صفحه‌کلید و فوکوس):** `Tabs` یک توقف Tab دارد (AQ-02): فوکوس روی بخش انتخاب‌شده می‌آید و بخش‌های دیگر با Tab فوکوس نمی‌گیرند. کلیدهای ← و → فوکوس را به بخشِ مجاور در همان سمتِ دیده‌شده می‌برند و همان بخش را انتخاب می‌کنند (در RTL بخش سمت راست زودتر در ترتیب است؛ پس → به بخش پیشین و ← به بخش بعدی می‌رود). Home و End اولین و آخرین بخش را انتخاب می‌کنند؛ در دو سر چرخش نیست؛ ↑ و ↓ و Enter و Space کاری نمی‌کنند. چون انتخاب همراه فوکوس عوض می‌شود، فوکوس همیشه روی بخش انتخاب‌شده است و حلقه‌ی فوکوس دور کل ظرف رسم می‌شود. ضربه روی بخش انتخاب‌شده `onChanged` را صدا نمی‌زند. در `Chip` هر چیپ یک توقف Tab است و Enter و Space مثل ضربه عمل می‌کنند.
- **CT-09 (Semantics تب):** ظرف یک گره‌ی بدون برچسب (`container: true`) است؛ هر بخش یک گره با `button: true`، `selected` (فقط بخش انتخاب‌شده)، `inMutuallyExclusiveGroup: true` و برچسب برابر متن دیداری است (AQ-01). جایگاه «n از m» را پلتفرم اعلام می‌کند و ما متن اضافه نمی‌سازیم. در `readOnly` گره‌ی بخش‌ها اقدام ضربه ندارند و در `disabled` برابر `enabled: false` هستند. ترتیب خواندن همان ترتیب دیداری است (CM-05).
- **CT-10 (حرکت):** `Chip` فقط MO-01 دارد. `Tabs` علاوه بر MO-01 (بخش انتخاب‌نشده) MO-03 را دارد: نشانگر با `base` و `standard` از بخش قبلی به بخش تازه می‌لغزد و رنگ برچسب‌ها هم‌زمان با همان مدت و منحنی درون‌یابی می‌شود؛ با کاهش حرکت هر دو آنی‌اند. نخستین رسم و تغییر تعداد بخش‌ها یا عرض ظرف (چرخش، تغییر اندازه‌ی پنجره، تغییر مقیاس متن) انیمیشن ندارد: نشانگر در همان فریم جای نهایی را می‌گیرد. اگر حین لغزش انتخاب دوباره عوض شود، نشانگر از جای فعلی‌اش به هدف تازه می‌رود و مدت `base` از نو شمرده می‌شود. هیچ چیز دیگری حرکت نمی‌کند: ریپل، تغییر مقیاس، انیمیشن تعویض متن چیپ و لغزش محتوای پشت تب ندارند.
- **CT-11 (رنگ):** رنگ نشانگر `Tabs` از `context.accent` می‌آید (در ثبت سریع `primary`؛ QD-01)؛ رنگ ثابت یا رنگ ماژولی دیگر ممنوع است. `Chip` فقط توکن‌های خنثی و `focus-ring` را دارد و به `AccentScope` وابسته نیست.
