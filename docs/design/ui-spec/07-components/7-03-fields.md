### ۷-۳ فیلدها: `TextField`، `NumberField` و `FieldMessage`

فیلدها برچسب دائمی در بالا دارند؛ برچسب شناور و جایگزین‌شدن برچسب با جای‌نگهدار ممنوع است. زیر هر فیلد یک `FieldMessage` است (راهنما یا خطا). `NumberField` ورودی عددی دقیق و بدون `double` است و پایه‌ی فیلد مبلغ ثبت سریع (AM-01) است.

```dart
enum FieldMessageKind { helper, error }
enum FieldEmphasis { normal, hero } // hero فقط در ثبت سریع (FD-11)

class FieldMessage extends StatelessWidget {
  const FieldMessage({required this.kind, required this.text});
  final FieldMessageKind kind;
  final String text;                // از کاتالوگ متن (CM-10)
}

class AppTextField extends StatelessWidget {
  const AppTextField({
    required this.label,            // برچسب دائمی بالای فیلد
    required this.controller,
    this.showLabel = true,          // false فقط طبق FD-01
    this.semanticLabel,             // الزامی وقتی showLabel == false
    this.hint,                      // مثال یا قالب (FD-02)
    this.helper,                    // یک خط راهنما
    this.error,                     // null یعنی بدون خطا
    this.optional = false,          // «(اختیاری)» کنار برچسب
    this.maxLength,
    this.isTechnical = false,       // ایمیل، URL، کد: LTR (FD-08)
    this.clearable = false,
    this.enabled = true,
    this.readOnly = false,
    this.textInputAction,
  }) : assert(showLabel || (semanticLabel != null && semanticLabel == hint));
}

class AppNumberField extends StatelessWidget {
  const AppNumberField({
    required this.label,
    required this.value,            // رشته‌ی کانونی ASCII مثل '1250000' یا '12.5'؛ خالی: ''
    required this.onChanged,        // ValueChanged<String>
    required this.maxIntegerDigits, // سقف رقم‌های صحیح (AM-01)
    this.fractionDigits = 0,        // ۰ برای ریال و تومان، ۲ برای دلار
    this.unit,                      // مثل «تومان»؛ غیرقابل‌ویرایش
    this.emphasis = FieldEmphasis.normal,
    this.error,
    this.autofocus = false,
  });
}
```

| بخش | مقدار |
| --- | --- |
| برچسب | `label` با `text-primary`، بالای فیلد با فاصله‌ی `space-1`؛ برای فیلد اختیاری کنارش «(اختیاری)» با `caption` و `text-secondary` |
| ظرف فیلد | حداقل ارتفاع `control-md` (۴۴)؛ شعاع `radius-md`؛ پس‌زمینه‌ی `surface`؛ فاصله‌ی افقی داخلی `space-3` و عمودی `space-2` |
| مرز | ۱px `border-strong`؛ ۲px برای focus و error رزرو شده است، پس محتوا هنگام تغییر مرز جابه‌جا نمی‌شود |
| متن و جای‌نگهدار | متن `body` با `text-primary`؛ جای‌نگهدار `body` با `text-secondary` |
| آیکون‌ها | `icon-md`؛ دکمه‌ی «پاک کردن» (`IconButton` با ناحیه‌ی ۴۴) فقط وقتی `clearable` است و فیلد فوکوس دارد و خالی نیست |
| شمارنده | `caption` با `text-secondary` در `end` ردیف پیام؛ فقط وقتی `maxLength` هست و حداکثر ۲۰ نویسه باقی مانده (FD-03) |

| نوع پیام | محتوا | رنگ و نقش | Semantics |
| --- | --- | --- | --- |
| `helper` | فقط متن | `caption` با `text-secondary`؛ بدون آیکون | `hint` فیلد |
| `error` | آیکون خطا (`icon-sm`) و متن | آیکون و متن `danger`؛ متن `body-sm` | `liveRegion` از نوع assertive و `errorText` فیلد |

ارتفاع بلوک پیام خطا برابر خط `body-sm` (۲۴) به‌علاوه‌ی دو برابر `space-1` یعنی ۳۲ است؛ آیکون در start و متن کنارش با فاصله‌ی `space-2` می‌آید و تا دو خط می‌شکند.

| حالت | قاعده |
| --- | --- |
| عادی | مرز ۱px `border-strong` |
| hover (فقط ماوس) | لایه‌ی `text-primary` با شفافیت ۰٫۰۸ روی ظرف (MO-01) |
| focus (هر روش ورودی) | مرز ۲px `focus-ring` و بدون حلقه‌ی بیرونی. این تنها استثنای قاعده‌ی «حلقه فقط برای صفحه‌کلید» (بخش ۲-۶) است، چون فیلد فوکوس‌دار همیشه در حالت درج است |
| disabled | سطح و محتوا و مرز: `text-primary` با شفافیت ۰٫۱۲ و ۰٫۳۸؛ فوکوس‌پذیر نیست؛ `Semantics(enabled: false)` |
| readOnly | مثل عادی ولی مرز `border`؛ فوکوس‌پذیر و قابل انتخاب و کپی، بدون ویرایش |
| loading | ندارد؛ بررسی ناهم‌زمان با `FieldMessage(helper)` گفته می‌شود |
| error | مرز ۲px `danger` به‌علاوه‌ی `FieldMessage(error)` (FD-05)؛ اگر فیلد هم‌زمان فوکوس دارد مرز `danger` می‌ماند و `focus-ring` جایش را نمی‌گیرد |

- **FD-01 (برچسب):** هر فیلد برچسب دیداری دائمی بالای فیلد دارد. فهرست استثناها کامل و سه‌تایی است: ۱) فیلد درون‌خطی‌ای که با یک دکمه‌ی متنی باز می‌شود (NT-01 «افزودن یادداشت»)؛ ۲) فیلد جست‌وجوی انتخابگر (PK-04؛ PKX-06)؛ ۳) فیلد نوار ورودی دستیار (AI-05؛ AIX-18). در هر سه `showLabel: false` مجاز است، به شرط آن‌که `hint` و `semanticLabel` یک متن باشند (QX-09 «یادداشت (اختیاری)»)؛ سازنده این را `assert` می‌کند. استثنای چهارم ندارد مگر با تأیید Agent 1 و ثبت در همین بند (CM-13).
- **FD-02 (اختیاری و جای‌نگهدار):** فیلد الزامی نشانگر ندارد و فیلد اختیاری با «(اختیاری)» کنار برچسب مشخص می‌شود؛ ستاره ممنوع است. جای‌نگهدار فقط مثال یا قالب است («مثلاً: خرید نان»؛ QX-12)، هرگز جای برچسب یا توضیح ضروری نیست و با شروع تایپ ناپدید می‌شود.
- **FD-03 (طول):** حد `maxLength` را خود فیلد اعمال می‌کند (۲۰۰ برای یادداشت NT-01 و ۱۲۰ برای عنوان کار TS-01): نویسه‌ی اضافه وارد نمی‌شود و paste در حد مجاز بریده می‌شود، بدون هیچ پیام خطا. نویسه یعنی یک واحد نمایشی (grapheme cluster)، پس نیم‌فاصله جدا شمرده نمی‌شود. شمارنده‌ی «۱۸۵ از ۲۰۰» (با حالت ارقام کاربر) وقتی حداکثر ۲۰ نویسه باقی مانده در `end` ردیف پیام دیده می‌شود و در Semantics هم خوانده می‌شود.
- **FD-04 (زمان خطا):** خطا هنگام تایپ ظاهر نمی‌شود. پیش‌فرض: پس از ترک فیلد، پس از ضربه‌ی دکمه‌ی اصلی، یا پس از شکست عملیات؛ قاعده‌ی هر فیلد می‌تواند زودتر یا دیرتر بگوید (SD-05: پس از ضربه‌ی «ساخت حساب»). خطا با نخستین ویرایش همان فیلد پاک می‌شود. خالی‌بودنِ فیلد الزامی هرگز خودبه‌خود خطا نیست و فقط دکمه‌ی اصلی غیرفعال می‌ماند (AM-04). اگر چند فیلد هم‌زمان خطا دارند، فوکوس به نخستین فیلد خطادار به ترتیب دیداری می‌رود.
- **FD-05 (قالب خطای فیلد):** خطا همیشه `FieldMessage(kind: error)` است: آیکون خطا و متن `body-sm` هر دو `danger`، با `liveRegion` از نوع assertive که هنگام ظاهر شدن اعلام می‌شود؛ همان متن در `errorText` فیلد هم می‌آید و مرز فیلد ۲px `danger` می‌شود. این قالبی است که SD-05 (QX-21)، AM-04 (QX-18) و IDP-04 (QX-16) به آن ارجاع می‌دهند؛ فقط جایش فرق می‌کند: زیر فیلد، زیر ردیف چیپ‌ها، یا بالای دکمه‌ی اصلی در ناحیه‌ی ثابت پایین. متن خطا یک جمله‌ی کامل فارسی است که می‌گوید چه شد و چه باید کرد، با «.» تمام می‌شود، بدون سرزنش و بدون کد فنی است و تا دو خط می‌شکند.
- **FD-06 (راهنما و تک‌پیامی):** `FieldMessage(kind: helper)` همان خط راهنمای SD-05 و QX-08 است و `danger` ندارد. در هر ناحیه‌ی پیام حداکثر یک `FieldMessage` هست و خطا بر راهنما برتری دارد؛ هرگز دو پیام هم‌زمان زیر یک فیلد یا بالای یک دکمه نیست.
- **FD-07 (Semantics و فوکوس):** گره‌ی `textField` با برچسب برابر برچسب دیداری (و در حالت `showLabel: false` برابر `semanticLabel`)، `hint` برابر راهنما، `errorText` برابر خطا و `readOnly` و `enabled` مطابق حالت ساخته می‌شود. برچسب جداگانه فوکوس نمی‌گیرد. `textInputAction` فیلد اصلی ثبت سریع `done` است (Enter ثبت می‌کند؛ BT-01) و فیلدهای میانی `next`. فوکوس خودکار فقط جاهایی است که این سند گفته است: AM-01، نام حساب در SD-05 و فیلد یادداشت در NT-01.
- **FD-08 (فیلد فنی):** ایمیل، URL، کد و شناسه‌ها با `isTechnical: true` ساخته می‌شوند: جهت متن همیشه LTR و هم‌ترازی در start است (RT-04) و جای‌نگهدار با جهت رابط می‌ماند.
- **FD-09 (`NumberField`: مقدار):** مقدار همیشه رشته‌ی کانونی ASCII است (خالی، یا `^[0-9]+(\.[0-9]+)?$` بدون گره‌بندی و بدون صفر ابتدایی مگر خودِ «۰») و هرگز `double` یا `int` نیست؛ تبدیل به واحد کوچک کار use-case است (MN-01؛ مسئله‌ی دقت عدد صحیح در وب در بخش ۱۲). ورودی کاربر طبق NM-05 تحلیل می‌شود.
- **FD-10 (`NumberField`: گره‌بندی، paste و سقف):** گره‌بندی با هر نویسه اعمال می‌شود و مکان‌نما نمی‌پرد: جای مکان‌نما با «تعداد رقم‌های قبل از آن» حفظ می‌شود، نه با اندیس نویسه. رقم یا اعشار بیش از `maxIntegerDigits` و `fractionDigits` پذیرفته نمی‌شود و بدون خطا ساکت است (AM-01). paste پس از تحلیل NM-05 اگر هیچ رقم معتبری نداشت نادیده گرفته می‌شود، خطای «عدد معتبر وارد کنید.» نشان داده می‌شود و مقدار قبلی می‌ماند؛ اگر بیش از سقف بود تا سقف بریده می‌شود.
- **FD-11 (`NumberField`: ظاهر):** ارقام هم‌عرض‌اند (NM-04) و عدد در یک جزیره‌ی LTR در start ظرف (راست در RTL) هم‌تراز می‌شود؛ واحد (`caption` با `text-secondary`) در لبه‌ی `end` ظرف است، غیرقابل‌ویرایش است و بیرون از ناحیه‌ی فوکوس می‌ماند. `emphasis: normal` مثل `TextField` است. `emphasis: hero` فقط در ثبت سریع است (AM-01): ارتفاع ثابت ۶۰ (خط `heading` یعنی ۴۴ به‌علاوه‌ی دو برابر `space-2`) که با تغییر پله‌ی AM-02 عوض نمی‌شود تا چیدمان نپرد؛ نقش متن عدد طبق AM-02 و واحد `caption` است. وقتی عدد در کوچک‌ترین پله هم جا نشد، ناحیه‌ی عدد افقی اسکرول می‌شود و رقم در حال تایپ همیشه دیده می‌ماند.
- **FD-12 (آزمون):** برای `TextField` هر ردیف جدول حالت‌ها یک آزمون ویجت و یک golden دارد. مکان متن در حالت‌های عادی، focus و error دقیقاً یکی است (اختلاف صفر پیکسل). در حالت خطا `FieldMessage` دارای `liveRegion` و `errorText` است. `maxLength`: نویسه‌ی ۲۰۱ وارد نمی‌شود، paste با ۲۵۰ نویسه به ۲۰۰ بریده می‌شود و شمارنده از نویسه‌ی ۱۸۰ دیده می‌شود. فیلد بدون برچسب دیداری فقط وقتی ساخته می‌شود که `hint` و `semanticLabel` یکی باشند. برای `NumberField`: بردارهای جدول ۳-۸ (`۱٬۲۵۰٬۰۰۰`، `1,250,000` و `١٬٢٥٠٬٠٠٠` همگی `1250000`؛ paste مقدار `abc` ← خطا و مقدار قبلی)؛ تایپ `1234567` عدد `۱٬۲۳۴٬۵۶۷` می‌دهد و درج یک رقم در وسط مکان‌نما را پس از همان رقم نگه می‌دارد؛ سقف‌های ۱۸ و ۱۷ رقم و ۱۶ رقم صحیح با دو اعشار (TQ-13)؛ ارتفاع حالت `hero` در هر سه پله‌ی AM-02 برابر ۶۰ است.
- **FD-13 (بلوک عنوان کار):** فیلد عنوان نوع task در ثبت سریع (TS-01، QT-03) بلوکی است که از بالا به پایین این اجزا را دارد: برچسب دائمی «عنوان کار» (label، `text-primary`، ارتفاع خط `22×s`)، فاصله‌ی `space-1` (۴) و یک TextField تک‌خطی با maxLength برابر ۱۲۰ (FD-03) و حداقل ارتفاع `max(44, 28×s + 16)` یعنی ۴۴ و ۵۸ و ۷۲. ارتفاع بلوک `22×s + 4 + ارتفاع فیلد` است: ۷۰ و ۹۵ و ۱۲۰ در مقیاس متن ۱٫۰ و ۱٫۵ و ۲٫۰ (جدول‌های ۷-۱۱-الف و ث). فیلد جای‌نگهدار «مثلاً: خرید نان» (QX-12) و فوکوس خودکار دارد و حالت error ندارد: عنوان خالی یا فقط‌فاصله فقط دکمه‌ی اصلی را غیرفعال نگه می‌دارد و پیامی نمی‌سازد (TS-01). ردیف شمارنده‌ی FD-03 جزو این ارتفاع نیست؛ وقتی دیده می‌شود (حداکثر ۲۰ نویسه مانده) به محتوای Z2 پنجره `20×s + 8` اضافه می‌کند و ارتفاع ظرف را عوض نمی‌کند (QD-04). آزمون: ارتفاع بلوک در سه مقیاس برابر اعداد بالا است و مکان متن عنوان در حالت‌های عادی و focus دقیقاً یکی است (FD-12).
