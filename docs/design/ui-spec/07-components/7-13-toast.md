### ۷-۱۳ پیام کوتاه (Toast)

Toast بازخورد کوتاهِ اقدامی است که کاربر همین لحظه انجام داده: ثبت موفق، نتیجه‌ی واگرد، روشن یا خاموش‌شدن یک ماژول. کامپوننت پایه است و با use-case حرف نمی‌زند (CM-01)؛ ساخت ToastVM از رویداد دامنه، مثل QuickAddSavedEvent، کار فراخواننده است (ترتیب‌دهنده‌ی SV-01). قاب از CM-12 و مدت‌ها از `toast-visible` و `toast-undo-visible` (بخش ۴-۲) می‌آیند و تنها حرکتش MO-10 است.

```dart
// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum ToastKind { standard, error }                 // error: آیکون خطا، بدون سطر دوم و اقدام (TO-02)
enum ToastCloseReason { timeout, action, tapped, replaced, dismissed }

sealed class ToastDetail {                         // سطر دوم؛ فقط همین سه شکل (QX-14)
  factory ToastDetail.text(String text) = _TextDetail;                                  // عنوان کار؛ «داده‌های شما نگه داشته شد.»
  factory ToastDetail.money({required MoneyVM money, required String label}) = _MoneyDetail;   // [مبلغ] · [نام دسته]
  factory ToastDetail.transfer({required MoneyVM money, required String from, required String to}) = _TransferDetail;
}

class ToastAction {
  const ToastAction({required this.label, required this.onPressed});
  final String label;                              // «واگرد» (QX-15)؛ از کاتالوگ (CM-10)
  final VoidCallback onPressed;                    // فوراً و فقط یک‌بار (MR-05، UN-01)
}

class ToastVM {
  const ToastVM({required this.message, this.detail, this.action, this.kind = ToastKind.standard})
      : assert(kind == ToastKind.standard || (detail == null && action == null), 'TO-02');
  final String message;                            // سطر اول
  final ToastDetail? detail;                       // سطر دوم
  final ToastAction? action;                       // وجودش مدت ماندن را عوض می‌کند (TO-05)
  final ToastKind kind;
}

abstract interface class ToastHandle {
  void dismiss();                                  // خروج MO-10 (TO-05)
  Future<ToastCloseReason> get closed;             // وقتی کامل می‌شود که Toast واقعاً از درخت رفته است
}

abstract interface class ToastController {         // یکی برای کل برنامه؛ UI فقط از راه ToastHost
  ToastHandle show(ToastVM vm);                    // هم‌گام در همان فریم؛ Toast قبلی را جایگزین می‌کند (TO-06)
}

class ToastHost extends StatelessWidget {          // یک‌بار در ریشه‌ی برنامه؛ بالای همه‌ی لایه‌ها، مودال‌ها هم (TO-07)
  const ToastHost({super.key, required this.child});
  final Widget child;
}
```

جدول ۷-۱۳-الف: هندسه و نقش‌ها (واحد px؛ همه توکن‌اند).

| جزء | مقدار |
| --- | --- |
| قاب | `inverse-surface`، بدون مرز، `elev-1`، `radius-lg` (CM-12) |
| فاصله‌ی داخلی | افقی `space-4` و عمودی `space-3` |
| عرض | `min(عرض ناحیه − ۲×page-padding، side-panel-width)`، یعنی ۳۲۸ در ۳۶۰ و ۴۲۰ در Medium و بالاتر |
| سطر اول | `body` (۲۸)، `inverse-text`؛ هر چند خط که لازم باشد می‌شکند (CM-07) |
| سطر دوم | `body-sm` (۲۴)، `inverse-text`؛ یک خط و بدون فاصله از سطر اول؛ مبلغ بریده نمی‌شود و اگر جا نشد طبق CA-02 رفتار می‌کند، و نام‌ها با «…» کوتاه می‌شوند |
| آیکون خطا | فقط در `kind: error`؛ `icon-md` (۲۰)، `inverse-text`، در start و هم‌تراز اولین خط؛ فاصله تا متن `space-2` |
| اقدام | در end؛ فاصله از ستون متن `space-3`؛ برچسب `label` (۲۲)؛ ارتفاع md (BU-10)؛ از نظر عمودی وسط Toast؛ لبه‌ی end دکمه `space-2` از لبه‌ی Toast فاصله دارد (فاصله‌ی داخلی خود دکمه `space-4` است)؛ ناحیه‌ی لمس دست‌کم ۴۴×۴۴ |
| جداکننده‌ی سطر دوم | « · » میان مبلغ و برچسب؛ در انتقال آیکون جهت‌دار `icon-sm` (۱۶) با `inverse-text` و `space-1` در دو طرفش که در RTL آینه می‌شود (۲-۷) |

جدول ۷-۱۳-ب: ارتفاع Toast (px؛ سطرها تک‌خطی؛ فرمول: ۲ × `space-3` + بلندتر از (متن، اقدام)؛ سطر اول ۲۸×s، سطر دوم ۲۴×s و اقدام max(۴۴، ۲۲×s + ۱۶)؛ هر خط اضافه‌ی سطر اول ۲۸×s به ارتفاع متن اضافه می‌کند).

| ترکیب | s = ۱٫۰ | s = ۱٫۵ | s = ۲٫۰ |
| --- | --- | --- | --- |
| یک سطر | ۵۲ | ۶۶ | ۸۰ |
| یک سطر و «واگرد» | ۶۸ | ۷۳ | ۸۴ |
| دو سطر | ۷۶ | ۱۰۲ | ۱۲۸ |
| دو سطر و «واگرد» | ۷۶ | ۱۰۲ | ۱۲۸ |

جدول ۷-۱۳-پ: جای‌گیری (لبه‌ی پایین Toast؛ در Compact و Medium نسبت به لبه‌ی بالای نوار پایین).

| کلاس پنجره | لبه‌ی پایین | تراز افقی |
| --- | --- | --- |
| Compact و Medium | ۸۸ بالاتر وقتی دکمه‌ی fab دیده می‌شود (۸۸ = fab + دو `space-4`؛ QA-03) و `space-4` بالاتر وقتی دیده نمی‌شود (QA-02)؛ مرجع بالای نوار پایین است و در صفحه‌ی جزئیات یا فرم، که نوار پایین ندارند، لبه‌ی پایین پنجره | وسط پنجره |
| Expanded و Large | `space-6` بالاتر از لبه‌ی پایین پنجره (fab ندارد؛ QA-04) | وسط ناحیه‌ی محتوا، بدون سایدبار |

با صفحه‌کلید باز، لبه‌ی پایین Toast هرگز پایین‌تر از «بالای صفحه‌کلید + `space-4`» نمی‌رود (`viewInsets.bottom` در آن هست). با صفحه‌کلید بسته و وقتی مرجع لبه‌ی پایین پنجره است (Expanded و Large، یا صفحه‌ای که نوار پایین ندارد)، `viewPadding.bottom` به فاصله افزوده می‌شود؛ نوار پایین آن را خودش دارد (BN-03)، پس وقتی مرجع بالای نوار پایین است چیزی اضافه نمی‌شود.

جدول ۷-۱۳-ت: خط‌زمان یک Toast (t0 لحظه‌ی show است؛ مدت‌ها توکن‌اند).

| لحظه | رویداد |
| --- | --- |
| t0 | ورود شروع می‌شود (MO-10، `base`)؛ شمارش مدت شروع می‌شود؛ liveRegion اعلام می‌کند؛ Toast قبلی، اگر هست، از Semantics بیرون می‌رود و خروجش شروع می‌شود |
| t0 + ۲۰۰ | خروج Toast قبلی تمام و از درخت حذف می‌شود |
| t0 + ۲۴۰ | ورود تمام می‌شود |
| t0 + ۴۰۰۰ بدون اقدام، یا t0 + ۶۰۰۰ با اقدام | خروج شروع می‌شود (MO-10، `exit`) و اقدام غیرفعال می‌شود |
| خروج + ۲۰۰ | Toast از درخت حذف می‌شود و `closed` با `timeout` کامل می‌شود |

جدول ۷-۱۳-ث: متن‌های خود Toast (TOX). متن‌های دیگر همان‌جا که تعریف شده‌اند می‌مانند: QX-13 تا QX-15، QX-17، DM-03 و DM-04. کاتالوگ بخش ۹ این دو ردیف را با همین شناسه در خود دارد.

| شناسه | جا | متن |
| --- | --- | --- |
| TOX-01 | اقدام Semantics برای بستن Toast | «بستن» |
| TOX-02 | خواندن سطر دوم انتقال | «{مبلغ}، از {مبدأ} به {مقصد}» |

- **TO-01 (نقش و دامنه):** Toast فقط برای نتیجه‌ی اقدام همین لحظه‌ی کاربر است: ثبت موفق (QX-13، QX-14)، نتیجه‌ی واگرد (QX-15، QX-17) و روشن یا خاموش‌شدن ماژول (DM-03، DM-04). چیزی فقط در Toast وجود ندارد، چون Toast ناپدید می‌شود: هر اطلاعاتی که کاربر ممکن است بعداً لازم داشته باشد جای دیگری هم هست (مثلاً حذف رکورد از صفحه‌ی جزئیاتش؛ UN-01). Toast برای شکست بارگذاری (ST-03)، شکست ذخیره‌ی فرم (FD-05، IDP-04) و رویداد پس‌زمینه مثل همگام‌سازی (MT-09، ۷-۱۴) به کار نمی‌رود. Toast فوکوس نمی‌گیرد، چیزی را مسدود نمی‌کند و تصمیمی از کاربر نمی‌خواهد.
- **TO-02 (قاب و محتوا):** قاب طبق جدول الف و CM-12 است. متن دو سطر دارد: سطر اول نتیجه (`message`، الزامی) و سطر دوم جزئیات (`detail`، اختیاری). سطر دوم فقط سه شکل دارد: مبلغ و برچسب با « · » و انتقال (مبلغ، حساب مبدأ، آیکون جهت‌دار، حساب مقصد) که QX-14 تعریف کرده است، و متن ساده که یا عنوان کار است (QX-14) یا جمله‌ی دوم Toast غیرفعال‌سازی ماژول، «داده‌های شما نگه داشته شد.» (DM-03؛ فراخواننده جمله‌ی اول را `message` و جمله‌ی دوم را `detail` می‌دهد). مبلغ با CurrencyAmount از MoneyVM ساخته می‌شود، نه با الحاق رشته (MN-03، CA-01)، و بریده نمی‌شود؛ اگر در یک خط جا نشد طبق CA-02 رفتار می‌کند (واحد به خط دوم می‌رود) و ارتفاع Toast از جدول ب بیشتر می‌شود، چون آن جدول حالت تک‌خطی است. نام دسته، حساب و عنوان کار با «…» کوتاه می‌شوند و متن کامل در Semantics می‌ماند. `kind: error` فقط یک سطر دارد (assert) و آیکون خطا در start می‌گیرد. Toast نقطه‌ی پایانی اضافه یا حذف نمی‌کند و متن را همان‌طور که کاتالوگ داده نشان می‌دهد.
- **TO-03 (رنگ روی inverse-surface):** روی `inverse-surface` فقط جفت `inverse-text` راستی‌آزمایی‌شده است (CM-09؛ ۱۷٫۰۶ در تم روشن و ۱۵٫۹۳ در تاریک). رنگ‌های معنایی و تأکید روی آن بررسی نشده‌اند و ناموفق‌اند (`danger` فقط ۲٫۷۶ و ۲٫۳۵) و `focus-ring` در تم تاریک فقط ۲٫۱۶ می‌دهد؛ پس Toast سبز یا قرمز نمی‌شود، وضعیت خطا با آیکون و متن می‌آید (CM-11، TK-04) و حلقه‌ی فوکوس دکمه‌ی Toast ۲px با `inverse-text` است. CurrencyAmount عدد را با `text-primary` و واحد را با `text-secondary` می‌کشد (CA-03، CA-04) و این دو روی `inverse-surface` جفت مجاز نیستند؛ AmountTone هم حالت وارونه ندارد. برای همین یک ویجت رنگ تازه در همین بخش تعریف می‌شود: `InverseScope`، هم‌خانواده‌ی AccentScope در TK-03 (تعریف تازه‌ی همین بخش). InverseScope فقط `text-primary` و `text-secondary` را در زیردرخت خود به `inverse-text` نگاشت می‌کند و هیچ رنگ دیگری را عوض نمی‌کند؛ `context.colors` در آن زیردرخت همین نگاشت را برمی‌گرداند (اگر Flutter تأیید شود: ThemeExtension بازنویسی‌شده؛ TK-03). Toast تمام محتوایش را داخل آن می‌سازد، پس CurrencyAmount با `tone: neutral` و بدون پارامتر تازه روی Toast درست دیده می‌شود. `tone` مثبت یا بحرانی داخل Toast assert می‌شود. InverseScope فقط برای Toast است؛ Tooltip فقط یک متن ساده با `inverse-text` است و به آن نیازی ندارد، و منو سطح `surface-raised` دارد (CM-12، جدول ۲-۴).
- **TO-04 (اقدام):** Toast حداکثر یک اقدام دارد و آن در end می‌آید («واگرد»؛ QX-15، DM-03). برچسب از کاتالوگ است و حداکثر سه کلمه (BU-03). اقدام یک دکمه‌ی متنی بی‌قاب است با نقش `label`، رنگ `inverse-text`، `radius-md` و ارتفاع md (BU-10) و حالت‌هایش این‌هاست: hover (فقط ماوس) لایه‌ی `inverse-text` با شفافیت ۰٫۰۸ (MO-01)، pressed همان لایه با شفافیت ۰٫۱۲، focus حلقه‌ی ۲px با فاصله‌ی ۲px از لبه و رنگ `inverse-text` (جدول ۲-۶، TO-03)، و disabled فقط در خروج و بی‌تغییر در ظاهر؛ loading و error برای این دکمه «ندارد» (CM-03). ضربه، Enter یا Space اقدام را فوراً و فقط یک‌بار صدا می‌زند (MR-05)؛ همان لحظه دکمه غیرفعال می‌شود و Toast با MO-10 می‌رود. نتیجه‌ی عملیات را فراخواننده با Toast تازه اعلام می‌کند (UN-01).
- **TO-05 (مدت و بستن):** شمارش مدت از لحظه‌ی show (t0، فریم آغاز ورود) است، نه از پایان ورود: بدون اقدام `toast-visible` (۴۰۰۰ms) و با اقدام `toast-undo-visible` (۶۰۰۰ms)، و در پایان آن خروج شروع می‌شود (TQ-06). Toast خطا مثل بدون اقدام است. از لحظه‌ی شروع خروج اقدام دیگر کار نمی‌کند، چه با ضربه چه با صفحه‌کلید (UN-01). با hover ماوس روی Toast یا فوکوس صفحه‌کلید روی دکمه‌اش شمارش می‌ایستد و با رفتن آن‌ها با زمان باقی‌مانده ادامه می‌یابد؛ هیچ شمارش معکوس دیداری نیست (MT-10). ضربه روی بدنه، Escape وقتی فوکوس روی دکمه‌ی Toast است، `dismiss()` و اقدام Semantics «بستن» (TOX-01) همه همان خروج MO-10 را اجرا می‌کنند (MR-05). بدنه‌ی Toast فوکوس نمی‌گیرد و hover و pressed ندارد: ضربه روی آن فقط میان‌بر بستن است (مثل DY-04) و راه صفحه‌کلید و صفحه‌خوان اقدام جداست. اپ در پس‌زمینه شمارش را نمی‌ایستاند؛ اگر هنگام بازگشت مدت گذشته باشد Toast بدون انیمیشن حذف شده است.
- **TO-06 (یکی در هر لحظه):** در هر لحظه یک Toast فعال است (SV-03). `show` تازه، Toast قبلی را بی‌درنگ از درخت Semantics بیرون می‌برد، اقدامش را غیرفعال می‌کند و خروج MO-10 را برایش آغاز می‌کند؛ Toast تازه هم‌زمان و در همان جا وارد می‌شود. قبلی فقط تا پایان خروجش (`exit`، ۲۰۰ms) دیده می‌شود و این تنها هم‌پوشانی مجاز است. صف وجود ندارد: Toast جایگزین‌شده هرگز دوباره نشان داده نمی‌شود و `closed` آن با `replaced` کامل می‌شود. Toast با ناوبری میان صفحه‌ها بسته نمی‌شود، چون ToastHost در ریشه‌ی برنامه است.
- **TO-07 (جای‌گیری و لایه):** `ToastHost` یک‌بار و بالای Navigator در ریشه‌ی برنامه ساخته می‌شود و Toast را طبق جدول‌های الف و پ می‌گذارد. Toast روی همه‌ی لایه‌هاست، از جمله مودال‌ها و scrim‌شان، چون SV-01 در t0 هم‌زمان پنجره را می‌بندد و Toast را وارد می‌کند. Toast جزو «پس‌زمینه»ی مودال نیست (OV-01)، از درخت Semantics بیرون نمی‌رود و فوکوس نمی‌گیرد؛ دکمه‌اش با Tab فقط وقتی فوکوس می‌گیرد که مودالی باز نباشد (OV-04 ب) و مودالی که باز می‌ماند Toast اقدام‌دار نمی‌سازد. Toast در ترتیب فوکوس بعد از همه‌ی عناصر صفحه و نوار پایین می‌آید. اگر در زمان نمایش چیدمان عوض شود (چرخش، تغییر کلاس پنجره، آمدن یا رفتن fab یا صفحه‌کلید)، Toast بدون انیمیشن و بدون ریست شمارش در جای تازه می‌نشیند (CM-08).
- **TO-08 (حرکت):** Toast فقط یک ردیف حرکت دارد، MO-10 (CM-08): ورود با جابه‌جایی ۱۶px به‌سوی بالا (MT-05) و شفافیت ۰ به ۱ در `base` (۲۴۰ms) با `decelerate`؛ خروج فقط با شفافیت ۱ به ۰ در `exit` (۲۰۰ms) با `accelerate` و بدون جابه‌جایی. ماندن را `toast-visible` یا `toast-undo-visible` می‌دهد (TO-05). با «کاهش حرکت» ورود هم فقط محو شدن است (ستون «کاهش حرکت» جدول ۴-۳؛ SV-01). Toast جزو سقف MT-08 است: در توالی SV-01 دو انیمیشن در t0 هست (خروج پنجره و ورود Toast) و اگر Toast قبلی هم باشد خروج آن سومی است؛ پس رخدادی که در همان لحظه انیمیشن دیگری هم شروع می‌کند باید با MotionProbe (MX-08) سنجیده شود. بازخورد hover و pressed دکمه فقط رنگ لایه است (MO-01). جابه‌جایی Toast (TO-07)، تغییر متن و شمارش مدت حرکت ندارند.
- **TO-09 (Semantics و فوکوس):** Toast یک گره‌ی Semantics با `liveRegion` از نوع polite (SV-02) و برچسب «{سطر اول}، {سطر دوم}» دارد (AQ-01)؛ سطر دوم انتقال طبق TOX-02 خوانده می‌شود و آیکون جهت‌دار `excludeSemantics` است. `kind: error` به‌جای polite اعلام assertive دارد (مثل خطای ذخیره در QX-16). دکمه‌ی اقدام گره‌ی جدا و فوکوس‌پذیر با برچسب دیداری خودش است (CM-05) و پس از متن Toast خوانده می‌شود؛ گره‌ی متن فوکوس نمی‌گیرد و اقدام Semantics «بستن» (TOX-01) روی آن است. اعلام در لحظه‌ی show (t0) انجام می‌شود، نه در پایان ورود. گره‌ی Toast و دکمه‌اش در لحظه‌ی شروع خروج یا جایگزینی از درخت Semantics بیرون می‌روند (TO-05، TO-06). اگر فوکوس صفحه‌کلید روی دکمه‌ی Toast بود و Toast رفت، فوکوس به عنصری برمی‌گردد که پیش از رسیدن به Toast داشت و اگر آن عنصر دیگر در درخت نیست به ریشه‌ی صفحه. ToastHost هرگز فوکوس را خودکار نمی‌گیرد.
