#### ۷-۱۶-۴ نشان (Badge)

Badge برچسب کوچک و غیرتعاملی است که یک وضعیت کوتاه یا یک شمارنده را کنار عنوان یا مقدار می‌گذارد. تنها شمارنده‌ی برنامه است (VI-07، PD-01). این زیربخش حرکت ندارد (۷-۰) و رنگ تأکید ماژول را نمی‌خواند؛ رنگ‌هایش فقط رنگ‌های وضعیت‌اند (۲-۳).

```dart
// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum BadgeTone { neutral, success, warning, danger, info }

class AppBadge extends StatelessWidget {
  const AppBadge.status({
    super.key,
    required String this.label,                      // رشته‌ی آماده از کاتالوگ یا ViewModel (CM-10)؛ assert دیگر: خالی یا بیش از سه کلمه (BG-02)
    this.tone = BadgeTone.neutral,
    this.icon,                                       // با هر tone غیر neutral الزامی است (BG-02)
    this.semanticLabel,                              // null یعنی همان label
  })  : count = null,
        assert(tone == BadgeTone.neutral || icon != null);
  const AppBadge.count({
    super.key,
    required String this.count,                      // رشته‌ی آماده، مثل «۳» یا «۹۹+»؛ کوتاه‌کردن با فراخواننده است (BG-02)
    required String this.semanticLabel,              // مثل «۳ کار معوق»؛ هرگز عدد تنها (BG-08)
    this.tone = BadgeTone.neutral,
  })  : label = null,
        icon = null;
  final String? label;
  final String? count;
  final BadgeTone tone;
  final IconData? icon;
  final String? semanticLabel;
}
```

جدول ۷-۱۶-۴-الف: tone‌ها (رنگ‌ها فقط توکن‌های ۲-۲ و ۲-۳؛ نام آیکون‌ها قراردادی‌اند و در ADR-UI-005 به مجموعه‌ی آیکون نگاشت می‌شوند).

| tone | پس‌زمینه و مرز | آیکون و رنگش | متن | کاربرد |
| --- | --- | --- | --- | --- |
| `neutral` | شفاف روی سطح والد با مرز ۱px `border-strong` | اختیاری؛ `text-primary` | `text-primary` | برچسب بی‌وضعیت، مثل نوع یا دسته |
| `success` | `success-subtle` بدون مرز | `check` با `success` | `text-primary` | انجام‌شده یا سالم |
| `warning` | `warning-subtle` بدون مرز | `warning` با `warning` | `text-primary` | نیازمند توجه |
| `danger` | `danger-subtle` بدون مرز | `error` با `danger` | `text-primary` | خطا، معوق یا بیش از حد |
| `info` | `info-subtle` بدون مرز | `info` با `info` | `text-primary` | اطلاع بی‌فوریت |

جدول ۷-۱۶-۴-ب: هندسه (px؛ مقیاس متن ۱٫۰ مگر خلافش گفته شود).

| ویژگی | مقدار |
| --- | --- |
| متن | `caption` (۱۲/۲۰) با `text-primary`؛ وزن در همه‌ی tone‌ها یکی |
| فاصله‌ی داخلی | افقی `space-2` و عمودی `space-1` |
| شعاع | `radius-sm` (۶) |
| آیکون | `icon-sm` (۱۶) در start و `space-1` تا متن؛ از خط متن کوتاه‌تر است، پس ارتفاع Badge را عوض نمی‌کند |
| ارتفاع | ارتفاع خط متن + ۲×`space-1`: ۲۸ |
| عرض | status: محتوا + ۲×`space-2`؛ count: همین، با کمینه‌ی عرض برابر ارتفاع |
| شکستن | status تا دو خط (CM-07)؛ count هرگز نمی‌شکند |
| لمس، حالت‌ها و حرکت | ندارد؛ غیرتعاملی است (CM-03، CM-08) |

جدول ۷-۱۶-۴-پ: اندازه در مقیاس‌های متن (px؛ ارتفاع یا عرض×ارتفاع).

| ترکیب | ۱٫۰ | ۱٫۵ | ۲٫۰ |
| --- | --- | --- | --- |
| status یک‌خطی، با آیکون یا بی‌آیکون | ارتفاع ۲۸ | ارتفاع ۳۸ | ارتفاع ۴۸ |
| status دوخطی | ارتفاع ۴۸ | ارتفاع ۶۸ | ارتفاع ۸۸ |
| count تک‌رقمی (مثل «۳») | ۲۸×۲۸ | ۳۸×۳۸ | ۴۸×۴۸ |

- **BG-01 (نقش):** Badge فقط یک وضعیت کوتاه یا یک شمارنده را کنار عنوان یا مقدار می‌گوید و تنها شمارنده‌ی برنامه است (VI-07، PD-01)؛ PulseDot، نقطه‌ی رنگی و Chip جای آن را نمی‌گیرند. غیرتعاملی است: ضربه، hover، فوکوس و Tooltip ندارد. Badge حامل متن است، نه جایگزین آن؛ رنگ هیچ‌گاه تنها نیست (TK-04).
- **BG-02 (انواع و ورودی‌ها):** `AppBadge.status` برچسب متنی کوتاه با آیکون اختیاری است و `AppBadge.count` یک رشته‌ی آماده‌ی عددی. رشته‌ها را فراخواننده می‌دهد و از کاتالوگ یا ViewModel می‌آیند (CM-10)؛ کامپوننت عدد قالب نمی‌دهد و کوتاه نمی‌کند، پس «۹۹+» کار فراخواننده است (CM-01). سازنده‌ها assert دارند (HI-09): tone غیر neutral بدون آیکون؛ label خالی یا بیش از سه کلمه (شمارش SC-02)؛ count خالی یا بیش از چهار نویسه.
- **BG-03 (رنگ):** رنگ‌ها فقط جدول الف است. پس‌زمینه‌ی tone همیشه `{tone}-subtle` است، نه پرکننده‌ی پررنگ و نه رنگ تأکید ماژول؛ Badge را AccentScope رنگ نمی‌کند (TK-07، مثل CT-11). متن همیشه `text-primary` است و `text-secondary` هیچ‌جای Badge نیست، چون Badge ممکن است روی یک سطح \*-subtle بنشیند (TK-05، CM-09). آیکون رنگ همان tone را روی \*-subtle خودش دارد (کمینه‌ی ۴٫۶۲ و ۵٫۰۱ در ۲-۸) و `text-primary` روی هر \*-subtle جفت اعتبارسنجی‌شده است (CM-09). neutral پس‌زمینه ندارد و مرزش ۱px `border-strong` است (TK-11).
- **BG-04 (هندسه):** اندازه‌ها از جدول‌های ب و پ است و همه از توکن‌ها می‌آید (TK-13). ارتفاع حداقل است، نه ثابت (CM-07): خط متن + ۲×`space-1`. count تک‌رقمی مربع‌گوشه‌گرد است (`radius-sm`) و تا وقتی متنش از ارتفاع کوتاه‌تر است عرضش برابر ارتفاع می‌ماند.
- **BG-05 (متن و جهت):** status تا مقیاس ۲٫۰ بریده نمی‌شود: متن به‌جای «…» تا دو خط می‌شکند و Badge بلندتر می‌شود (CM-07). count مثل مبلغ یک‌خط است و نمی‌شکند و بریده نمی‌شود (CA-02). ترتیب درونی منطقی است: آیکون در start و متن پس از آن؛ آیکون‌های معنایی آینه نمی‌شوند (۲-۷).
- **BG-06 (معنای tone):** tone وضعیت را به‌تنهایی نمی‌گوید: label همیشه هست و برای هر tone غیر neutral آیکون هم هست، تا معنا هم با متن و هم با شکل منتقل شود (TK-04، CM-11). اینکه چه چیزی success یا warning یا danger باشد را جدول اطلاعات همان صفحه می‌گوید (HI-01)، مثل positive و critical در SC-03؛ Badge خودش معنا نمی‌سازد.
- **BG-07 (جایگاه):** Badge را والد در محتوای صفحه کنار عنوان یا مقدار می‌گذارد، در یک Row یا Wrap با فاصله‌ی `space-2` و حداکثر دو Badge کنار یک عنوان. موقعیت‌دهی روی گوشه‌ی آیکون یا آواتار (Stack) ممنوع است. هر صفحه‌ای که Badge می‌خواهد آن را در جدول اطلاعات خودش (HI-01) نام می‌برد و بدون آن Badge جایی ندارد. صریحاً ممنوع است در: Chip (CT-01)، نوار پایین (BN-05)، اقدام‌های PageHeader (PH-06)، اسلات‌های ListRow (LC-02: leading و trailing بسته‌اند) و SummaryCard (SC-03: تزئین رنگی ندارد). آزمون ویجت هر یک از این میزبان‌ها نبودن AppBadge در درختش را بررسی می‌کند و چک ماشینی بخش ۱۱ ساخت AppBadge را در فایل‌های آن‌ها رد می‌کند.
- **BG-08 (Semantics):** status یک گره با برچسب `semanticLabel` یا، اگر نیست، `label` دارد؛ آیکون ExcludeSemantics است و نام رنگ یا tone خوانده نمی‌شود. count یک گره با `semanticLabel` دارد («۳ کار معوق») و متن دیداری‌اش ExcludeSemantics می‌شود تا عدد تنها یا دوباره خوانده نشود. Badge `button` نیست و فوکوس نمی‌گیرد؛ اینکه با عنوان کنارش در یک گره ادغام شود را والد تعیین می‌کند (مثل SC-09).
- **BG-09 (حالت و حرکت):** حالت loading، error و disabled ندارد (CM-03) و حرکت هم ندارد (CM-08): تغییر متن، tone یا شمار آنی است. وقتی ناحیه‌ی والد Skeleton یا EmptyState است Badge هم نیست.
- **BG-10 (آزمون):** هر ردیف جدول الف یک آزمون ویجت و هر مورد زیر یک آزمون یا golden دارد؛ آزمون Semantics و ردیف نمونه در Style Guide هم لازم است (CM-13). الف) هندسه با `tester.getSize`: status یک‌خطی در مقیاس ۱٫۰ و ۱٫۵ و ۲٫۰ ارتفاع ۲۸ و ۳۸ و ۴۸؛ دوخطی ۴۸ و ۶۸ و ۸۸؛ count «۳» ۲۸×۲۸ و ۳۸×۳۸ و ۴۸×۴۸؛ عرض status بی‌آیکون = عرض متن + ۱۶ و با آیکون = ۱۶ + ۴ + عرض متن + ۱۶ (با خطای ۰٫۵)؛ count «۹۹+» عریض‌تر از ۲۸ است و نمی‌شکند. ب) رنگ در هر دو تم: پس‌زمینه‌ی هر tone برابر `{tone}-subtle`، مرز فقط در neutral، رنگ آیکون برابر رنگ tone و متن `text-primary`؛ هیچ `text-secondary` در درخت نیست. پ) assert: tone غیر neutral بدون آیکون، label خالی یا چهارکلمه‌ای و count پنج‌نویسه‌ای خطا می‌دهند. ت) Semantics: برچسب status، برچسب count بدون عدد تنها، آیکون و متن count بیرون از درخت، نبودن `button` و فوکوس. ث) جهت: آیکون در RTL سمت راست و در LTR سمت چپ متن است. ج) تضاد: `text-primary` روی چهار \*-subtle، هر رنگ وضعیت روی \*-subtle خودش و `border-strong` روی سه سطح در هر دو تم از آستانه‌های ۲-۸ کمتر نیست (اسکریپت بخش ۱۱). چ) golden: پنج tone در status (neutral با آیکون و بی‌آیکون)، count «۳» و «۹۹+»، و «بدترین حالت» بخش ۱۰ (برچسب دوخطی در مقیاس ۲٫۰)، در چهار ترکیب جهت × تم و مقیاس ۱٫۰ و ۲٫۰.
