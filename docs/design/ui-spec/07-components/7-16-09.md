#### ۷-۱۶-۹ ظرف نمودار (ChartContainer)

پیشوند قاعده‌ها CC است. ChartContainer تنها راه نمایش نمودار در برنامه است و کارت نمودار سطح ۲ را می‌سازد (HI-04): قاب، سرتیتر، خلاصه‌ی متنی، نمودار، راهنما و حالت‌ها. خودِ نمودار را کتابخانه‌ای می‌کشد که ADR-UI-006 انتخاب می‌کند، ولی کتابخانه فقط از راه رابط ChartAdapter به ظرف وصل است تا عوض کردن آن جز آداپتر به هیچ بخشی دست نزند. نمودار بدون خلاصه‌ی متنی و جدول داده‌ها کامل نیست (CH-05).

// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum ChartKind { line, bar, rankedBars }                 // Donut رزرو است و فعلاً ساخته نمی‌شود (CH-04)
enum ChartTimeDirection { followLocale, ltr }            // CH-01؛ موقت تا ADR-UI-006
enum SeriesDash { solid, dashed, dotted }
enum SeriesMark { circle, square, triangle, diamond, cross }

class ChartPointVM {
  const ChartPointVM({required this.label, required this.minor, required this.money});
  final String label;        // برچسب محور افقی؛ از قالب‌بند مرکزی (CH-02)
  final BigInt minor;        // واحد کوچک ارز؛ هندسه از این می‌آید، نه از متن
  final MoneyVM money;       // همان مقدار برای جدول، ردیف rankedBars و برچسب‌ها (CA-01)
}

class ChartSeriesVM {
  const ChartSeriesVM({required this.name, required this.points});
  final String name;
  final List<ChartPointVM> points;
}

class ChartAxisFormat {
  const ChartAxisFormat({required this.compact, required this.exactText});
  final MoneyVM Function(BigInt minor) compact;    // MN-04، CA-06
  final String Function(BigInt minor) exactText;   // متن Tooltip برچسب محور (TP-06)
}

class ChartSeriesStyle {
  const ChartSeriesStyle({required this.color, required this.dash, required this.mark, required this.showMark});
  final Color color;
  final SeriesDash dash;
  final SeriesMark mark;
  final bool showMark;       // فقط وقتی سری‌ها بیش از یکی‌اند (CC-05)
}

class ChartPlotSpec {
  const ChartPlotSpec({
    required this.kind, required this.series, required this.styles,
    required this.lower, required this.upper,
    required this.height, required this.topInset, required this.xBandHeight,
    required this.maxXLabels, required this.plotDirection, required this.progress,
  });
  final ChartKind kind;                  // line یا bar
  final List<ChartSeriesVM> series;
  final List<ChartSeriesStyle> styles;
  final BigInt lower, upper;             // کران‌های محور؛ ChartContainer حساب می‌کند (CC-06)
  final double height, topInset, xBandHeight;
  final int? maxXLabels;                 // ۶ در Compact (CH-02)؛ null یعنی فقط «روی هم نیفتادن»
  final TextDirection plotDirection;     // نقطه‌ی نخست در start این جهت (CC-10)
  final Animation<double> progress;      // MO-16؛ آداپتر با repaint: progress می‌کشد و setState نمی‌زند (PF-01)
}

abstract interface class ChartAdapter {
  Widget buildPlot(ChartPlotSpec spec);  // شبکه، سری‌ها و برچسب‌های افقی؛ هیچ مبلغی نمی‌نویسد
}

class ChartContainer extends StatefulWidget {
  ChartContainer({
    super.key,
    required this.title,                 // حداکثر سه کلمه (HI-04)
    required this.kind,
    required this.series,
    required this.summary,               // خلاصه‌ی متنی فارسی (CH-05)
    required this.axisFormat,
    required this.onOpenDataTable,       // مقصد L3 (HI-05، MR-04)
    this.adapter,                        // برای line و bar الزامی است
    this.timeDirection = ChartTimeDirection.followLocale,
    this.state = CardState.ready,
    this.stateContent,                   // StateVM در ۷-۱۲
  })  : assert(wordCount(title) <= 3, 'HI-04'),
        assert(series.length <= 5, 'CH-03'),
        assert(kind == ChartKind.rankedBars || adapter != null, 'CC-01'),
        assert(state == CardState.ready || stateContent != null, 'CC-02');   // به‌علاوه‌ی assertهای CC-02
  final String title, summary;
  final ChartKind kind;
  final List<ChartSeriesVM> series;
  final ChartAxisFormat axisFormat;
  final VoidCallback onOpenDataTable;
  final ChartAdapter? adapter;
  final ChartTimeDirection timeDirection;
  final CardState state;
  final StateVM? stateContent;
  @override
  State<ChartContainer> createState() => throw UnimplementedError();
}

class ChartDataTable extends StatelessWidget {    // محتوای صفحه‌ی L3 (CC-13)
  const ChartDataTable({super.key, required this.title, required this.series});
  final String title;
  final List<ChartSeriesVM> series;
}

جدول ۷-۱۶-۹-ث: متن‌های ChartContainer (کاتالوگ بخش ۹)

| شناسه | متن | کاربرد |
| --- | --- | --- |
| CCX-01 | جدول داده‌ها | عنوان صفحه‌ی ChartDataTable |
| CCX-02 | نمایش جدول داده‌ها: {عنوان} | برچسب Semantics دکمه‌ی «همه» (CH-05) |

- **CC-01 (نقش و مرز):** ChartContainer تنها راه نمایش نمودار است. `line` و `bar` را کتابخانه‌ی ADR-UI-006 فقط از راه `ChartAdapter` می‌کشد و آداپتر فقط ناحیه‌ی نمودار را می‌سازد (شبکه، سری‌ها، برچسب‌های افقی). قاب، سرتیتر، خلاصه، برچسب‌های محور عمودی، راهنما، حالت‌ها، Semantics و فرمان MO-16 با خود ChartContainer است. `rankedBars` را ChartContainer با ویجت‌های خودش می‌کشد و کتابخانه نمی‌خواهد. import کتابخانه فقط در `chart_adapter_<نام>.dart` مجاز است (چک ماشینی بخش ۱۱). ناحیه‌ی نمودار داخل `RepaintBoundary` است (PF-01). ChartAdapter ساختار تازه است و مثل هر ساختار تازه تأیید Agent 1 می‌خواهد (CM-13).
- **CC-02 (ورودی‌ها و assert):** سازنده این موارد را رد می‌کند: عنوان بیش از ۳ کلمه (HI-04)؛ خلاصه‌ی خالی (CH-05)؛ در `ready` سری‌ی خالی یا بیش از ۵ سری (CH-03)؛ سری‌هایی با تعداد نقطه یا برچسب x نابرابر؛ `line` با کمتر از ۲ نقطه؛ `rankedBars` با بیش از یک سری، بیش از ۵ نقطه (HI-04، CH-04) یا `minor` منفی؛ نقطه‌هایی با `unitText` متفاوت (نمودار چندارزی ممنوع است و صفحه ارز را انتخاب می‌کند)؛ `line` یا `bar` بدون `adapter`؛ و `state` غیر از `ready` بدون `stateContent`. `ChartKind` عمداً Donut ندارد؛ افزودنش تغییر ساختار است.
- **CC-03 (قاب، سرتیتر و اقدام):** قاب و سرتیتر دقیقاً LC-01 هستند. تنها اقدام کارت دکمه‌ی «همه» است (`Button.tertiary`، اندازه‌ی `sm`، آیکون جهت‌دار `icon-sm` در end) و `onOpenDataTable` را صدا می‌زند که ChartDataTable را به‌عنوان L3 باز می‌کند (HI-04، HI-05). فقط در `ready` دیده می‌شود (LC-07) و برچسب Semantics آن CCX-02 است. خود کارت و ناحیه‌ی نمودار ضربه‌پذیر نیستند.
- **CC-04 (اندازه):** اندازه‌ها جدول الف است. ارتفاع ناحیه‌ی line و bar توکن `ring-diameter` را به‌عنوان مقدار ثابت قرض می‌گیرد (توکن تازه ساخته نمی‌شود) و با مقیاس متن بزرگ می‌شود: ۱۸۴ × max(۱، s). بقیه‌ی ارتفاع‌ها از خود متن‌هاست و هیچ‌جا بریده نمی‌شود (CM-07). پهنای ناحیه پهنای کارت منهای دو `space-4` است.
- **CC-05 (سری‌ها):** سبک سری i از جدول ب و فقط از روی ترتیب سری می‌آید؛ صفحه رنگ نمی‌دهد. رنگ هیچ‌جا تنها نیست (CH-03): وقتی سری‌ها بیش از یکی‌اند، هر سری نشانه‌اش را روی نقطه‌های خط یا روی سر میله‌ها دارد (اندازه‌ی `space-2`، هم‌رنگ سری؛ ضربدر با خط ۲px) و در راهنما هم هست؛ سریِ تنها نشانه و راهنما ندارد و عنوان کارت برچسب آن است. در `bar` سری‌ها پهلوی هم و بدون فاصله می‌نشینند و تفاوتشان فقط رنگ و نشانه‌ی سر میله است؛ الگوی خط فقط در `line` معنا دارد (خط‌چین: خط `space-2` و فاصله‌ی `space-1`؛ نقطه‌چین: نقطه‌ی ۲px و فاصله‌ی `space-1`).
- **CC-06 (محورها و شبکه):** محور مقدار در سمت start است (CH-01) با سه برچسب: پایین، وسط، بالا. کران‌ها را ChartContainer با `BigInt` حساب می‌کند، نه آداپتر و نه `double`: اگر همه‌ی مقدارها ≥ ۰ باشد \[۰، نیمه، حد\]؛ اگر همه ≤ ۰ \[−حد، نیمه، ۰\]؛ و اگر هر دو علامت باشد \[−حد، ۰، +حد\]؛ «حد» کوچک‌ترین عدد از شکل {۱، ۲، ۵} × ۱۰ به توان k است که از بزرگ‌ترین |minor| کمتر نباشد. برچسب‌ها `CurrencyAmount.compact` با نقش `caption` و `text-secondary` هستند (MN-04، CA-06) و هر کدام در `AppTooltip` با `trigger: tap` و متن `exactText` می‌نشیند (TP-06)؛ ناحیه‌ی لمس هر برچسب ۴۴ است (CM-04) و به مرکز خط شبکه‌اش بسته می‌شود. پهنای ستون برچسب‌ها یک‌بار با TextPainter و TextScaler جاری سنجیده می‌شود (روش NC-05) و با تغییر مقیاس دوباره؛ اگر از ۴۰٪ پهنای ناحیه بیشتر شود برچسب‌ها دوخطی می‌شوند (CM-07). برچسب‌های افقی از قالب‌بندهای مرکزی می‌آیند (CH-02)، `caption` و `text-secondary` هستند، در Compact حداکثر ۶ تا، هیچ دو برچسبی روی هم نمی‌افتد (آداپتر به‌طور یکنواخت کم می‌کند) و آخرین نقطه همیشه برچسب دارد. شبکه سه خط افقی ۱px با `ring-track` است، نه `border` (DV-04)، و خط صفر وقتی در بازه است `border-strong` ۱px؛ خط عمودی نداریم.
- **CC-07 (رسم line و bar):** `line` پاره‌خط راست بین نقطه‌هاست، با ضخامت ۲px و سر گرد، بدون منحنی‌سازی، بدون پر کردن زیر خط و بدون سایه. `bar` میله‌ها را از خط صفر می‌کشد (مقدار منفی زیر آن)؛ پهنای میله min(`space-6`، سهمش از گروه) است، فاصله‌ی گروه‌ها دست‌کم `space-2` و گوشه‌های لبه‌ی آزاد `radius-sm` (حداکثر نصف پهنا). شیب رنگ، سایه، برچسب مقدار روی نمودار و لمس روی نقطه نداریم؛ مقدار دقیق هر نقطه فقط در جدول داده‌هاست. ضخامت ۲px همان ۲pxِ TK-11 است (فهرست TK-11 خط نمودار را هم دارد).
- **CC-08 (rankedBars):** ردیف‌ها از بزرگ به کوچک (minor) مرتب می‌شوند؛ ChartContainer خودش مرتب می‌کند تا ترتیب به صفحه وابسته نباشد. هر ردیف: بالا نام (`body-sm`، `text-primary`، start، تا دو خط) و مبلغ (`NumericCell` با نقش `body-sm`، end؛ `NumericColumnMetrics` یک‌بار برای همه‌ی ردیف‌ها)، سپس `space-1` و نوار ۸ با `radius-full`: مسیر `ring-track` در تمام پهنا و پرِ رنگ تأکید به نسبت minor ردیف به بزرگ‌ترین minor (ردیف نخست پر است؛ مقدار صفر فقط مسیر دارد). نوار از start به‌سوی end پر می‌شود و با MO-16 از ۰ می‌آید. این همان نمودار توصیه‌شده در CH-04 برای سهم دسته‌هاست.
- **CC-09 (راهنما):** وقتی `line` یا `bar` بیش از یک سری دارد، زیر ناحیه یک راهنما هست: برای هر سری جعبه‌ی `icon-sm` با نشانه‌ی همان سری، `space-1` و نام سری با `caption` و `text-secondary`؛ فاصله‌ی ورودی‌ها `space-3`، خط‌شکن، ردیف‌ها ۲۰ با فاصله‌ی `space-2`، به ترتیب سری‌ها و از start. راهنما ضربه‌پذیر و فوکوس‌پذیر نیست و برای سری تنها و برای rankedBars نیست.
- **CC-10 (جهت):** `followLocale` (پیش‌فرض): قدیمی‌ترین نقطه در start (راست در فارسی) و محور مقدار در start؛ `ltr`: نقطه‌ی نخست چپ و محور مقدار چپ در همه‌ی زبان‌ها. نمودار با محور x عددی خالص باید `ltr` بدهد (CH-01). ChartContainer فقط ناحیه‌ی نمودار و ستون برچسب‌های عمودی را با `Directionality(plotDirection)` می‌پوشاند؛ سرتیتر، خلاصه و راهنما از جهت زبان می‌آیند. rankedBars به `timeDirection` کاری ندارد: نوار از start می‌آید و نام در start و مبلغ در end است. عددها و متن‌های برچسب‌ها با BidiText ایزوله می‌شوند (RT-04). این تصمیم تا آزمایش کاربر فارسی‌زبان موقت است و تغییرش فقط مقدار پیش‌فرض این پارامتر را عوض می‌کند (ADR-UI-006).
- **CC-11 (حالت‌ها):** حالت‌ها جدول پ است. در `loading` عنوان می‌ماند و فقط محتوا `Skeleton.block` می‌شود؛ ارتفاع بلوک چنان است که مجموع کارت با `ready` یک‌خطی و بی‌راهنما برابر باشد (۲۹۲ در line و bar، ۲۴۰ در rankedBars با ۳ ردیف) تا با آمدن داده چیدمان نپرد. `error` و `empty` عنوان را نگه می‌دارند و فقط جای محتوا را عوض می‌کنند (LC-07). داده‌ی تهی در `ready` ممنوع است (CC-02)؛ صفحه باید `empty` بدهد.
- **CC-12 (حرکت؛ MO-16):** ChartContainer یک `AnimationController` دارد که `progress` را از ۰ به ۱ با `enter` (۳۲۰ms) و decelerate می‌برد و فقط به آداپتر یا نوارهای rankedBars می‌دهد؛ `setState` در هر فریم ندارد (PF-01). خط در جهت زمان رسم می‌شود، میله‌ها از خط صفر بالا می‌آیند و نوارهای rankedBars از start پر می‌شوند؛ نشانه‌ها بعد از رسیدن خط یا میله دیده می‌شوند. فقط نخستین نمایش ناحیه حرکت دارد و به‌ازای هر بار ساخته شدن صفحه یک‌بار (MR-01): `loading` ← `ready` اجرا می‌شود، اما بازگشت به تب، تازه‌سازی (`ready` ← `loading` ← `ready`) و جایگزینی داده آنی است و دوباره اجرا نمی‌شود. با کاهش حرکت `progress` از فریم اول ۱ است. بقیه‌ی کارت حرکت ندارد.
- **CC-13 (جدول داده‌ها):** ChartDataTable جدول ت است و همه‌ی نقطه‌ها را با `NumericCell` نشان می‌دهد؛ `NumericColumnMetrics` برای هر سری یک‌بار سنجیده می‌شود (NC-05). ترتیب ردیف‌ها ترتیب نمودار است و در rankedBars همان ترتیب مرتب‌شده. نموداری که این صفحه را نداشته باشد ساخته نمی‌شود (CH-05).
- **CC-14 (Semantics و فوکوس):** ناحیه‌ی نمودار، برچسب‌های محور و راهنما با `ExcludeSemantics` از درخت بیرون‌اند؛ معادل متنی نمودار فقط خلاصه و جدول داده‌هاست. ترتیب خواندن: عنوان (`header`)، خلاصه، دکمه‌ی «همه» با برچسب CCX-02. تنها توقف Tab درون کارت همان دکمه است. Tooltipهای برچسب‌های محور فقط با لمس یا کلیک کار می‌کنند و راه صفحه‌کلید یا صفحه‌خوان به مقدار دقیق جدول داده‌هاست.
