### ۷-۱۱ مونتاژ ثبت سریع (`QuickAdd`)

این بخش اجزای بخش‌های قبل (`Tabs`، `NumberField`، `ChipRow`، `Button`، `BottomSheet` و `Dialog`) را در یک پنجره سوار می‌کند: چیدمان سه ناحیه، بودجه‌ی پیکسلی، ارتفاع پایدار، جای پیام‌ها، حالت‌ها، ترتیب فوکوس و اتصال به دکمه‌ی QuickAdd. رفتار تازه‌ای نمی‌سازد؛ رفتار پنجره همان QE، QT، AM، CP، NT، BT، SD، IDP، UN، DR و TS است و اگر ردیفی از این بخش با یکی از آن‌ها ناسازگار دیده شد، قاعده‌ی رفتاری برنده است و ناسازگاری به Agent 1 گزارش می‌شود. پوسته‌ی پنجره و سه نوع مالی با Agent 3، بدنه‌ی نوع «کار» با Agent 4، دکمه‌ی QuickAdd و اتصال موفقیت (SV-01) با Agent 2 و ورودی هوشمند با Agent 5 است؛ مالک این قرارداد Agent 1 است. همه‌ی اندازه‌ها در Compact با عرض ۳۶۰ و مقیاس متن ۱٫۰ داده شده‌اند، مگر خلافش گفته شود؛ فرمول مقیاس‌های دیگر کنار هر جدول است.

    required this.type, required this.enabledTypes, required this.phase,
    required this.amountText, required this.noteText, required this.noteOpen,
    required this.taskTitle, required this.currency, required this.date,
    required this.clientRequestId,
    this.categoryId, this.accountId, this.toAccountId, this.dueDate,
    this.notice, this.failure,
  });
  final QuickAddType type;                 // QT-01
  final List<QuickAddType> enabledTypes;   // table order; 'task' only with the tasks module on (DM-01)
  final QuickAddPhase phase;
  final String amountText;                 // canonical ASCII (FD-09); '' when empty
  final String noteText;                   // raw; trimmed only when saved (NT-01)
  final bool noteOpen;
  final String taskTitle;                  // raw; trimmed only when saved (TS-01)
  final CurrencyCode currency;             // currency of the chosen account (SD-06)
  final LocalDate date;                    // fixed when the window opens (SD-06)
  final String clientRequestId;            // IDP-01
  final CategoryId? categoryId;            // expense and income
  final AccountId? accountId;              // expense, income, and the source of transfer
  final AccountId? toAccountId;            // transfer
  final LocalDate? dueDate;                // task
  final QuickAddNotice? notice;
  final QuickAddFailure? failure;          // non-null only with notice == saveFailed (IDP-04)
  bool get isDirty;                        // QD-10 (DR-01)
  bool get canSubmit;                      // AM-04, SD-05, TS-01; false unless phase == editing
}

abstract interface class QuickAddController {
  QuickAddState get state;
  Future<void> selectType(QuickAddType t); // QD-07: the last call wins
  void setAmount(String canonical);
  void openNote();
  void setNote(String text);
  void setTaskTitle(String text);
  Future<void> pickChip(QuickAddChipSlot slot); // CP-01; opens the picker of 7-10
  void submit();                           // BT-01; ignored unless canSubmit
  Future<CloseDecision> requestClose(CloseReason reason); // QD-10
}

class QuickAddSavedEvent {                 // everything the Toast and the halo need (SV-01, SV-03)

      this.categoryName, this.fromAccountName, this.toAccountName, this.taskTitle});
  final QuickAddType type;
  final RecordId recordId;                 // for UndoQuickAdd (UN-01)
  final CurrencyAmount? amount;            // null for task; built with the money type, never a string (MN-03)
  final String? categoryName, fromAccountName, toAccountName, taskTitle;
}

enum QuickAddCloseKind { saved, dismissed, openedFullForm }

/// onSaved is called once, synchronously, in the frame where the result arrives (t0 of SV-01),
/// NOT when the exit motion ends. The returned future completes after the window has really closed.
Future<QuickAddCloseKind> showQuickAdd(
  BuildContext context, {
  required DestinationId origin,           // QT-02, SD-01
  required void Function(QuickAddSavedEvent event) onSaved,
});

class QuickAddLauncher extends StatelessWidget { // fab in Compact and Medium (QA-01); sidebar button in Expanded and Large (QA-04)
  const QuickAddLauncher({required this.origin, required this.style});
  final DestinationId origin;
  final QuickAddLauncherStyle style;       // fab | sidebarButton | railIcon
  // It publishes its bounds to the SV-01 sequencer; when it is not in the tree the halo is not played.
}

- **QD-01 (ریشه و رنگ تأکید):** ریشه‌ی پنجره، بلافاصله زیر ظرف BottomSheet یا Dialog (۷-۱۰)، یک `AccentScope` است که accent را صریحاً روی `primary` می‌گذارد؛ پنجره هرگز accent صفحه‌ی بازکننده را به ارث نمی‌برد (OV-09). بنابراین نشانگر Tabs (CT-11)، دکمه‌ی اصلی (BT-01، BU-01) و هر مصرف‌کننده‌ی دیگر `context.accent` در هدر، Z2 و Z3 همیشه `primary` است، حتی وقتی پنجره از صفحه‌ای با رنگ تأکید ماژولی دیگر باز شده باشد. لایه‌های دوم (انتخاب‌گر چیپ و دیالوگ بستن؛ QD-12) از داخل پنجره باز می‌شوند و همین `primary` را می‌گیرند. دکمه‌ی QuickAdd بیرون هر AccentScope است و همیشه `primary` می‌ماند (QA-01).
- **QD-02 (سه ناحیه):** پنجره سه ناحیه‌ی عمودی دارد و عناصر، ترتیب و ارتفاع هر ناحیه از جدول ۷-۱۱-الف می‌آید. Z1 (ثابت، بالا): دستگیره (فقط برگه)، هدر و Tabs نوع. Z2 (اسکرول‌شونده، میانی): فیلد اصلی، چیپ‌ها، یادداشت، «جزئیات بیشتر» و پیام ناحیه‌ی میانی (QD-05). Z3 (ثابت، پایین): پیام ناحیه‌ی پایین و دکمه‌ی اصلی. فقط Z2 اسکرول عمودی دارد؛ Z1 و Z3 هرگز اسکرول نمی‌شوند و هیچ بخشی از آن‌ها زیر صفحه‌کلید یا بیرون ظرف نمی‌ماند (KB-01). paddingهای بالا (۴) و پایین (۸) جزو محتوای اسکرول‌شونده‌ی Z2 هستند. Z2 در لبه‌ها کشش و فنر ندارد (MT-03). هر سه ناحیه پس‌زمینه‌ی ظرف (`surface-raised`؛ CM-12) را دارند و سایه‌ی جدا ندارند؛ وقتی محتوای Z2 زیر یکی از لبه‌هایش رفته باشد، همان لبه یک خط ۱px با توکن `border` نشان می‌دهد. این خط روی لبه‌ی Z2 نقاشی می‌شود، در ارتفاع‌ها حساب نمی‌شود و حرکت ندارد.
- **QD-03 (ظرف به تفکیک کلاس پنجره):** ظرف و عرض‌ها فقط طبق جدول ۷-۱۱-ت هستند و عرض محتوا همیشه عرض ظرف منهای دو padding افقی `space-4` است. حداکثر ارتفاع ظرف (Hmax) در QD-04 تعریف شده و از ۹۰٪ ارتفاع صفحه بیشتر نمی‌شود (QT-04). اگر کلاس پنجره حین باز بودن عوض شود (چرخش، تغییر اندازه، تاشدن)، ظرف بی‌حرکت از BottomSheet به Dialog یا برعکس عوض می‌شود؛ QuickAddState، `clientRequestId`، عنصر فوکوس‌دار و مکان‌نما حفظ می‌شوند. لایه‌ی انتخاب‌گر چیپ، اگر باز باشد، بدون انتخاب بسته می‌شود و فوکوس به چیپ بازکننده برمی‌گردد؛ ConfirmDialog بسته نمی‌شود و فقط دوباره چیده می‌شود (OV-01).

- **QD-04 (ارتفاع پایدار):** ارتفاع ظرف H یک عدد پایدار است، نه تابع محتوای نوع جاری: `H = min(Hmax, Z1 + Z3 + C)` که در آن `Hmax = min(⌊0.9 × ارتفاع صفحه⌋, ارتفاع صفحه − viewInsets.bottom)` (۷-۱۰) و C بزرگ‌ترین ارتفاع محتوای Z2 میان نوع‌های فعال است، با یادداشت بسته و بدون هیچ پیام. اجزا و فرمول‌هایشان در جدول ۷-۱۱-ث است. در هر پنج ستون جدول ۷-۱۱-ب محتوای transfer از سه نوع دیگر بلندتر است و transfer همیشه فعال است؛ پس C همیشه برابر محتوای transfer است و H به روشن‌بودن ماژول tasks بستگی ندارد. H فقط با این ورودی‌ها عوض می‌شود: ارتفاع صفحه، `viewInsets.bottom`، `viewPadding.bottom`، مقیاس متن و کلاس پنجره. با تعویض نوع، باز شدن فیلد یادداشت، ظاهر شدن پیام، فاز saving یا باز شدن لایه‌ی دوم، H تغییر نمی‌کند؛ بنابراین Tabs و دکمه‌ی اصلی هنگام تعویض نوع حتی یک پیکسل جابه‌جا نمی‌شوند و محتوای کوتاه‌تر از بالای Z2 شروع می‌شود و زیرش فضای خالی می‌ماند. نمای Z2 برابر `H − Z1 − Z3 − ارتفاع پیام ناحیه‌ی پایین` است (QD-05) و اسکرول Z2 فقط وقتی هست که محتوای نوع جاری از نمای Z2 بلندتر باشد (ستون‌های جدول ۷-۱۱-ب). باز و بسته شدن صفحه‌کلید Hmax و در نتیجه H را طبق همین فرمول عوض می‌کند؛ این تغییر بومی است و جزو حرکت‌های ثبت‌شده نیست (KB-01، MT-09).

- **QD-05 (جای پیام‌ها و ارتفاع آن):** پنجره چهار پیام دارد و فقط جدول ۷-۱۱-ج جای آن‌ها را می‌گوید. `notice` یک مقدار nullable است؛ پس در هر لحظه حداکثر یک پیام در کل پنجره هست و در نتیجه حداکثر یکی در هر ناحیه. اگر چند شرط هم‌زمان درست باشند، پیام با بالاترین اولویت جدول نشان داده می‌شود و بقیه پس از پاک شدن آن دوباره از شرط‌هایشان محاسبه می‌شوند (تنها هم‌زمانی واقعی: saveFailed با reason برابر accountMissing وقتی حساب فعالی نمانده باشد). saveFailed با نخستین تغییر هر مقدار پنجره یا شروع تلاش بعدی پاک می‌شود (IDP-04)؛ سه پیام دیگر وضعیتی‌اند و با برطرف شدن شرطشان ناپدید می‌شوند. noAccount فقط وقتی دیده می‌شود که هیچ حساب فعالی در برنامه نیست؛ چیپ حساب خالی‌شده با وجود حساب‌های فعال (accountMissing؛ QX-22) هیچ خط راهنمایی ندارد. noTransferTarget فقط در transfer دیده می‌شود، وقتی چیپ مبدأ پر و چیپ مقصد به‌دلیل نبودن حساب هم‌ارز خالی است (SD-03). ارتفاع بلوک پیام ثابت نیست و از شکستن واقعی متن در عرض محتوا می‌آید (در پیام خطا منهای آیکون و `space-2`): `خط‌ها × ارتفاع خط × s + 2 × space-1`، با ارتفاع خط ۲۴ برای خطا (body-sm) و ۲۰ برای راهنما (caption). در s = ۱٫۰ یک‌خطی: خطا ۳۲ و راهنما ۲۸؛ دوخطی: ۵۶ و ۴۸ (قالب FieldMessage در ۷-۳؛ FD-05، FD-06). هیچ متنی بریده نمی‌شود (CM-07) و بلوک بیرون از ۴px بالا و پایین خودش فاصله‌ی اضافه نمی‌گیرد. پیام هرگز H را عوض نمی‌کند: پیام Z3 از نمای Z2 کم می‌کند (QD-04) و پیام Z2 به محتوای Z2 اضافه می‌شود و Z2 بی‌انیمیشن به کم‌ترین اندازه‌ی لازم اسکرول می‌شود تا پیام دیده شود (QD-08). پیام خطا همیشه آیکون و متن دارد، نه فقط رنگ (CM-11)، تکان یا لرزش ندارد (MT-10) و با Toast جایگزین نمی‌شود.

- **QD-06 (فازها):** پنجره فقط سه فاز دارد و فقط این گذارها مجازند: editing ← saving (ثبت پذیرفته شد؛ IDP-02)، saving ← editing (QuickAddFailed یا گذشتن save-timeout؛ IDP-04) و saving ← closing (نتیجه‌ی موفق در t0؛ SV-01). الف) editing: همه‌ی کنترل‌ها طبق جدول حالت‌های همان کامپوننت کار می‌کنند. ب) saving: از همان فریمی که ثبت پذیرفته می‌شود، دکمه‌ی اصلی غیرفعال است و برچسبش «در حال ذخیره…» (QX-11) با اسپینر MO-13 پس از skeleton-delay است؛ فیلدها و چیپ‌ها فقط‌خواندنی‌اند (ظاهرشان عوض نمی‌شود)؛ Tabs و دکمه‌های «ورودی هوشمند» و «بستن» غیرفعال‌اند؛ `selectType`، `setAmount`، `openNote`، `setNote`، `setTaskTitle`، `pickChip` و `submit` اثری ندارند؛ هر پنج راه بستن نادیده گرفته می‌شود (QD-10)؛ Z2 همچنان اسکرول می‌شود. پ) closing: از t0 تا پایان حرکت خروج، پنجره ورودی نمی‌پذیرد و مقدارها، چیپ‌ها و برچسب دکمه‌ی اصلی عوض نمی‌شوند؛ هیچ پیام یا خطایی ظاهر نمی‌شود و فوکوس پس از بسته شدن طبق SV-02 برمی‌گردد. ت) در بستن بدون ذخیره (dismissed و openedFullForm) phase عوض نمی‌شود و ظرف از شروع حرکت خروج ورودی را رد می‌کند (OV-06).
- **QD-07 (تعویض نوع):** `selectType(t)` فقط وقتی اثر دارد که phase برابر editing باشد، t در `enabledTypes` باشد و با نوع جاری فرق کند؛ در غیر این‌ها بی‌صدا تمام می‌شود. تعویض ناهم‌زمان است، چون پیش‌فرض‌های نوع تازه از GetQuickAddDefaults می‌آیند (SD-01، QT-03). هر فراخوانی یک شماره‌ی ترتیب می‌گیرد و فقط نتیجه‌ی آخرین فراخوانی اعمال می‌شود (آخرین فراخوانی برنده است): نتیجه‌ی فراخوانی قدیمی‌تر که دیرتر برسد دور ریخته می‌شود و Future آن بدون اثر کامل می‌شود. نوع و پیش‌فرض‌های نوع تازه (دسته، حساب‌ها، تاریخ، سررسید) با هم در یک فریم اعمال می‌شوند؛ هیچ فریمی نوع تازه را با چیپ‌های نوع قبلی نشان نمی‌دهد و تا اعمال نتیجه canSubmit برابر false است (QD-10). مبلغ، یادداشت (و باز بودن فیلدش) و عنوان کار نگه داشته می‌شوند و بقیه از پیش‌فرض نوع تازه پر می‌شوند (QT-03، TQ-17)؛ پس از پر شدن، SD-07 برای مبلغ و ارز اجرا می‌شود. نشانگر Tabs با MO-03 می‌لغزد و محتوای Z2 بدون حرکت و در همان فریم عوض می‌شود؛ H تغییر نمی‌کند (QD-04) و Z2 به آفست صفر برمی‌گردد. پس از تعویض با لمس یا ماوس، فوکوس به فیلد اصلی نوع تازه می‌رود (مبلغ، و در task عنوان) تا صفحه‌کلید باز بماند و ارتفاع پایدار بماند؛ با صفحه‌کلید یا صفحه‌خوان فوکوس روی Tabs می‌ماند. با tasks خاموش، «کار» در هیچ جای پنجره نیست (DM-01).
- **QD-08 (اسکرول Z2 و صفحه‌کلید):** صفحه‌کلید عددی در سه نوع مالی و متنی در task با فوکوس خودکار باز می‌شود (AM-01، TS-01)، لبه‌ی پایین پنجره روی لبه‌ی بالای آن می‌نشیند و Z1 و Z3 همیشه دیده می‌مانند (QD-02، QD-04). در نمای مرجع A (۳۶۰×۶۴۰، صفحه‌کلید ۲۶۰px) فهرست KB-01 بدون اسکرول دیده می‌شود: هدر، Tabs، فیلد مبلغ با میانبرها، ردیف ۱ چیپ‌ها و دکمه‌ی اصلی. ردیف ۱ چیپ‌ها در s = ۱٫۰ و ۱٫۵ کامل در نمای Z2 جا می‌گیرد (۱۶۴ از ۱۹۶ و از ۱۹۱) و در s = ۲٫۰ جا نمی‌گیرد و با اسکرول در دسترس است (۱۸۲ از ۱۵۴؛ TQ-11 پ). Z2 اسکرول را طبق ردیف آخر جدول ۷-۱۱-ب دارد یا ندارد؛ وقتی محتوا در نما جا می‌شود (مثلاً task در A با ۶px جا) نه اسکرولی هست و نه اثر لبه‌ای. هر عنصر Z2 با اسکرول قابل رسیدن است و عنصر آخر با padding پایین کامل دیده می‌شود. جابه‌جایی خودکار Z2 همیشه بی‌انیمیشن و به کم‌ترین اندازه‌ی لازم است و فقط در این چهار رخداد اجرا می‌شود: الف) فوکوس گرفتن هر عنصر Z2 (از جمله فیلد یادداشت پس از باز شدن) تا کاملاً دیده شود؛ ب) ظاهر شدن پیام Z2؛ پ) ظاهر شدن پیام Z3 وقتی عنصر فوکوس‌دار Z2 از نما بیرون می‌افتد؛ ت) تغییر Hmax با باز یا بسته شدن صفحه‌کلید. تعویض نوع آفست را صفر می‌کند (QD-07) و باز شدن لایه‌ی دوم یا دیالوگ بستن آن را تغییر نمی‌دهد. وقتی صفحه‌کلید بسته می‌شود Hmax بزرگ‌تر می‌شود و ظرف تا H رشد می‌کند (حرکت بومی؛ MT-09).

* **QD-09 (ترتیب فوکوس):** ترتیب فوکوس و ترتیب خواندن Semantics یکی است و AQ-02 مرجع آن است. توقف‌ها به ترتیب: ۱) «ورودی هوشمند» (فقط با assistant روشن و نوع غیر task)؛ ۲) «بستن»؛ ۳) Tabs نوع (یک توقف؛ کلیدهای ← و → میان بخش‌ها، CT-08)؛ ۴) فیلد مبلغ (در task عنوان)؛ ۵) «هزار» و «میلیون» (فقط سه نوع مالی، به ترتیب QX-05)؛ ۶) چیپ‌ها: ردیف ۱ از start به end و در transfer سپس چیپ تاریخ در ردیف ۲، و آیکون جهت میان دو چیپ حساب فوکوس نمی‌گیرد؛ ۷) «افزودن یادداشت» یا فیلد یادداشتِ باز (نه در task)؛ ۸) «جزئیات بیشتر»؛ ۹) دکمه‌ی اصلی. پیام‌ها فوکوس نمی‌گیرند ولی در ترتیب خواندن جای خود را دارند: accountsEqual بلافاصله پس از چیپ‌های حساب و پیش از چیپ تاریخ، و پیام‌های Z3 بلافاصله پیش از دکمه‌ی اصلی. فوکوس اولیه روی فیلد اصلی است (initialFocus؛ OV-04 الف) و Tab و Shift+Tab فقط در همین توقف‌ها می‌چرخند و از پنجره بیرون نمی‌روند (OV-04 ب). فوکوس در این لحظه‌ها جابه‌جا می‌شود: پس از انتخاب در انتخاب‌گر چیپ و پس از ساخت حساب درون‌خطی روی فیلد اصلی (CP-01، OV-04 پ، TQ-09)؛ پس از «ماندن» در دیالوگ بستن روی همان عنصری که پیش از دیالوگ داشت (TQ-07)؛ پس از تعویض نوع طبق QD-07؛ و پس از بسته شدن پنجره طبق SV-02. پیام تازه، خطای ذخیره و فاز saving فوکوس را جابه‌جا نمی‌کنند.
* **QD-10 (isDirty، canSubmit و بستن):** `isDirty` برابر است با: `amountText` غیرخالی، یا `noteText` پس از فاصله‌زدایی دو سر غیرخالی، یا `taskTitle` پس از فاصله‌زدایی دو سر غیرخالی (تعبیر «غیرخالی» در DR-01 با همان معیار NT-01 و TS-01). سنجش روی همه‌ی مقدارهای نگه‌داری‌شده است، نه فقط نوع فعلی، و نوع، چیپ‌ها، باز بودن فیلد یادداشت و ساخت حساب درون‌خطی در آن نقشی ندارند. `canSubmit` فقط وقتی true است که این‌ها همه برقرار باشد: phase برابر editing باشد و تعویض نوع نیمه‌تمام نباشد (QD-07)؛ در expense و income مبلغ غیرخالی و بزرگ‌تر از صفر و چیپ حساب پر باشد (AM-04، SD-05) و چیپ دسته می‌تواند «بدون دسته» باشد (QX-06)؛ در transfer مبلغ معتبر، هر دو چیپ حساب پر، دو حساب یکسان نباشند و ارز دو حساب برابر باشد (AM-04، SD-03، SD-07)؛ در task عنوان پس از فاصله‌زدایی غیرخالی باشد (TS-01). هیچ‌یک از این شرط‌ها پیام خطا نمی‌سازد، به‌جز accountsEqual (QD-05). `submit()` وقتی canSubmit برابر false است بی‌صدا تمام می‌شود؛ ضربه روی دکمه و Enter در فیلد اصلی هر دو از همین‌جا می‌گذرند (BT-01) و ثبت را فقط یک بار می‌پذیرند (IDP-02). `requestClose(reason)` با پنج دلیل OV-02 (ضربه روی پس‌زمینه، کشیدن، Escape، بازگشت سیستم‌عامل و دکمه‌ی بستن) به یکی از دو مقدار `CloseDecision` می‌رسد: `stay` یا `close`. در saving و closing برای هر پنج دلیل `stay` است، بی‌دیالوگ؛ اگر isDirty برابر false باشد `close` است، بی‌دیالوگ؛ وگرنه دیالوگ QX-19 (NV-04، DR-01) نشان داده می‌شود و «ماندن» به `stay` و «دور انداختن» به `close` بدون ذخیره می‌انجامد. «جزئیات بیشتر» از این مسیر نمی‌گذرد: بدون دیالوگ می‌بندد و همه‌ی مقدارها را به فرم کامل می‌سپارد (QT-04).
* **QD-11 (اتصال به دکمه‌ی QuickAdd):** پنجره فقط با `showQuickAdd` باز می‌شود و `QuickAddLauncher` تنها بازکننده‌ی آن در رابط است (میان‌بر صفحه‌کلید در ADR-UI-008 ثبت می‌شود؛ QA-05). سه سبک `fab` (Compact و Medium؛ QA-01)، `sidebarButton` (Expanded و Large؛ QA-04) و `railIcon` (در Rail، فقط آیکون و با Tooltip «ثبت سریع»؛ BU-08) فقط ظاهر را عوض می‌کنند و هر سه یک برچسب Semantics «ثبت سریع» (QX-01) و یک رفتار دارند: ضربه، Enter یا Space، `showQuickAdd(origin:)` را با مقصد سطح‌بالایی که دکمه روی آن است صدا می‌زند (QT-02، SD-01). launcher روی مقصدهایی که QA-02 کنار گذاشته ساخته نمی‌شود. در هر لحظه فقط یک پنجره‌ی ثبت سریع هست و تا Future فراخوانی قبلی کامل نشده فراخوانی تازه نادیده گرفته می‌شود. launcher مستطیل خود را (در مختصات پنجره) پس از هر چیدمان به ترتیب‌دهنده‌ی SV-01 می‌دهد؛ اگر در درخت نباشد یا دیده نشود هاله پخش نمی‌شود و خطایی نیست. در طول باز بودن پنجره launcher پشت scrim است و از درخت فوکوس و Semantics بیرون می‌ماند (OV-01). `onSaved` یک بار و همگام در فریم t0 صدا زده می‌شود (نه در پایان حرکت خروج) و فقط `QuickAddSavedEvent` را می‌دهد؛ Toast (SV-03) و به‌روزرسانی صفحه‌ی پشت (فقط آنچه دیده می‌شود) از همین رویداد ساخته می‌شوند. Future برگشتی پس از بسته شدن واقعی با `saved`، `dismissed` یا `openedFullForm` کامل می‌شود و فوکوس طبق SV-02 به launcher برمی‌گردد، یا اگر در صفحه نیست به عنصر پیشین.
* **QD-12 (لایه‌های روی پنجره):** روی پنجره حداکثر یک لایه‌ی دیگر باز می‌شود: انتخاب‌گر چیپ (CP-01) یا دیالوگ بستن (DR-01)؛ ساخت حساب درون‌خطی (SD-05) داخل انتخاب‌گر است و لایه‌ی سوم نمی‌سازد (OV-01). انتخاب‌گر در Compact و Medium BottomSheet و در Expanded و Large Popover است (CP-01) و دیالوگ بستن ConfirmDialog است. `pickChip(slot)` فقط در editing انتخاب‌گر را باز می‌کند و Future آن با بسته شدن انتخاب‌گر (با انتخاب یا بی‌انتخاب) کامل می‌شود؛ تا آن زمان چیپ دیگری ضربه نمی‌گیرد، چون پنجره پشت لایه ورودی نمی‌گیرد (OV-01). انتخاب مقدار را همان لحظه در QuickAddState می‌نشاند (برای حساب با SD-07)، فوکوس را به فیلد اصلی می‌برد و مقدار تایپ‌شده را پاک نمی‌کند (CP-01)؛ بسته شدن بی‌انتخاب فوکوس را به چیپ بازکننده برمی‌گرداند (OV-04 پ). Escape و بازگشت سیستم‌عامل فقط لایه‌ی بالا را می‌بندند، نه پنجره‌ی ثبت سریع را. لایه‌ها accent `primary` می‌گیرند (QD-01)، مقیاس متن، جهت و تم پنجره را می‌گیرند و بودجه‌ی ارتفاع پنجره را تغییر نمی‌دهند (QD-04).

- **QD-13 (Semantics):** برچسب‌ها همان AQ-01 هستند و این قاعده فقط ساختار و وضعیت‌ها را اضافه می‌کند. ظرف یک گره‌ی مسیر دارد (scopesRoute و namesRoute) با نام «ثبت سریع» (QX-01) و دستگیره excludeSemantics است (OV-05).
