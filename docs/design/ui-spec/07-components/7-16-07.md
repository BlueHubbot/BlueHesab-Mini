#### ۷-۱۶-۷ ابزارهای عددی و جهت (BidiText، NumericCell، PercentageChange)

سه ابزار کوچک اما حساس‌اند: BidiText تنها راه ساخت جزیره‌ی جهتی است (RT-04)، NumericCell تنها جای استثنای جهت فیزیکی است (RT-05، CA-07) و PercentageChange تنها راه نمایش تغییر درصدی است (MN-05، VI-20). هیچ‌کدام عدد یا متن نمی‌سازند؛ فقط متن آماده‌ی formatter مرکزی (بخش ۳) را رسم می‌کنند.

```dart
// نمونه؛ نام‌ها و مقدارها قرارداد است (CM-02).
enum BidiMode { auto, ltr }              // auto: FSI؛ ltr: LRI (شناسه، ایمیل، URL، کد، عدد)

class BidiText extends StatelessWidget {
  const BidiText(this.text, {super.key, this.mode = BidiMode.auto});
  final String text;
  final BidiMode mode;
  // تنها helper رشته‌ای جزیره (RT-04)؛ رفتار دقیق در NC-02.
  static String isolate(String text, {BidiMode mode = BidiMode.auto}) => throw UnimplementedError();
}

class NumericColumnMetrics {
  const NumericColumnMetrics({required this.numberWidth, required this.unitWidth});
  final double numberWidth;              // پهن‌ترین numberText ستون، با علامت، در TextScaler جاری
  final double unitWidth;                // پهن‌ترین unitText ستون (caption)
  static NumericColumnMetrics measure(BuildContext context, List<MoneyVM> values, {required TextStyle role}) =>
      throw UnimplementedError();          // TextPainter؛ NC-05
}

class NumericCell extends StatelessWidget {
  const NumericCell({super.key, required this.money, required this.role, required this.metrics});
  final MoneyVM money;                   // همان MoneyVM مبلغ (CA-01)
  final TextStyle role;                  // مثل CurrencyAmount: context.text.<token> (TY-02)
  final NumericColumnMetrics metrics;
}

enum ChangeDirection { up, down, none }

class PercentVM {
  final String text;                     // formatter مرکزی: علامت (U+200E سپس + یا −)، ارقام، «٪» (MN-05)
  final String spokenText;               // «۱۲٫۵ درصد افزایش»؛ برای Semantics
  final ChangeDirection direction;       // فقط پیکان و علامت؛ خوب یا بد بودن با tone است
  final AmountTone tone;                 // همان AmountTone مبلغ (VI-20)
  final String? statusText;              // الزامی وقتی tone == critical
}

class PercentageChange extends StatelessWidget {
  const PercentageChange({super.key, required this.change, required this.role});
  final PercentVM change;
  final TextStyle role;
}
```

جدول ۷-۱۶-۷-الف: ساختار و اندازه‌ها.

| جزء | ساختار | اندازه و تراز |
| --- | --- | --- |
| جزیره‌ی `auto` | FSI (U+2068)، متن، PDI (U+2069) | جهت از نخستین نویسه‌ی قوی |
| جزیره‌ی `ltr` | LRI (U+2066)، متن، PDI (U+2069) | همیشه LTR؛ در پاراگراف RTL در start (راست) می‌نشیند |
| NumericCell | جعبه‌ی عدد، `space-1`، جعبه‌ی واحد | عرض = `numberWidth` + ۴ + `unitWidth`؛ ارتفاع = خط نقش؛ عدد در جعبه‌اش به راست فیزیکی چسبیده است |
| PercentageChange | پیکان `icon-sm`، `space-1`، جزیره‌ی عدد و، برای `critical`، `space-2` و statusText | ارتفاع = خط نقش؛ پیکان ۱۶×۱۶ و وسط‌چین عمودی |

جدول ۷-۱۶-۷-ب: مقدارهایی که جزیره می‌شوند.

| مقدار | mode | منبع |
| --- | --- | --- |
| نام حساب، دسته یا عنوانی که درون جمله‌ی بزرگ‌تر می‌نشیند (مثل TOX-02) | `auto` | RT-04 |
| ایمیل، URL، کد، شناسه و شماره حساب | `ltr` | RT-04، FD-08 |
| عدد مبلغ، درصد و هر عدد قالب‌بندی‌شده | `ltr` | VI-19 |
| مقدار تنهای یک Text (عنوان ردیف، نام صفحه) | جزیره نمی‌خواهد؛ خودش پاراگراف است | RT-04 |

جدول ۷-۱۶-۷-پ: حالت‌ها و حرکت (CM-03).

| حالت | مقدار |
| --- | --- |
| hover، pressed، focus، disabled | ندارد؛ هیچ‌کدام کنترل نیستند و فوکوس نمی‌گیرند |
| loading و error | ندارد؛ بارگذاری و خطای جدول را Skeleton، ErrorState و EmptyState می‌گویند (۷-۱۲) |
| حرکت | ندارد؛ شمارش MO-14 و هر انیمیشن دیگری در این سه ابزار نیست (۷-۰) |

- **NC-01 (نقش و مرز):** BidiText، NumericCell و PercentageChange فقط متن آماده‌ی formatter مرکزی را رسم می‌کنند و نه محاسبه می‌کنند و نه قالب می‌دهند (CM-01). عدد خام (`double` یا `int`) نمی‌پذیرند (MN-01)؛ NumericCell فقط `MoneyVM` و PercentageChange فقط `PercentVM` می‌گیرد.
- **NC-02 (BidiText.isolate):** `isolate` رشته را با FSI (`auto`) یا LRI (`ltr`) آغاز و با PDI تمام می‌کند. متن خالی خالی می‌ماند؛ متنی که از قبل جزیره‌ی کامل است دوباره پیچیده نمی‌شود؛ و کنترل‌های جداساز U+2066 تا U+2069 که در خود متن باشند حذف می‌شوند، چون PDI سرگردان جزیره را زودتر می‌بندد و بقیه‌ی متن را از جزیره بیرون می‌اندازد. U+202A تا U+202E و LRM و RLM درون متن دست نمی‌خورند، چون PDI پایانی اثرشان را در همان جزیره می‌بندد. جدول ب می‌گوید کدام مقدار با کدام mode جزیره می‌شود. جز `BidiText.isolate` و formatter مرکزی (که علامت را با U+200E می‌نویسد، NM-02) هیچ کدی FSI، LRI، PDI، LRM یا RLM نمی‌نویسد.
- **NC-03 (ویجت BidiText):** `BidiText(text, mode)` یک `Text` با همان جزیره و `TextAlign.start` است؛ نقش و رنگ را والد می‌دهد و متن بریده نمی‌شود (CM-07). مقدار `ltr` در رابط RTL در start یعنی لبه‌ی راست می‌نشیند و نویسه‌هایش از چپ به راست می‌روند (FD-08). برچسب Semantics آن بدون نشانه‌های جهت است؛ رشته‌ی Semantics دستی هم هیچ‌وقت جزیره نمی‌شود.
- **NC-04 (NumericCell: ساختار):** NumericCell همان CurrencyAmount است و هیچ قاعده‌ی دیگری از آن عوض نمی‌شود (CA-07): ساختار «جزیره‌ی عدد، `space-1`، واحد» می‌ماند، ولی جعبه‌ی عدد عرض ثابت `numberWidth` دارد و عدد در آن به راست فیزیکی چسبیده است و جعبه‌ی واحد عرض ثابت `unitWidth` دارد. ترتیب جعبه‌ها منطقی است (عدد در start، واحد پس از آن)، پس واحد در RTL سمت چپ عدد و در LTR سمت راست آن است (RT-07). نتیجه این است که رقم یکان همه‌ی ردیف‌های ستون، در هر دو جهت، روی یک خط عمودی است. علامت منفی بخشی از `numberText` و سمت چپ اولین رقم است (VI-19) و چون عدد به راست چسبیده، علامت به چپ بیرون می‌زند و رقم‌ها جابه‌جا نمی‌شوند. تنها جایی از برنامه که `TextAlign.right` یا `Alignment.centerRight` می‌نویسد فایل `numeric_cell.dart` است و در فهرست استثنای چک ماشینی RT-05 ثبت می‌شود.
- **NC-05 (NumericColumnMetrics):** عرض‌ها اندازه‌گیری می‌شوند، نه حدس: `measure` با `TextPainter`، همان نقش (ارقام هم‌عرض، NM-04) و `TextScaler` جاری همه‌ی مقدارهای ستون را می‌سنجد؛ `numberWidth` پهن‌ترین `numberText` با علامت و `unitWidth` پهن‌ترین `unitText` با نقش caption است. جدول یک‌بار برای کل ستون می‌سنجد و همان metrics را به همه‌ی سلول‌ها می‌دهد؛ هیچ سلولی خودش نمی‌سنجد. نتیجه تا تغییر داده، مقیاس متن، جهت، `digitMode` یا نقش نگه‌داشته می‌شود و با تغییر هر کدام در همان فریم دوباره سنجیده می‌شود. اگر ستون در عرض موجود جا نشد، پله‌های CA-02 (واحد به خط دوم، سپس نقش یک پله کوچک‌تر) برای کل ستون با هم اجرا و metrics دوباره سنجیده می‌شود، نه برای هر سلول جدا، تا ستون یکدست بماند.
- **NC-06 (NumericCell: Semantics و حالت‌ها):** یک گره با برچسب `spokenText` (CA-05) و جزء‌های دیگر excludeSemantics. حالت و حرکت ندارد (جدول پ). NumericCell فقط در سلول جدول می‌آید، نه در ردیف فهرست و نه در کارت (CA-07).
- **NC-07 (PercentageChange: ورودی و assert):** فقط از `PercentVM` ساخته می‌شود. `text` قالب MN-05 را دارد: «٪»، حداکثر یک رقم اعشار با حذف صفر انتهایی و علامت (U+200E سپس + یا U+2212) برای `up` و `down`. سازنده assert می‌کند: `none` فقط با `tone: neutral` و متن بی‌علامت؛ `up` فقط با متن دارای «+»؛ `down` فقط با متن دارای «−»؛ و `critical` فقط با `statusText`. علامت «+» برای موجودی ممنوع است و فقط برای تغییرهاست (MN-05).
- **NC-08 (PercentageChange: ساختار و رنگ):** ساختار طبق جدول الف است. پیکان عمودی `icon-sm` برای `up` رو به بالا و برای `down` رو به پایین است، آینه نمی‌شود (RT-03) و برای `none` نیست. رنگ پیکان و متن یکی است: `neutral` با `text-primary`، `positive` با `success` و `critical` با `danger` (VI-20، CM-09). جهت و رنگ مستقل‌اند: کاهش هزینه می‌تواند `down` با `positive` باشد و دامنه آن را تعیین می‌کند. رنگ هرگز تنها نیست: پیکان و علامت همیشه هست و با `critical` statusText هم کنار عدد می‌آید (TK-04، CM-11). نقش را والد می‌دهد (CA-03). عدد شکسته یا بریده نمی‌شود و اگر statusText جا نشد به خط بعد، هم‌تراز start، می‌رود (CM-07).
- **NC-09 (PercentageChange: Semantics و جا):** یک گره با برچسب `spokenText` و، اگر `statusText` هست، «{spokenText}، {statusText}»؛ پیکان و علامت excludeSemantics. فعلاً تنها جایش ستون «تغییر» جدول است؛ در SummaryCard نیست (comparisonText با کلمه است، SC-06)، در ListRow.trailing نیست (RowTrailing فقط پول و متن دارد، ۷-۶) و روی Chip و Badge نیست. جای تازه در این فهرست ثبت و تأیید Agent 1 می‌خواهد (CM-13).
- **NC-10 (ممنوع‌ها):** ساخت دستی جزیره (FSI، LRI، PDI) یا LRM و RLM بیرون از BidiText و formatter؛ `Directionality(textDirection: ltr)` دستی دور یک مقدار؛ تراز فیزیکی راست یا چپ بیرون از `numeric_cell.dart`؛ سنجش عرض داخل خود سلول؛ عرض ثابت حدسی (مثل ۸۰)؛ NumericCell در ردیف فهرست؛ شمارش انیمیشنی (MO-14) در سلول جدول؛ رنگ سبز یا قرمز بدون پیکان و علامت؛ و علامت «+» برای موجودی.
- **NC-11 (آزمون):** هر ردیف جدول‌های الف تا پ یک آزمون ویجت و هر مورد زیر یک آزمون یا golden دارد (CM-13). الف) BidiText: `isolate('abc')` برابر FSI، `abc`، PDI و با `ltr` برابر LRI، `abc`، PDI است؛ متن خالی خالی می‌ماند؛ دوبار صدا زدن نتیجه‌ی یک‌بار را می‌دهد؛ PDI سرگردان داخل متن حذف می‌شود؛ در Toast با قالب TOX-02 و نام حسابی که U+202E دارد ترتیب دیداری بقیه‌ی جمله عوض نمی‌شود؛ ایمیل در پاراگراف RTL از لبه‌ی راست و از چپ به راست رسم می‌شود. ب) هندسه با `tester.getRect` برای ستونی با «۱٬۲۵۰»، «−۹۸٬۷۶۵٬۴۳۲» و «۰» به تومان: لبه‌ی راست جعبه‌ی عدد در هر سه سلول یکی است (اختلاف صفر)، رقم یکان هر سه روی یک x است، علامت منفی سمت چپ اولین رقم است، واحد در RTL سمت چپ عدد و در LTR سمت راست آن است، و مبلغ ۱۵ رقمی در مقیاس ۲٫۰ بریده یا همپوشان نیست. پ) metrics با مقیاس ۱٫۰ و ۲٫۰ مقدار متفاوت می‌دهد؛ با تغییر مقیاس در همان فریم دوباره سنجیده می‌شود و بدون تغییر داده دوباره نمی‌سنجد (شمارنده‌ی TextPainter در آزمون). ت) PercentageChange: برای `up` پیکان بالا، برای `down` پیکان پایین و برای `none` بدون پیکان؛ رنگ هر `tone` دقیقاً توکن خودش است؛ assert ناسازگاری جهت و علامت و `critical` بدون statusText می‌شکند؛ Semantics «۱۲٫۵ درصد افزایش» و برای critical با statusText؛ در مقیاس ۲٫۰ بدون بریدگی و با statusText در خط بعد. ث) چک ماشینی بخش ۱۱ هر FSI، LRI، PDI، LRM و RLM خام و هر `TextAlign.right`، `TextAlign.left`، `Alignment.centerRight` و `Alignment.centerLeft` را بیرون از فایل‌های مجاز (BidiText، formatter مرکزی، `numeric_cell.dart`) رد می‌کند. ج) golden: روشن و تاریک × RTL و LTR × مقیاس ۱٫۰ و ۲٫۰ برای ستون سه‌مبلغی بالا، داده‌ی «بدترین حالت» بخش ۱۰ (۱۵ رقمی) و سه PercentageChange (`up` با `positive`، `down` با `neutral`، `critical` با statusText)، به‌علاوه‌ی ردیف نمونه در Style Guide.
