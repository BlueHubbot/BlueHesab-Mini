## ۱. هویت بصری «آبی‌حساب»

هویت بصری BlueHesab Mini روی سه عنصر ساخته می‌شود: نقطه‌ی زنده (`PulseDot`)، حلقه‌ی روز (`DayRing`) و ریتم عددی؛ هر سه فقط با توکن‌های بخش ۲ و حرکت‌های بخش ۴ ساخته می‌شوند و هیچ رنگ، اندازه یا زمان ثابتی در کد ویجت‌ها مجاز نیست.

**وضعیت:** پیشنهاد (Proposed). پس از تأیید مالک محصول، معمار (Agent 1) آن را با شناسه‌ی `ADR-UI-001` در مخزن ثبت می‌کند و تا آن زمان هیچ ایجنتی کد این بخش را ادغام نمی‌کند. اگر با «قانون اساسی UI/UX» تعارض پیدا شد، همان قانون اساسی برنده است، مگر ADR تأییدشده خلاف آن بگوید.

### ۱-۱ پنج قانون هویت

| شناسه | قانون | راه بررسی |
| --- | --- | --- |
| VI-01 | عدد قهرمان صفحه است: اندازه‌ی عدد حداقل ۱٫۶ برابر اندازه‌ی برچسبش و وزن آن حداقل برابر وزن برچسب است. | تست ویجت `SummaryCard` + golden |
| VI-02 | هر ماژول دقیقاً یک رنگ تأکید دارد (بخش ۲-۳)؛ رنگ تأکید دوم در همان بخش ممنوع است. | چک ماشینی بخش ۱۱ + بازبینی |
| VI-03 | حرکت فقط برای رساندن معناست: تغییر عدد، ورود جزئیات، موفقیت واقعی. هر انیمیشن باید در فهرست بخش ۴-۳ ثبت شده باشد. | چک ماشینی مدت‌ها |
| VI-04 | سکوت بصری: بین دو گروه محتوا حداقل `space-6` (۲۴px) و در هر کارت حداکثر یک عدد قهرمان. | golden |
| VI-05 | هر خروجی تولیدشده با هوش مصنوعی با نشان «پیشنهاد» و دکمه‌ی تأیید صریح نشان داده می‌شود (بخش ۸). | تست ویجت |

### ۱-۲ نقطه‌ی زنده (`PulseDot`)

نقطه‌ی زنده امضای بصری برنامه است: یک دایره‌ی کوچک به رنگ تأکید جاری که فقط در سه جای مشخص دیده می‌شود.

| ویژگی | مقدار |
| --- | --- |
| هسته (`core`) | دایره‌ی توپر؛ اندازه‌ها: `dot-sm` = ۶px، `dot-md` = ۸px، `dot-lg` = ۱۲px |
| هاله (`halo`) | دایره‌ی هم‌مرکز با قطر ۲ برابر هسته و همان رنگ؛ شفافیت پایه ۰ و فقط در حالت‌های `thinking` و `success` دیده می‌شود |
| رنگ | توکن `accent` جاری (پیش‌فرض `primary`)؛ در حالت خطا `danger` همراه با آیکون |
| جایگاه‌های مجاز (فقط همین سه) | ۱) `BrandMark` در سایدبار و صفحه‌ی آغاز ۲) هاله‌ی موفقیت روی `QuickAdd` ۳) سرصفحه‌ی `AssistantPage` و `AIActionCard` برای نمایش وضعیت مدل |

| حالت | شکل | حرکت | کاربرد |
| --- | --- | --- | --- |
| `idle` | هسته‌ی ثابت | ندارد | پیش‌فرض |
| `thinking` | هسته + هاله | «تنفس»: مقیاس هسته ۰٫۹↔۱٫۰ و شفافیت ۰٫۵۵↔۱٫۰ در یک چرخه‌ی ۱۶۰۰ms با منحنی `standard`؛ تا پایان کار تکرار می‌شود | دستیار در حال پردازش، OCR یا تبدیل گفتار |
| `success` | هسته + هاله | یک‌بار: هاله از مقیاس ۱ به ۱٫۸ و شفافیت ۰٫۴ به ۰ در ۳۲۰ms با منحنی `decelerate`؛ سپس بازگشت به `idle` | فقط پس از ذخیره‌ی واقعی تراکنش |
| `error` | هسته‌ی `danger` + آیکون هشدار کنارش | ندارد | خطای دستیار |

وضعیت مدل هوش مصنوعی (قرارداد بخش ۹ سند UI) با شکل و برچسب متنی نشان داده می‌شود، نه با رنگ تنها:

| وضعیت مدل | شکل نقطه | برچسب فارسی | آیکون کنار نقطه |
| --- | --- | --- | --- |
| محلی | هسته‌ی توپر | «محلی» | ندارد |
| ابری | هسته‌ی توپر + هاله‌ی ثابت (بدون انیمیشن) | «ابری» | ابر |
| آفلاین | حلقه‌ی توخالی با خط ۱٫۵px | «آفلاین» | ندارد |
| غیرفعال | هسته با شفافیت ۰٫۴ | «غیرفعال» | خط مورب |

- **VI-06:** در هر صفحه حداکثر یک `PulseDot` در حالت `thinking` فعال است.
- **VI-07:** `PulseDot` هرگز نماد فهرست، نشان خوانده‌نشده یا تزئین نیست؛ برای شمارنده از `Badge` استفاده می‌شود.
- **VI-08:** انیمیشن `success` فقط پس از بازگشت موفق use-case (ذخیره‌ی ماندگار) شروع می‌شود؛ هنگام ارسال، دکمه فقط در حالت loading است.
- **VI-09:** با «کاهش حرکت» روشن، `thinking` به هسته‌ی ثابت همراه با متن «در حال پردازش…» و `success` به حالت بدون هاله (فقط Toast) تبدیل می‌شود (بخش ۴-۴).
- **VI-10:** لوگوی نهایی در این سند طراحی نمی‌شود. `BrandMark` موقتاً برابر است با `PulseDot` در اندازه‌ی `dot-lg` به‌علاوه‌ی نام برنامه با فونت برنامه، تا کار جداگانه‌ی طراحی لوگو تأیید شود.

### ۱-۳ حلقه‌ی روز (`DayRing`)

حلقه‌ی روز در صفحه‌ی خانه وضعیت امروز را در یک نگاه نشان می‌دهد. حداکثر سه کمان هم‌مرکز دارد و هر کمان فقط وقتی رسم می‌شود که ماژولش فعال باشد.

| کمان | جایگاه (از بیرون) | رنگ | معنای طول کمان |
| --- | --- | --- | --- |
| بودجه | ۱ | `accent-finance` | بخش باقی‌مانده‌ی بودجه‌ی دوره‌ی جاری (هرچه بلندتر، بهتر) |
| کارها | ۲ | `accent-tasks` | نسبت کارهای انجام‌شده‌ی امروز |
| عادت‌ها | ۳ | `accent-health` | نسبت عادت‌های انجام‌شده‌ی امروز |

| ویژگی هندسه | مقدار ثابت |
| --- | --- |
| قطر بیرونی | ۱۸۴px (موبایل و دسکتاپ یکسان) |
| ضخامت هر کمان | ۱۰px با سر گرد (`StrokeCap.round`) |
| فاصله‌ی بین کمان‌ها | ۴px |
| شعاع مرکز خط کمان‌ها | ۸۷، ۷۳ و ۵۹px (از بیرون به درون) |
| شروع و جهت | ساعت ۱۲ و **ساعت‌گرد** در هر دو جهت LTR و RTL؛ حلقه آینه نمی‌شود |
| رنگ مسیر | توکن `ring-track` |
| کمینه‌ی کمان دیدنی | اگر ۰ < fraction < ۰٫۰۲ آنگاه ۰٫۰۲؛ اگر fraction = ۰ فقط مسیر دیده می‌شود |
| مرکز حلقه | `caption` «امروز» و زیر آن تاریخ کوتاه با `title-sm`؛ عدد مالی در مرکز قرار نمی‌گیرد |

قرارداد داده: UI هیچ محاسبه‌ای نمی‌کند و لایه‌ی use-case مقادیر را آماده می‌دهد.

```dart
enum DayRingKind { budget, tasks, habits }
enum DayRingStatus { normal, attention, over }

class DayRingArcVM {
  final DayRingKind kind;
  final double fraction;   // بین ۰ و ۱؛ توسط use-case محاسبه می‌شود
  final String label;      // «بودجه»
  final String valueText;  // «۶۸٪ باقی‌مانده»؛ قبلاً با formatter مرکزی ساخته شده
  final DayRingStatus status;
}

class DaySummaryVM {
  final List<DayRingArcVM> arcs; // فقط ماژول‌های فعال، به ترتیب budget, tasks, habits
}
```

- **VI-11:** نخستین نمایش: کمان‌ها در ۳۲۰ms رسم می‌شوند و هر کمان ۶۰ms دیرتر از قبلی شروع می‌کند؛ به‌روزرسانی‌های بعدی در ۲۴۰ms انجام می‌شود (بخش ۴-۳).
- **VI-12:** زیر حلقه (اگر عرض کارت دست‌کم ۴۴۰ باشد کنار آن؛ DY-06) همیشه فهرستی متنی هست با یک ردیف برای هر کمان: آیکون ماژول، برچسب و `valueText`. حلقه به‌تنهایی کافی نیست.
- **VI-13:** وضعیت با متن و آیکون منتقل می‌شود: `attention` یعنی آیکون هشدار و عبارت «نزدیک به سقف»؛ `over` یعنی آیکون خطا و عبارت «بیش از بودجه». رنگ کمان تغییر نمی‌کند و هیچ قرمز چشمک‌زنی وجود ندارد.
- **VI-14:** برچسب `Semantics` یک جمله‌ی کامل است: «حلقه‌ی روز: بودجه ۶۸ درصد باقی‌مانده، کارها ۴ از ۶، عادت‌ها ۲ از ۵.»
- **VI-15:** اگر هیچ کمانی وجود نداشته باشد، به‌جای حلقه‌ی خالی `EmptyState` با این متن نمایش داده می‌شود: «برای دیدن وضعیت امروز، یک بودجه یا یک عادت اضافه کنید.»
- **VI-16:** ضربه روی حلقه یا هر ردیف فهرست، صفحه‌ی همان ماژول را باز می‌کند.

### ۱-۴ ریتم عددی

- **VI-17:** هر عدد سه لایه‌ی تایپی دارد: برچسب (`label`، وزن ۵۰۰، `text-secondary`)، عدد (`title` یا `heading` یا `display` بر اساس جایگاه؛ وزن مطابق جدول ۳-۱، `text-primary`) و واحد (`caption`، `text-secondary`). عدد هرگز کم‌رنگ‌تر یا کوچک‌تر از برچسب نیست.
- **VI-18:** ارقام با ویژگی ارقام هم‌عرض (tabular figures) رسم می‌شوند و فاصله‌ی حروف (`letterSpacing`) برای متن فارسی همیشه صفر است (بخش ۳).
- **VI-19:** عدد منفی با علامت `−` (U+2212) در سمت چپِ ارقام نمایش داده می‌شود و قالب‌بندی عدد در یک جزیره‌ی LTR با `LRI/PDI` انجام می‌شود؛ راستی‌آزمایی با golden (بخش ۳-۷).
- **VI-20:** رنگ مبلغ پیش‌فرض خنثی است (`text-primary`). فقط تغییر مثبت `success` می‌گیرد و فقط وضعیت بحرانی `danger`؛ هر دو همیشه با علامت یا متن همراه‌اند.

### ۱-۵ ممنوعیت‌های هویت

- هیچ گرادیان، درخشش (glow) یا محو کردن پس‌زمینه و هیچ سایه‌ای فراتر از سطوح بخش ۲-۴.
- هیچ تصویرسازی شخصیت‌دار؛ تصویر حالت خالی فقط آیکون خطی حداکثر ۶۴px با رنگ `text-secondary` است.
- هیچ صدای رابط، لرزش یا کانفتی.
- هیچ رنگ تأکید جدید و هیچ استفاده‌ی رنگ تأکید برای نشان دادن وضعیت (وضعیت فقط با رنگ‌های معنایی همراه آیکون و متن).
- هیچ Design System جداگانه برای یک ماژول.
