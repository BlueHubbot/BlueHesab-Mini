## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). LP-04 caps loops in view at two. The page-level `MotionBudget` of T-045 already lives at the page root, so a loop `MotionHandle` built under a `MotionBudgetScope` now joins the same budget, counted apart from the MT-08 non-loop count. `repeat()` runs the loop only while fewer than two other loops of the page run; otherwise the loop waits still at its start value, exactly as RM-02 «ایستا» shows it (D0: the spec does not say what a third loop does; still-at-start is the state the spec already defines for a loop that does not run, and nothing is invented). Unlike a non-loop row, a waiting loop still has its real state behind it (LP-02), so when a running loop of the page stops (cut with `interrupt()`, disposed, or made still by reduced motion) the oldest waiting loop starts (D0: first asked, first started). A `MotionLoopGroup` owns one handle, so a whole group of Skeleton plates counts as one loop (LP-04 second sentence). Reduced motion turned off again restarts waiting loops only up to the cap. "In view" is read as "on the same page scope": a page hidden by `TickerMode` (LP-03) has its own scope and its muted loops count only there. A handle outside any scope is not capped.
