## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). RM-01 says a change of the reduced-motion setting applies at once, without a restart. `context.motion` already rebuilds its dependants (T-037), but a `MotionHandle` resolves RM-02 once, when it is created. This slice adds `MotionHandle.updateReduced(bool)`, which the widget calls from `didChangeDependencies`. It re-resolves the phase and sets the controller's duration for the next play. The spec does not say what an animation that is running should do. D0 (conservative, matches MX-08's "end value" sentence): when reduced turns on, a running non-loop jumps to the value it was heading for, and a loop that RM-02 stops («ایستا») goes to its start. When reduced turns off, a running crossfade ends as it started, and a loop asked for with `repeat` starts again. The curve never changes, because RM-02 keeps the phase's curve in every case. `dispose` now disposes the `CurvedAnimation` as well (T-039 review nit).

## Objective
A widget that holds a `MotionHandle` follows a change of RM-01 (setting or system flag) in the same frame, with no restart, and MotionProbe shows the result.
