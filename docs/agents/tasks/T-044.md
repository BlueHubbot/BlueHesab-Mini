## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). LP-04 wants every Skeleton plate of a page to pulse on one controller, not one per plate; LP-03 wants a loop to stop ticking when its widget is not shown. Today a component can only get a loop by building its own `MotionHandle`, so ten plates would mean ten controllers. This slice adds `MotionLoopGroup`, a widget in `app_motion` that owns one `MotionHandle` for the loop phase of one table 4-3 loop row and hands its curved animation to every descendant through `MotionLoopGroup.of(context)`. Its `running` flag is required (LP-02: the caller says whether the real wait is still on); when it turns false the handle is disposed and descendants get a stopped animation at the start value, so the count is 0. The group's ticker comes from `SingleTickerProviderStateMixin`, which follows `TickerMode`: under `TickerMode(enabled: false)` the value stops moving and goes on when it is enabled again (LP-03). The group follows RM-01 at once with `MotionHandle.updateReduced` (RM-02: MO-12 loop «ایستا», the value stays at the start). Mapping the 0…1 value to MO-12's opacity 0.6…1.0 belongs to the Skeleton component, not here. The app-in-background half of LP-03 is the framework's own (no frames are scheduled while the app is not resumed); it is not tested here because the widget-test binding pumps frames regardless.

## Objective
A component can make any number of descendants pulse on one loop controller that respects LP-02, LP-03 and RM-01, with `app_motion` only.
