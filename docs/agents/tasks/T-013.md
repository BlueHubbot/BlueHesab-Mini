## Understanding summary (AG-06) — written by the owner of the task before work starts

## Objective
App-level theme engine: user setting `theme = ivory | plum | clay | glow | auto | custom`; `auto` follows the editable schedule (default 06:00 ivory, 11:00 clay, 17:00 plum, 21:00 glow) and switches only on the next screen change, never inside an open sheet or form; `custom` («تم من») lets the user pick bg, surface, text and accent from the curated palette or a free colour picker, with T-012's `contrast_guard` preventing unreadable combinations (proposes the nearest passing shade). Settings persisted locally; custom themes included in backup/restore. No raw colours in widgets (TK-13); strings via the copy catalog (CM-10).

## Non-goals
New screens beyond Settings › Theme and its editor; sync.

## Allowed paths
`lib/app/**`, `lib/features/settings/**`, `lib/design/theme/**`, `test/**`, `docs/agents/tasks/T-013.md`, `docs/ops/AGENT_LOG.md`, `docs/ops/STATUS.md`

## Acceptance criteria
- [ ] Widget tests: each of the four themes renders; `auto` picks the right theme at the schedule borders (fake clock); switching is deferred while a sheet is open.
- [ ] Custom editor cannot save a combination below 4.5:1 for body text (test with negative control).
- [ ] Custom theme survives backup and restore (test).
- [ ] All CI checks green.
