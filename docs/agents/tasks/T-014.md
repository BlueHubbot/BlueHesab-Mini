## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Builder-Platform (scheduled run), 2026-11-02. A new spike package `spike/T-014-share` (SDK packages only) with a draft field, a paste button and a `ShareInbox` method-channel wrapper; native glue in `native/MainActivity.kt`. CI generates the Android folder with `flutter create` and a checked script adds the glue and one filter, so no generated platform code is committed. CI sends four synthetic shares with `am start` (cold ASCII, running Persian, cold Persian, cold 4 000 characters) and compares length + FNV-1a fingerprint from logcat; an integration test on the emulator covers clipboard on tap. Interpretations (D0): (1) the app logs only length and fingerprint, never text (CAPTURE_PIPELINE §6); (2) explicit component in `am start` plus `query-activities` for implicit resolution, since the chooser needs a real UI; (3) the clipboard test copies from the same app (another-app copy is a real-phone item); (4) the warm-path source is reported, not asserted.

## Objective
Prove on an Android emulator in CI that a Flutter app with no third-party plugin receives `ACTION_SEND` `text/plain` through its own manifest filter and a small `MainActivity` method channel, both on a cold start and while running, with the text arriving exactly (ASCII, Persian with Persian digits and an LTR number, 4 000 characters); that the clipboard is read only when the user taps; and that the APK asks for no permission. Record what the real phone must still show.

## Non-goals
Real phone run (owner, Q-09); SMS parsing, QuickAdd, PasteSmsSheet UI or copy (ADR-UI-010, M2); iOS share extension; desktop; any third-party receiver plugin (would need an audit row); changes to the root app (`lib/**`, `android/**`).

## Acceptance criteria
- [x] The spike package builds a release APK on CI; its Android folder is generated by `flutter create` in CI and only `MainActivity.kt` and one manifest `<intent-filter>` are added by a checked script (no committed generated platform code). Result: release APK 47.6 MB (universal, debug key). Evidence: CI log.
- [x] `cmd package query-activities` for `ACTION_SEND` `text/plain` lists the spike activity (implicit resolution, not only an explicit component). Result: `dev.bluehesab.spike.spike_share/.MainActivity`. Evidence: CI notice.
- [x] Cold start with a share intent: the text reaches Dart exactly (code-unit length and FNV-1a 32 of the UTF-8 bytes equal to the expected values) for ASCII, Persian + Persian digits + LTR number, and 4 000 characters. Result: 3/3 exact (30/`3b97f3c3`, 33/`e6c70ebc`, 4000/`ca532708`). Evidence: logcat markers, CI notice.
- [x] Running app: a second share reaches Dart exactly; whether it arrives through `onNewIntent` (same instance) or a new instance is recorded. Result: exact, through `onNewIntent` (am: delivered to the running top-most instance). Evidence: CI notice.
- [x] Clipboard is read only on tap: an on-device integration test shows the field empty after start with text on the clipboard and filled after tapping the paste button. Result: `00:03 +1: All tests passed!`. Evidence: `flutter test integration_test` output on the emulator.
- [x] The release APK requests no permission in the main manifest, and no SMS permission at all (`aapt2 dump permissions`). Result: only AndroidX's own signature permission `<app id>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (added by the manifest merger, not by the spike). Evidence: CI notice.
- [x] Host tests (channel wrapper with a mocked channel, fingerprint vectors) and `flutter analyze` green; license scan of the spike lockfile passes (SDK packages only). Result: analyze `No issues found!`, `00:00 +8: All tests passed!`, license scan 33 packages 0 failing. Evidence: CI log.
- [x] README lists findings and what the real phone must still show (share from a real SMS app, chooser, Android version on the owner's phone).
