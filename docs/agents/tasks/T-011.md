## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Tester (scheduled run), 2026-10-31. Build a tiny golden harness in a new spike package and prove on CI that the same goldens come out byte for byte on three separate fresh Linux runners, and that a fourth fresh runner compares the first run's goldens with 0 diffs. The subject is one toy card made only of Flutter Material widgets with their defaults (no raw colours or sizes, no tokens needed): text, a determinate progress bar, an indeterminate spinner frozen at time zero (GM-07), a button and the card's own shadow. Each case is rendered 8 times (light/dark × RTL/LTR × scale 1.0/2.0, GMX-01) at Compact 360×640, device pixel ratio 1.0, named by GM-02. Exactness (GM-01, no threshold): a mutation run with a progress value changed by 0.001 must fail the comparison. macOS generates the same set once for information (expected to differ; recorded, not asserted). Interpretations (D0): (1) goldens are made only inside CI and passed between jobs as artifacts; none are committed in the spike (GM-06 applies to real goldens later); (2) text is copy-catalog keys (CM-10), rendered in the Flutter test font, so glyph shaping of Persian text is not covered here (SP-03); (3) artifacts move between jobs with the runner's preinstalled `gh` CLI, as in T-009 (no new action, CB-9).

## Objective
Answer SP-06 with CI evidence: 3 independent Linux runs produce identical golden bytes, a 4th compares with 0 diffs, and a 1-step change is caught (no tolerance). Record what the harness needs (view size, DPR, fixed time, font) for the real golden suite.

## Non-goals
Vazirmatn or any font asset (SP-03, ADR-UI-003), Persian glyph shaping, the real Style Guide or components (T-010, ON_HOLD), committing goldens, `ui_check` golden coverage (GM-08), any `lib/**` change.

## Acceptance criteria
- [ ] Harness: one golden test file renders the toy card in the 8 GMX-01 combinations at 360×640, DPR 1.0, file names per GM-02 (`ToyCard/default__<theme>_<dir>_s<scale>.png`); the spinner is pumped once, never `pumpAndSettle` (GM-07). Evidence: test source, CI log.
- [ ] SP-06: three separate fresh `ubuntu-24.04` runners generate the goldens; their `SHA256SUMS` are identical (0 diffs). Evidence: CI notice from the compare job.
- [ ] SP-06: a fourth fresh runner runs the golden test in compare mode against run 1's files and passes. Evidence: CI log `All tests passed!`.
- [ ] GM-01 exactness: the same compare with `--dart-define=TOY_MUTATE=true` (progress value +0.001) fails with a pixel difference. Evidence: CI log of the expected failure.
- [ ] Information only: a macOS run's hashes are compared with Linux and the result is recorded (equal or not), never asserted. Evidence: CI notice, README.
- [ ] Analyzer clean, license scan of the spike lockfile passes, no new dependency (Flutter SDK only). README with findings. Evidence: CI output, diff.
