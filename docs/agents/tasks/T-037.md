It provides: (1) `AppMotion`, the value object behind `context.motion` with the names of the §4-2 code sample (`micro`, `exit`, `base`, `enter`, `max`, the three curves, `reduced`) plus the remaining §4-2 tokens, all read from `DesignTokens` — no new numbers (AG-05); (2) a catalog of table 4-3: one entry per `MO-xx` with its phases, each phase naming its duration token and curve token exactly as column «مدت و منحنی» does, and the row's reduced behaviour (همان/محو/آنی/ایستا → `same`/`fade`/`instant`/`still`); (3) RM-01: three-way setting and the rule that makes `reduced` true; (4) RM-02: one `resolve` function that turns a row phase into what a widget may do (duration, curve, may it move or scale, does it animate, does it loop). Tests read the spec table and the token JSON so a drift in either fails CI.
Two places where the spec gives a duration but no curve are read through MT-03 (curve by direction), not invented: the RM-02 «محو» crossfade keeps the phase's own curve (enter → `decelerate`, exit → `accelerate`, in-place → `standard`), and the MO-11 highlight fade (duration `enter`) is an in-place change → `standard`. Both are listed in the handoff for Agent 1's review.
