## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Builder-Platform (scheduled run), 2026-11-14. The marker does not need a `lib/` change: a spike entry file `spike/T-031-desktop-start/first_frame_main.dart` imports the root app (`package:bluehesab_mini/main.dart`), calls `runApp(const BlueHesabApp())`, waits for `WidgetsBinding.instance.waitUntilFirstFrameRasterized` and then ends the process with a distinctive exit code (37). The root package is built with `-t` pointing at that file (same build command as `ci.yml` plus `-t`), so the widget tree is exactly the skeleton's. A new workflow `spike-desktop-start.yml` (macOS and Windows jobs, pinned Flutter, no new action or dependency) launches the release executable 5 times with `spike/T-031-desktop-start/tool/start_time.py` (Python standard library only) and records wall-clock time from process spawn to process exit, every value and the median. Negative control: the unchanged root app (no marker) is launched once with a 20 s limit and must still be running, so the measurement cannot pass without the marker. Interpretations (D0): (a) "start time" = spawn → first frame rasterized → process exit; the exit adds a few ms, so the number is an upper bound; (b) launches run right after the build on a CI runner (files in the OS cache, no GPU), so the numbers are indicative, not the reference device, as for Android in T-009; (c) like T-009 and T-021 the folder is not its own Dart package: the entry file is compiled as part of the root package, and the root `analysis_options.yaml` already excludes `spike/**` (layout deviation recorded in the README).
