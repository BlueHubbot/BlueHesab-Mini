## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Builder-UI (scheduled run), 2026-10-30. Build a toy app in a new spike package `spike/T-008-modules/` with the MODULE_CONTRACT layering: `lib/core/` (descriptor interface, Riverpod registry with enabled state, go_router table built from the registry, the four core pages and `ModuleDisabledPage`), `lib/modules/budget/` (one descriptor with its routes and one Home contribution), and `lib/app/module_list.dart` (the one list, MDC-A3). Prove with tests that navigation and Home are built only from enabled modules (MDC-A4, DM-01), that enable/disable takes effect without restart (DM-03, DM-04), that a route of a disabled module renders `ModuleDisabledPage` and an unknown route falls back to Home (DM-05, MDC-T4), that `core/` never imports `modules/` or `app/` (MDC-A2, MDC-T1), and that deleting the budget line from `module_list.dart` still compiles and passes the core tests (MDC-T7, run by CI on a modified copy). Also record what the audit rows ask: the resolved dependency graph of both packages, RTL back navigation and a deep link. Interpretations (D0): (1) titles are copy-catalog keys as plain identifiers, never Persian text (CM-10); (2) RTL is forced with `Directionality` in the app builder; the real locale setup with `flutter_localizations` is not part of this spike; (3) routes follow ND-04 names (`/home`, `/accounting`, `/reports`, `/settings`, `/budget`); (4) the web demo build item of the audit is covered by compiling and running the widget tests in Chrome; a full `flutter build web` needs a `web/` folder and is recorded as not done.
