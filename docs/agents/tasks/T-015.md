## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Builder-UI (scheduled run), 2026-11-02. A spike package `spike/T-015-fonts` (Flutter SDK packages only). A stdlib Python tool fetches one pinned Vazirmatn release archive from the upstream GitHub release at test time into a git-ignored folder, verifies SHA-256 and extracts the TTF files; nothing font-related is committed (ADVISOR_REPLY-001 clarification). A second stdlib tool reads the TTF tables (cmap, fvar, GSUB, hmtx, glyf, hhea, OS/2) and reports coverage, weights, tabular digits, Latin/Persian digit height and file sizes. Flutter tests load the font with `FontLoader` and check, per typography token, that ascent + descent fit the token line height, that Persian digits are equal width, that typing Persian digits into a number field normalises to the exact integer, that an LTR number inside RTL text keeps its order, and that a toy amount card at text scale 1.0/1.3/2.0 has no overflow and no ellipsis; a specimen PNG per OS is uploaded as a CI artifact for a human look. Interpretations (D0): (1) the archive SHA-256 cannot be computed in the agent container (GitHub downloads are blocked there), so the first CI run discovers the latest release, prints its tag and SHA-256, and a separate `pin` job stays red until the values are committed (trust on first use from the official release over HTTPS, recorded); (2) "on all four OSes" for vertical metrics is covered on the three desktop OSes here, mobile is a recorded gap; (3) ink clipping is judged by font metrics against token line height (TY-04: default `TextHeightBehavior`), not by pixel scan.
