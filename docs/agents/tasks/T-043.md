## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). MR-03 and MT-07 say a second row started on an element that is still animating cuts the first and starts from the value the element has now, never from the row's own start. `MotionHandle` (T-039) has no way to say "stop here" or "start from this value". This slice adds two small things to `MotionHandle`: `interrupt()` stops a running controller where it is (no jump to either end, idempotent, loops included), and `from(current, end)` returns the handle's curved animation mapped from a given current value to the row's end value, so the next row continues from the value read just before the cut. The new row keeps its own table 4-3 duration and curve (D0: MR-03 fixes the start value, not the time; every row's time comes from table 4-3). Properties the next row does not animate stay at the value they had (MO-10 exit and MO-09 exit change only opacity, so `dy`/`scale` freeze where enter left them). Under reduced motion the next row follows RM-02 as usual: «محو» continues the opacity from its current value with `exit`; «آنی» shows the end value at once. MotionProbe must read the newest registration on the element, which it already does (newest first).

## Objective
A component can cut a running row and start the next one from the current value with `app_motion` only, and MR-03 is proven by tests.
