## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). Add MC-06 to the `rules` stage over the lexer's `code` view (comments and string bodies blanked, so digits in strings or comments never match). Openers: `EdgeInsets.<name>(` and `EdgeInsetsDirectional.<name>(` (every named constructor: `all`, `symmetric`, `only`, `fromLTRB`, `fromSTEB`, …), `BorderRadius.circular(`, `Radius.circular(`: every argument is checked; `SizedBox(`: only the top-level `width:` and `height:` arguments. In a checked argument, any numeric literal (decimal, double, exponent, hex, digit separators) whose value is not zero is a violation, at any bracket depth inside that argument; `0`, `0.0`, `0x0` pass. One line per violation at the literal's line (VR-01). "Allowed in" is empty, so no file is exempt, the generated token file included (it holds no such call today). D0 (recorded, stricter reading): a literal used inside an expression (`space.s4 * 2`, `f(8)`) is still a raw number in the call; a named constant (`const double gap = 8; SizedBox(width: gap)`) is not seen without static types and stays for the analyzer rows. `SizedBox.square(dimension:)`, `SizedBox.fromSize` and other constructors are not in the row's list and are not checked (narrowest reading, VR-03 forbids widening only by exemption, not by reading).
