Builder-Platform adds `tool/ci/android_device_ready.sh` (restart the adb server, `adb wait-for-device` with a time limit, poll `sys.boot_completed`, print the resolved serial; on failure print `adb devices -l` and the last 200 lines of the emulator log and exit non-zero) and calls it before each attempt of the on-device step in `spike-share.yml`. At most 2 attempts; retry only on the DDS message or "No supported devices found"; any other failure stops at once; a `::warning` names the cause on each retry. Interpretations (D0): (1) the script writes diagnostics to stderr and only the serial to stdout, so the workflow can capture it; (2) the time limit is 180 s for each of the two waits, overridable by `DEVICE_WAIT_SECONDS`; (3) "3 consecutive green runs" means three `workflow_dispatch` runs of `spike-share.yml` on the branch head, all with the `android` job green, counted only after the PR's own run.
