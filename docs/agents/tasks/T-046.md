## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). SC-08 already fixes the arithmetic, so nothing is invented: `motionCountValue(from, to, progress, unit)` returns `from + (delta × k) ~/ 1000` with k = round(progress × 1000) clamped to 0…1000, all in `BigInt` (no `int` product, so 18-digit amounts do not overflow). The intermediate value is then rounded to a multiple of `unit` toward the origin (`unit` is 1 for rial and 10 for toman, MN-02; the caller decides it) and clamped into the closed range between `from` and `to` (MR-02). At k = 1000 the result is exactly `to`, even when `to` is not a multiple of `unit`; at k = 0 it is exactly `from`. `MotionCount` is an `Animation<BigInt>` over a MO-14 `MotionHandle.animation` (already `max` + `decelerate`, and «آنی» under reduced motion, so only the last frame is shown — RM-02); its `target` is `to`, the only value a Semantics label may read (MR-02, MX-05). D0: when `from` is not a multiple of `unit`, rounding toward the origin can fall outside the range; the clamp wins, so that frame shows `from` (MR-02 outranks the rounding detail).
