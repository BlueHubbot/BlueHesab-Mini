## Understanding summary (AG-06) — written by the owner of the task before work starts
Written by Product/Contracts (same run). MT-08 caps a page at three running non-loop animations; loops have their own cap (LP-04) and are not counted here. SV-01 is the one place the spec says what happens to a fourth: it is done at once, and the order of who gets a place is MO-14, MO-15, MO-11, MO-18. This slice adds a page-level budget: `MotionBudgetScope` (a widget the page puts at its root) holds a `MotionBudget`; a non-loop `MotionHandle` built under it joins that budget, and its `forward()` / `reverse()` animate only while fewer than three other members run; otherwise it shows its end value at once, exactly like an RM-02 «آنی» row (D0: SV-01's "the rest are done at once" applied to every page, because MT-08 has no other compliant outcome that keeps every row's table 4-3 time). A handle that does not run (finished, cut by MR-03, «آنی» under reduced motion, disposed) frees its place at once, because the count is read from the controllers when a play starts. `forwardInPriorityOrder` plays a group of handles that start in the same frame in the SV-01 order (rows not in SV-01 after them, in the given order), so the lowest-priority one is the one done at once. A handle outside any scope is not capped (pages opt in by adding the scope; the page shells arrive with Builder-UI).
