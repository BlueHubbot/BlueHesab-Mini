## Understanding summary (AG-06) — written by the owner of the task before work starts
## Objective
In `spike/T-004-jalali/`, define one central calendar port (Gregorian ↔ Jalali conversion, leap year, month length, weekday from Saturday, month addition clamped to the last day), implement it twice — an adapter over `shamsi_date` 1.0.2 and an in-house arithmetic reference (the ADRX-04 fallback) — and prove both against every DT-05 vector, against each other day by day, and against an ICU-generated Nowruz fixture.

## Non-goals
Time zones and instants (needs an audited tz package; follow-up), display formatting and month/day names (copy catalog, later task), holidays (DT-03: not in v0.1), UI, `lib/**`.

## Allowed paths
`spike/T-004-jalali/**`, `.github/workflows/spike-jalali.yml` (spike CI, as T-002 did), and on finish only: this packet's status/summary, one line in `docs/ops/AGENT_LOG.md`, `docs/ops/STATUS.md` (Lead).

## Forbidden paths
`lib/**`, `test/**` (spike/README.md §2), `docs/design/**`, `design/**`, contracts, `pubspec.yaml` at the root.

## Acceptance criteria
- [ ] Every DT-05 vector passes through the port for both implementations: the seven conversions both ways, 1403 leap / 1405 common, month lengths of 1405 (6×31, 5×30, 29) and Esfand 1403 = 30, 2026-10-24 is Saturday, 1405/06/31 + 1 month = 1405/07/30. Evidence: CI test log per OS.
- [ ] Both implementations agree on every day from 1900-01-01 to 2123-12-31 and round-trip Gregorian → Jalali → Gregorian. Evidence: test log with the day count.
- [ ] Both agree with an ICU-generated fixture (Nowruz date and leap flag per Jalali year) over its range; any range where ICU differs is recorded as a finding, not hidden. Evidence: fixture generator + ICU version in the README.
- [ ] `package:shamsi_date` is imported by exactly one file (the adapter); DT-01: dates are stored and parsed as Gregorian `yyyy-MM-dd` only. Evidence: test.
- [ ] Spike lockfile license-scanned (0 failing), analyzer clean; all of it green on Linux, macOS, Windows and Chrome.
- [ ] README with SP-04 findings and a proposal input for ADR-UI-004 (library vs. in-house); no ADR decided here.
