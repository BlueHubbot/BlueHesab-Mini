# RELEASE_AND_VERSIONING — انتشار و نسخه‌گذاری (v2)

**وضعیت:** پیشنهادی · **مالک:** Lead + Builder-Platform · **تاریخ:** 2026-10-26
تکمیل‌کننده‌ی `docs/product/DISTRIBUTION_PLAN.md` (کانال‌ها و CI) و `docs/DEFINITION_OF_DONE.md`. انتشار عمومی همیشه D3 است (تأیید صاحب محصول).

## ۱. نسخه‌گذاری
- برنامه: معنایی `MAJOR.MINOR.PATCH` (+ build number)، تگ `vX.Y.Z`. پیش از ۱٫۰ تغییرات ناسازگار فقط با افزایش MINOR و در یادداشت‌ها.
- نسخه‌ی schema پایگاه‌داده مستقل است (`PRAGMA user_version`، DATA_MODEL MG-01) و در یادداشت‌ها می‌آید.
- نسخه‌ی قالب پشتیبان (`format_version`) و بسته‌ی قاعده‌های پیامک (`version`) مستقل‌اند.
- پیش‌انتشار: `v0.1.0-alpha.N` (فقط صاحب محصول)، `-beta.N` (گروه کوچک)، `-rc.N`.
- Android: `versionCode` یکنواخت افزایشی؛ Windows/macOS: نسخه‌ی بسته از همان تگ.

## ۲. مسیر انتشار
1. شاخه‌ی `release/vX.Y` از `main` فقط وقتی همه‌ی اقلام M3 تمام است؛ فقط رفع باگ بحرانی وارد آن می‌شود.
2. CI بیلد سه پلتفرم را می‌سازد: APK امضاشده، نصب‌کننده‌ی ویندوز، DMG، `SHA256SUMS`، فهرست مجوزها، یادداشت انتشار.
3. چک‌لیست انتشار (§۳) توسط Tester و Security پر می‌شود؛ Lead گزارش یک‌صفحه‌ای به صاحب محصول می‌دهد.
4. صاحب محصول تأیید می‌کند (D3) ← تگ ← Release پیش‌نویس در GitHub ← انتشار ← به‌روزرسانی لندینگ و `CHANGELOG.md`.
5. پس از انتشار: ۴۸ ساعت پایش Issueها؛ رفع بحرانی ← `vX.Y.Z+1`.
